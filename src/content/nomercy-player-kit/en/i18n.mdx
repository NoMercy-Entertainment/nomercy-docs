# i18n

The player ships a lightweight i18n layer. All player-generated strings (error messages, phase labels, accessibility announcements) are routable through a pluggable `ITranslator` adapter.

---

## Configuration

```ts
player.setup({
  language: 'nl',
  translations: {
    'player.error.stream-load-failed': 'Stream kon niet worden geladen',
    'player.action.play': 'Afspelen',
  },
  loadTranslations: async (lang) => {
    const mod = await import(`./locales/${lang}.json`);
    return mod.default;
  },
});
```

### `language`

```ts
language?: string
```

Initial language code (BCP-47, e.g. `'en'`, `'nl'`, `'ja-JP'`). Default: `navigator.language` (browser locale).

### `translations`

```ts
translations?: Translations
```

Inline translation map. Keys are the player's internal translation keys. Values are translated strings. Supports variable interpolation:

```ts
translations: {
  'player.queue.items-remaining': '{{count}} items remaining',
}
```

Merged with `loadTranslations` output. Inline translations take precedence.

### `loadTranslations`

```ts
loadTranslations?: (lang: string) => Promise<Translations>
```

Async loader called during `setup()` (if `language` is set) or when `setLanguage(lang)` is called at runtime.

---

## Runtime language switching

```ts
await player.setLanguage('fr');

player.language(); // 'fr'
```

`setLanguage` calls `loadTranslations('fr')`, merges the result with any inline translations, and emits a `language` event:

```ts
player.on('language', ({ lang }) => {
  document.documentElement.lang = lang;
});
```

---

## Translate a key

```ts
player.t('player.queue.items-remaining', { count: 5 });
// → '5 items remaining' (after variable substitution)
```

Variable substitution uses `{{key}}` syntax. Unrecognized keys fall back to the key string itself so the player never silently hides text.

---

## Translation events

| Event          | Payload                            | Fires when                     |
| -------------- | ---------------------------------- | ------------------------------ |
| `language`     | `{ lang: string }`                 | Language changes               |
| `translations` | `{ lang: string; keys: string[] }` | New translation strings loaded |

## Custom translator adapter

Replace the entire i18n backend with your own `ITranslator` implementation:

```ts
import type { ITranslator } from '@nomercy-entertainment/nomercy-player-core';
import i18n from 'i18next';

class I18nextAdapter implements ITranslator {
  t(key: string, vars?: Record<string, string | number>): string {
    return i18n.t(key, vars);
  }
  setLanguage(lang: string): Promise<void> {
    return i18n.changeLanguage(lang);
  }
  language(): string {
    return i18n.language;
  }
}

player.setup({
  translator: new I18nextAdapter(),
});
```

## Vite plugin

The kit ships a Vite plugin for build-time translation bundling. It scans your locale files and generates typed translation keys:

```ts
// vite.config.ts
import { nomercyTranslationsPlugin } from '@nomercy-entertainment/nomercy-player-core/vite-plugin';

export default {
  plugins: [
    nomercyTranslationsPlugin(),
  ],
};
```

This is optional. The runtime adapter works with any locale file format.
