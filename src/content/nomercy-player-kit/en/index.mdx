# nomercy-player-core — Kit

The kit is layer 2 of the five-layer architecture. It provides the generic infrastructure that both `nomercy-video-player` and `nomercy-music-player` build on.

---

## What the kit provides

- **Lifecycle machine** — 13-phase state machine from `idle` through `playing` to `disposed`
- **Plugin system** — typed `Plugin<P, O, E>` base class, dependency resolution, error quarantine, recovery policy
- **Event bus** — typed `BaseEventMap`, cancellable `before*` events, cross-plugin event routing
- **Auth pipeline** — bearer token injection, 401 refresh, 403 propagation
- **Queue engine** — append, prepend, remove, move, sort, shuffle, backlog
- **i18n** — `ITranslator` adapter, `t()` method, async language loading
- **Storage** — `IStorage` adapter with `LocalStorageBackend`, `MemoryStorageBackend`, `IndexedDBBackend`
- **Metrics** — `PlaybackMetrics` shape, `recordMetric()`, throttled `playback:metrics` event
- **28 adapter ports** — pluggable interfaces for every cross-cutting concern

---

## When to depend on the kit directly

Most consumers install `nomercy-video-player` or `nomercy-music-player` — both packages re-export the kit's public API. Install `nomercy-player-core` directly only if you:

- Are writing a library-level plugin that must work with both video and music players without importing either
- Are building a new library package on top of the kit

```
npm install @nomercy-entertainment/nomercy-player-core@beta
```

## Architecture context

```
Your app (layer 5)
      │
Built-in plugins (layer 4)
      │
nomercy-video-player / nomercy-music-player (layer 3)
      │
nomercy-player-core ← you are here (layer 2)
      │
IVideoBackend / IAudioBackend (layer 1)
```

The kit owns nothing above layer 2. It does not import from the library packages and has no knowledge of `NMVideoPlayer` or `NMMusicPlayer`.
