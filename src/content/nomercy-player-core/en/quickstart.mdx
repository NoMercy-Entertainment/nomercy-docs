# Core: Quick Start

This is the shortest path to composing a player from the kit: no media backend, no UI, just the same three ingredients `nomercy-video-player` and `nomercy-music-player` are built from. Everything below is real, published code, not pseudocode.

## Install

```
npm install @nomercy-entertainment/nomercy-player-core@rc
```

You will not normally install this package directly. `nomercy-video-player` and `nomercy-music-player` already depend on it and re-export everything you need day to day. Install it yourself only when you're composing your own player, as below.

## Compose a minimal player

Three ingredients, in order: extend `EventEmitter` so `.on()` / `.emit()` work, resolve the three-form constructor (`resolvePlayerConstructor` plus `initPlayerCoreState`) so an id, an index, or `undefined` all do the right thing, then stamp every shared mixin onto the prototype in one `composeMixins` call.

:::snippet{file="minimal-player" live="false"}
:::

`playerCoreMethods` is not a cut-down subset picked for this example: it's the same aggregate `NMVideoPlayer` and `NMMusicPlayer` compose onto their own prototypes. `MinimalPlayer` is missing exactly one thing they have, a media backend. Everything else (`setup()`, `ready()`, `dispose()`, the phase machine, the queue, volume, i18n, plugin registration, auth) is the identical code running underneath both real players.

## Mounting it

The constructor's three-form resolution is what `nmplayer(id)` and `nmMPlayer(id)` do in the real libraries: pass a string id and it either returns an existing instance registered under that id, or resolves `document.getElementById(id)` and requires it to be a `<div>`.

```html
<div id="player-container"></div>
```

```ts
const player = minimalPlayer('player-container');

player.setup({ logLevel: 'info' });
await player.ready();

console.log(player.phase()); // 'ready'
player.dispose();
```

`setup()` runs the same fixed pipeline described in [What is nomercy-player-core](/nomercy-player-core/introduction#the-setup-then-freedom-model). With no media backend attached, `MinimalPlayer` reaches `ready` without ever loading or playing anything. That's exactly the point: everything up to and including `ready()` is kit behavior, proven independently of any specific medium.
