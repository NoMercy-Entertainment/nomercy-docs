# What is nomercy-player-core

`nomercy-player-core` is not a player. It is the kit both NoMercy players are built from.

It holds the lifecycle machine, the plugin runtime, the queue, the event bus, i18n, auth, and every swappable adapter a media player needs before it can play a frame.

`nomercy-video-player` and `nomercy-music-player` each add one thing on top: a media backend, and a few methods for their own medium. The rest they get from here.

## Who it's for

Building a player for something the trio does not cover: a podcast player, a live radio player, a custom streaming protocol.

You get the lifecycle, queue, plugin and auth machinery already written and already tested, instead of writing it a third time.

If you want to play video or music for end users, use [`nomercy-video-player`](/nomercy-video-player) or [`nomercy-music-player`](/nomercy-music-player) instead. They have done this work.

## Why it exists

Video and music playback differ in one place: how a frame is decoded, and how a UI reacts to it.

Everything else is the same. Queueing the next track, tracking phase, running plugins, resolving auth headers, switching language. A movie and a song need identical machinery.

So it lives once. Both players compose it rather than reimplementing it, and a fix here reaches both in the same release.

## Setup is strict, the rest is yours

Call `setup(config)` once. The kit then walks a fixed pipeline:

```text
config snapshot
  -> cross-cutting policies (visibility, network, wake lock, metrics)
  -> pluginsRegistering -> streamsReady -> authReady
  -> playlistReady -> mediaReady
  -> ready()
```

Calling `setup()` twice, or calling it after `dispose()`, throws. There is one way in, and a half-configured instance is not one of them.

Above that, nothing is prescribed. The kit ships no UI, no DOM beyond a container, and no opinion about what your play button looks like.

Every behaviour outside the lifecycle is a named interface with a working default, and any of them can be replaced: `IStorage`, `IPlatform`, `IStreamSource`, `IUrlResolver`, `ITranslator`, `ICueParser`, `IPreloadStrategy`, `ITransitionStrategy`, `IShuffleStrategy`, `RealtimeFactory`.

Plugins extend behaviour without forking anything. Through the cancellable `before*` pipeline a plugin can veto, delay or rewrite a mutation before it lands.

## What you get

- **Lifecycle**: `setup()` / `ready()` / `dispose()` and a phase machine (`idle` → `setup` → `ready` → `playing`/`paused` → `disposed`) that every mixin and plugin can trust.
- **Shared playback primitives**: transport, time, volume, queue, and backlog methods, composed once and reused by both real players instead of hand-copied.
- **Plugin runtime**: a `Plugin` base class, typed registration, and a cancellable `before*` dispatch pipeline (`preventDefault()`, `delay(promise)`) for behavior that shouldn't require forking the player.
- **Adapter ports**: swappable interfaces for the media backend, stream source, storage, event bus, cue parsing, translation, platform capabilities (wake lock, network, visibility, fullscreen, pip), realtime channel, preload strategy, transition strategy, and shuffle strategy, each with a working default.
- **Auth-aware fetch**: one `authFetch` pipeline (401 refresh-and-retry, 403 propagates, never conflated) used by every kit-internal request and available to plugins via `Plugin.fetch`.
- **i18n engine**: a translator with the kit's own `core.*` strings built in (English eager, every other kit locale loaded lazily on demand), consumer async-loadable bundles, and a title-token interpolation system for per-library tokens like season/episode.
- **Cue parsing**: built-in VTT, sprite-VTT, and LRC parsers behind a registry you can add your own formats to.
- **Typed errors**: a `PlayerError` hierarchy (`AuthError`, `DrmError`, `MediaFormatError`, `NetworkError`, `StateError`, `StreamError`, ...) with severity, scope, and a retry policy, instead of raw thrown strings.
- **Composition primitives**: `composeMixins`, `resolvePlayerConstructor`, and `initPlayerCoreState`, the exact three functions `NMVideoPlayer` and `NMMusicPlayer` use to become players. [Quickstart](/nomercy-player-core/quickstart) shows them composing a real, minimal one.
