# State

Core keeps typed tokens for how the player is playing, muted, repeating, and more.
You read them with methods.

Most return an exported enum.
`fn streamState` is the exception: it returns a `cls string` from the backend.

No reader is reactive.
Each call is a snapshot at that moment.
Pair the read with the event that changed the value, so you know when to call again.

[Playback Time](/nomercy-player-core/tour/time) covers position and duration in seconds.

## Playback and volume

`fn playState` returns one of `str idle`, `str loading`, `str playing`, `str paused`, `str stopped`, or `str error`.
A fresh player reports `str idle`.
Subscribe to `str play`, `str pause`, `str stop`, `str phase`, `str mediaReady`, and `str fatal` when the value must stay current.

`fn volumeState` returns `str unmuted` or `str muted`, not the level.
A fresh player is `str unmuted`.
Subscribe to `str volume` and `str mute` for updates.

## Repeat and shuffle

These two are readable and writable.
With no argument, each returns the current token.
With an argument, each returns a promise, because the write runs a cancellable cycle.

`str beforeRepeat` or `str beforeShuffle` runs first.
A listener that cancels gets `str repeatPrevented` or `str shufflePrevented`, and nothing changes.
Otherwise the value is stored and `str repeat` or `str shuffle` is emitted.

```ts
import { RepeatState } from '@nomercy-entertainment/nomercy-player-core';

await player.repeatState(RepeatState.ALL);
```

Both start at `str off`.

The repeat mode decides whether the end of the queue loops or stops.

`fn shuffleState` with `str on`, or boolean `true`, randomizes the queue order at once.
`fn shuffleState` with `str off` changes the token and leaves the shuffled order in place.
Supply the queue again when you need the original order.

## Coarse readers

These map backend and platform detail into something you can render.
Each has a safe answer when its source is missing.

| Reader | Returns | When nothing is wired |
| --- | --- | --- |
| `fn bufferState` | `str idle`, `str loading`, `str seeking`, or `str stalled` | `str idle` |
| `fn networkState` | `str online`, `str offline`, or `str slow` below 1.5 Mbps | `str online` |
| `fn streamState` | the backend's raw state string | `str idle` |
| `fn visibilityState` | `str visible` or `str hidden` | `str visible` |

Prefer `fn bufferState` when you want the typed buffer token.
Reach for `fn streamState` only when you need the raw backend string.

## Selection mode

`fn qualityMode` and `fn audioTrackMode` report how the current choice was made, not which track or level is active.

`fn qualityMode` starts as `str auto`.
Pass a level index to lock `str manual`, or `str auto` to restore adaptive selection.
Each change emits `str qualityState`.

`fn audioTrackMode` starts as `str default`.
Pass an index to switch to `str manual` and forward that pick to the backend.
There is no argument that returns it to `str default`.

Each change emits `str audioTrackState`.

Those two writes apply immediately.
They do not emit a before-event you can cancel.

## Cancel a mutation

Many writes run a shared `str beforeMutation` guard before they take effect.
A listener sees `key method` and the arguments, and can call `preventDefault`.
`fn delay` on that event does nothing, because the guard is synchronous.

Canceling emits `str mutationPrevented` with the same `key method`, and the write does not run.
Pass `key mutationGuards` as `false` on `fn setup` to turn the guard off.

Pass `str all` to include hot methods that skip it by default.
The default skips `str time`, `str bandwidth`, and `str recordMetric`.

A cursor move reports `key method` as `str current`.
Plugins can also emit `str info`, `str warning`, or `str error` advisories for that method during the same pass.

## Snapshots that surprise

When the new id differs from the one that was mounted, time and duration are already `0` before `str item` fires.
An `item` listener does not see the outgoing end position.
