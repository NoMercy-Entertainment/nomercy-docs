# Plugins

A plugin is extra behavior you add to a player, such as counting each play.
Write one when the player should do something it does not already do.

Subclass `cls Plugin` and set a static `key id` and `key description`.
Pass that class to `fn addPlugin`, with options when the plugin needs them.
You do not construct the instance yourself, so the player can wire it and tear it down.

```ts
player.addPlugin(PlayCounterPlugin, { everyNPlays: 2 });
```

## Added, enabled, disposed

`fn addPlugin` hands the class to the player for installation.
The player constructs the instance, calls `fn use` once, then emits `str plugin:installed`.
Override `fn use` to subscribe and start the behavior you added.

A new plugin starts enabled, so its work can run right away.
`fn enable` and `fn disable` flip that flag without unloading the plugin.
Both emit `str plugin:enabled` or `str plugin:disabled`, and both are safe to call again.

`fn removePlugin` with the same class runs `fn dispose`, then emits `str plugin:disposed`.
Disposing the player does the same for every registered plugin.
Override `fn dispose` only for resources your helpers never tracked.

`fn getPlugin` returns the live instance, or `undefined` when it is missing.
`fn state` reports `key id`, `key version`, whether it is enabled, its options, and a `key runtime` object.
