# Cue Parsers

Use cue parsers when timed text, lyrics, or sprite crops need to line up with playback time.
Each parser returns a cue list you can query, grow, or drive from the player's clock.

Import the helpers from `@nomercy-entertainment/nomercy-player-core`.

## Parse text without a player

`fn parseVttSubtitles` turns WebVTT into cues with plain `key text` and optional `key markup`.
Inline `str b`, `str i`, and `str u` tags stay in `key markup`.
Cue settings map to `key alignment`, `key linePosition`, and `key size` on the payload when present.

`fn parseVtt` keeps each cue body as a raw string.
`fn parseVttSprite` reads `#xywh=` crops, and joins relative URLs when you pass `key baseUrl`.

`fn parseLrc` reads plain or word-level LRC.
End times come from the next cue's start, and the last cue lasts five more seconds.

`fn parseTimestamp` turns a WebVTT-style clock into seconds.
`fn parseDurationSeconds` turns an `H:M:S` or `M:S` string into seconds for item durations.

```ts
import { parseLrc, parseVttSubtitles } from '@nomercy-entertainment/nomercy-player-core';

const subtitles = parseVttSubtitles(vttText);
const lyrics = parseLrc(lrcText);
```

## Query by time

`fn createCueList` builds an immutable list from `{ start, end, payload }` entries.
Input order does not matter, because the list sorts by `key start`.

These queries answer where you are in that list.

`fn active` with a time returns every cue whose interval contains that time.
`fn next` returns the nearest cue that starts after it.
`fn prev` returns the nearest cue that already ended before it.

Overlapping cues stay in `fn active`, so parallel lines and adjacent sprites both work.

## Grow a list, or follow playback

`fn createMutableCueList` starts empty or from an initial array.
`fn add`, `fn remove`, and `fn clear` keep it sorted and notify `fn subscribe` listeners.

`cls CueTracker` listens to a player's `str time` and `str seek` events.
It runs your `str enter` and `str exit` handlers as cues activate.
It also emits `str cue:enter` and `str cue:exit` on the player with `key trackerId` and `key cue`.

```ts
const tracker = new CueTracker(list, { trackerId: 'lyrics' });
tracker.on('enter', cue => showLine(cue.payload));
tracker.attach(player);
```

## Built-in formats

During `fn setup`, Player Core registers three parsers.
A later `fn registerCueParser`, or an entry in `key cueParsers` on setup, wins when it matches the same URL first.

Which built-in matches depends on the URL, and sometimes the content type:

| Id | Matches when |
| --- | --- |
| `str lrc` | The URL has a `.lrc` extension, or content type `application/x-lrc`, `application/x-lyrics`, or `text/lrc` |
| `str vtt` | The URL has a `.vtt` extension or content type `text/vtt`, unless the URL looks like a sprite sheet |
| `str sprite-vtt` | The URL contains `sprite.vtt` or `sprites.vtt` |

## Resolve and register

`cls CueParserRegistry` walks newest first and returns the first parser whose `fn canParse` accepts the URL.
`fn register` replaces an existing `key id`.
Pass `prepend: true` to put a parser at the low-priority end.

On a player, `fn registerCueParser`, `fn unregisterCueParser`, and `fn resolveCueParser` wrap that registry.
`fn resolveCueParser` takes only a URL.

A parser needs `key id`, `fn canParse`, and `fn parse`.
`fn parse` may receive `{ baseUrl }` so relative sprite paths can resolve.
