# The Composition Boundary

Use `fn composeMixins` when your player class should receive method modules without a long inheritance chain.
The modules you pass early are the shared behavior you keep.
The modules you pass last are what your class adds or overrides.

## Keep shared first

Pass the general modules before the specific ones.
A later module replaces an earlier one when both export the same key.
That is how your class can change one method without rewriting the rest.

Getters and setters stay accessors during the copy.
They are not run while `fn composeMixins` stamps them.
Calling the same module again is safe, and it overwrites with the same descriptors.

These four rules are the whole stamp.

| Rule | Why it matters |
| --- | --- |
| Order left to right | Each module is applied in turn |
| Later key wins | Your override replaces the shared method |
| Accessors preserved | Getters and setters are not triggered by the copy |
| Repeat is safe | A second stamp of the same module matches the first |

## Add only what is yours

Write your class, then stamp modules onto its prototype.
Omit a later module when the shared behavior is enough.
Add one when your class needs a different key.

```ts
composeMixins(MyPlayer.prototype, generalMethods, specificMethods);
```

After that call, `specificMethods` owns every key it exports.
Every other key still comes from `generalMethods`.
