# The Event Bus

Listen on the player you already built.
`fn on`, `fn once`, `fn off`, and `fn emit` live on that instance.
There is no separate bus to create or pass into setup.

## Subscribe

`fn on` runs your handler on every emit of that name.
`fn once` runs it on the next emit, then removes it.
Keep the same function reference so `fn off` can find it later.

```ts
player.on('item', ({ item, index }) => highlightRow(index));
player.once('item', ({ index }) => console.log(index));
```

Registering the same function twice for one event registers it once.
The second call is not a second subscription.

A typed name from the player's event map types the handler payload.
A bare string also compiles, so names like `str plugin:<id>:<event>` stay callable.

## Stop listening

`fn off` with the name and the same function removes that one handler.
It works for both `fn on` and `fn once` registrations.
Cancel a `fn once` handler before it has fired the same way.

`fn off` with a name and no function drops every listener for that name.
`fn off` with `str all` and no function drops every listener for every name, firehose included.

## Hear a new item

Listen for `str item` when you need the active entry and its index.

```ts
player.on('item', ({ item, index }) => highlightRow(index));
```

`fn on` with `str current` never fires.
It logs a console warning that points to `str item`.

## What emit delivers

`fn emit` calls named listeners in subscription order, then any firehose listeners.
It returns at once when nobody is listening for that name or for `str all`.

The listener set is snapshotted before the walk.
An `fn off` inside a handler applies on the next emit, not this one.
A throwing handler is caught and logged, and the rest still run.

## The firehose

`fn on` with `str all` receives every emit as `(event, data)`.
That is the debugging hook.
Remove one with `fn off`, `str all`, and the same function.

Firehose listeners sit apart from named ones.
`fn hasListeners` ignores them, so it stays false when only `str all` is registered.

## Check before you build a payload

`fn hasListeners` is true when a named event has at least one handler.
Use it before you build a payload that costs something to create.
`fn listenerCount` counts every live handler, firehose included.

When a name gains its first listener or loses its last, the bus emits `str listeners-changed`.
The payload is `key name` and `key count`.
It arrives on a microtask, not inside your `fn on` call.
