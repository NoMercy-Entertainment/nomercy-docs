# Transport

Use transport when you need `fn play`, `fn pause`, `fn stop`, seek steps, or `fn load`.
Player Core does not decode media itself.
Each call forwards to the backend your player supplies.

Import the shared mixins from `@nomercy-entertainment/nomercy-player-core` and compose them onto your class.
The public methods then live on the instance.

Call them only after `fn setup` has left `str idle`, and never after `fn dispose`.
Before that, the call throws `str core:player/not-ready`.
After dispose, it throws `str core:player/disposed`.

## Shared shape

Every call in the table below checks readiness first.
It then announces a `before*` event so a listener can cancel.
Only when that passes does it change state and talk to the backend.

This table pairs each call with the events it uses.

| Call | Announces | Emits when it runs |
| --- | --- | --- |
| `fn play` | `str beforePlay` | `str play` |
| `fn pause` | `str beforePause` | `str pause` |
| `fn stop` | `str beforeStop` | `str stop` |
| `fn load` | `str beforeLoad` | `str mediaReady` on success |
| `fn rewind` / `fn forward` / `fn restart` | `str beforeSeek` | `str seek`, then `str seeked` |

`fn next` and `fn previous` announce `str beforeNext` and `str beforePrevious`.

`fn togglePlayback` announces nothing of its own.
It calls `fn pause` while playing, and `fn play` otherwise.

## Play, pause, and stop

`fn play` marks the player as playing, may move to `str starting`, emits `str play`, then awaits the backend `play`.
Await it when you need to know the backend accepted.

If the backend refuses, state rolls back to paused and `str playPrevented` fires with `str backend-refused`.
The refusal is rethrown, so an unawaited `fn play` becomes an unhandled rejection.

`fn pause` and `fn stop` do not await the backend, so they cannot fail that way.
`fn pause` moves to `str paused` from `str playing` or `str starting`.
`fn stop` always moves to `str stopped` and asks the backend to stop.

Pass `key silent: true` on these options when a restore must skip the `before*` guard and the plain event.

```ts
await player.play();
await player.pause();
await player.stop();
```

## Load an item

`fn load` mounts one item into the backend.
It needs `key url` on the item, and a wired backend, or it throws.

A listener can cancel with `str beforeLoad`; then `str loadPrevented` fires and nothing mounts.
After the guard passes, play state becomes `str loading` while the backend mounts.

From `str ready`, `str playing`, `str paused`, `str starting`, or `str ended`, the phase also flashes `str loading`.
On success it settles to `str ready`, play state becomes `str paused` unless a transport call already owned it, and `str mediaReady` fires.

Await `fn load` before `fn play` when you chose the item yourself.
Editing the queue does not start playback.
`fn play` must wait until the new item has loaded.

`key startAt` is a start offset in seconds for engines that honor it.
`key fadeIn` ramps volume up over that many seconds after the mount.
A faster second `fn load` wins; the older continuation stops quietly.

`fn loadQueue` fetches a playlist URL, replaces the queue, and emits `str playlistReady` on success.

```ts
await player.load(item, { startAt: 12 });
await player.play();
```

## Seek by a step

`fn rewind` and `fn forward` move relative to the current position.
Both default to 5 seconds.

`fn rewind` clamps at 0.
`fn forward` has no upper clamp; the backend snaps past the end if it must.

`fn restart` seeks to 0, then plays.
A prevented seek skips that play, because restart is one intent.

`str beforeSeek` carries the delta for rewind and forward, and `0` for restart.
`str seek` and `str seeked` carry the absolute target instead.

The seeking phase round-trip runs only from `str playing`, `str paused`, or `str starting`.
Earlier seeks emit no phase flash, so a restored position does not flicker seeking in the UI.

```ts
await player.forward(10);
await player.rewind();
await player.restart();
```

## Next and previous

`fn next` follows the repeat mode.
`str one` reloads the current item without moving the cursor.
`str all` wraps to the first item when there is no next.
`str off` emits `str queue:exhausted` when there is no next.

An empty queue emits `str queue:exhausted` under every mode.
`fn previous` at the start returns quietly and emits nothing.

Both move the queue cursor before the media switches when there is a neighbor to select.
That cursor move emits `str item`.
Awaiting `fn next` means the load finished, not that playback started.

Playback starts without being awaited, so a refused play emits `str playPrevented` while `fn next` still resolves.

## Cancel before it runs

A `before*` listener receives an event object.
Call `preventDefault` on it to stop the action.

```ts
player.on('beforePlay', (event) => {
	if (event.data.source === 'remote')
		event.preventDefault();
});
```

A canceled call changes no state and never reaches the backend.
The matching `*Prevented` event carries `key reason`, often `str listener-prevented`, and optional `key cause`.

## Attribute the caller

Every call accepts `key source` on its options.
Whatever you pass is stamped onto the events that follow.
Nothing fills one in when you omit it.

```ts
await player.play({ source: 'remote' });
```

`str seek` carries a source.
`str seeked` does not.
