# The Queue

Use the queue when you have more than one item, or when you want to jump to a specific one.
Editing the list does not by itself start playback.
Starting playback is a separate call, and it has to wait until the new item is loaded.

## Read and replace the list

`fn queue` with no argument returns the items as a read-only array.
Pass an array to replace the whole list.
The first call also connects list changes to the events you hear with `fn on`.

```ts
const items = player.queue();
player.queue(newItems);
```

`fn queueAppend`, `fn queuePrepend`, and `fn queueInsert` add one item or an array.
`fn queueRemove` takes an `key id`.
`fn queueRemoveAt`, `fn queueMove`, `fn queueClear`, `fn queueShuffle`, and `fn queueSort` change the list in place.

`fn queueLength` returns how many items are present.
`fn queueIndexOf` returns the zero-based index for an `key id`, or `-1` when it is missing.
`fn peekNext` and `fn peekPrevious` return the neighbor without moving the cursor.

## What happens to each item

Every item is normalized before it is stored.
`fn queue`, `fn queueAppend`, `fn queuePrepend`, and `fn queueInsert` all do that.

If you set `fn normalizePlaylistItem`, it runs first and can adapt a shape you got from your own backend.
`key transformPlaylistItem` on the config runs next.
A string `key title` can then fill in tokens you registered, such as a season or episode prefix.

`fn registerTitleTokens` adds those letter-to-translation pairs.
A later call merges with what you already registered.
It does not wipe the earlier pairs.
Until you or a library registers some, none are filled in.

## Move the cursor

`fn item` with no argument returns the active item, or `undefined` when the list is empty.
`fn index` returns its zero-based position, or `-1` when the list is empty.

Pass an item, an `key id`, a zero-based index, or a function that picks the item.
A listener can cancel that move.
When the cursor actually moves, the player emits `str item` with the item and its index.

The cursor moves, and `str item` fires, before the picture or sound switches.
By then, time and duration are already `0` when the new id differs from the one that was mounted.
An `str item` listener does not see the previous item's ending position.
Wait until the new media is ready before you act on the position.

```ts
player.item();
player.item('episode-3');
player.item(2, { autoplay: false });
```

During setup, if the list is still empty, the target is remembered instead of dropped.
It is applied once the playlist exists.
In `str idle`, `str disposing`, or `str disposed`, the call only moves or remembers the cursor.

Otherwise the player loads the active item.
It plays when `key autoplay` is not `false`.
Pass `autoplay: false` when you want to move the cursor and stay paused.

## Start playback after the load

`fn item` starts the load and does not give you a promise to await.
A `fn play` on the next line can run before the new source is on the element.
The item ends up loaded, and silent.

Pass `{ autoplay: true }`, or leave `key autoplay` unset, so play runs only after that load resolves.
`fn playItem` is that same path with autoplay forced on.
`fn playNow` replaces the list, then plays from the start you pass, or from the first item when you omit it.

An empty list passed to `fn playNow` does nothing: no replacement, and no cursor move.
`fn playNow` does not unload the current item first.
The load that follows interrupts it.

`key source` and `key startAt` on those options are forwarded to the load and the play, the same way as on `fn item`.

## Move by number without loading

`fn seekToIndex` counts from 1.
`seekToIndex(1)` selects the first item.
`seekToIndex(player.queueLength())` selects the last.

```ts
player.seekToIndex(1);
```

A listener can cancel it, the same way as `fn item`.
It only moves the cursor.
It does not load or play.

A position past the end is ignored.
A value that is not a positive integer throws `cls RangeError`.

## What you can listen for

A list change emits `str queue`.
Append, prepend, and insert emit `str queue:append`, `str queue:prepend`, and `str queue:insert`.
Remove, move, and clear emit `str queue:remove`, `str queue:move`, and `str queue:clear`.

Shuffle and sort emit `str queue:shuffle` and `str queue:sort`.
Selecting a new item emits `str item`.

```ts
player.on('queue', items => renderList(items));
player.on('item', ({ item, index }) => highlightRow(index));
```

## A second list

`fn backlog` reads or replaces a second list next to the queue.
`fn backlogAppend`, `fn backlogRemove`, and `fn backlogClear` change it.

It emits `str backlog`, `str backlog:append`, `str backlog:remove`, and `str backlog:clear`.
Filling the backlog does not move the cursor.
You choose what goes in it.
Those writes also skip the normalize step the queue uses.
