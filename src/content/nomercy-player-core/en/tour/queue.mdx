# The Queue

Move an ordered playlist and its cursor without racing `fn play` ahead of the loaded source.

You finished [Quick Start](/nomercy-player-core/quickstart), so `composeMixins` has already stamped method bundles onto your class.
A mixin is one of those bundles.

`queueMethods` is the bundle that reads and edits the list.
`playQueueMethods` is the bundle that moves the cursor and starts playback.

## Read and replace the list

`fn queue` with no argument returns the live playlist as a read-only array.
Pass an array to replace the whole list.
The first call also wires the list events onto the player event emitter, the same surface `fn on` listens to.

```ts
const items = player.queue();
player.queue(newItems);
```

`fn queueAppend`, `fn queuePrepend`, and `fn queueInsert` add one item or an array.
`fn queueRemove` takes an `key id`.
`fn queueRemoveAt`, `fn queueMove`, `fn queueClear`, `fn queueShuffle`, and `fn queueSort` mutate in place.

`fn queueLength` returns how many items are present.
`fn queueIndexOf` returns the zero-based index for an `key id`, or `-1` when missing.
`fn peekNext` and `fn peekPrevious` return the neighbor without moving the cursor.

## Every item is ingested on the way in

Ingest is the step that turns an incoming value into a stored playlist item.
`fn queue`, `fn queueAppend`, `fn queuePrepend`, and `fn queueInsert` run each entry through ingest before it lands.

Optional `fn normalizePlaylistItem` on the player adapts a wire format first.
Optional `key transformPlaylistItem` from config runs next on that result.
A string `key title` then resolves registered title tokens.

`fn registerTitleTokens` merges letter-to-translation-key pairs into the player's registry.
Later calls merge; they do not clear earlier ones.
Player Core ships an empty registry until a library or you register tokens.

## The cursor

`fn item` with no argument returns the active item, or `undefined` when the queue is empty.
`fn index` returns its zero-based position, or `-1` when empty.

`fn item(target, opts?)` moves the cursor to an item reference, `key id`, zero-based index, or predicate.
It fires `str beforeMutation` with method `str current` first, so a listener can cancel the move.
When the cursor moves, the player emits `str item` with the item and its index.

The cursor moves and `str item` fires before the media element switches.
Before that emit, the mixin zeroes the internal time and duration when the new `key id` differs from the mounted one.
An `item` listener therefore does not read the outgoing end position.

```ts
player.item();
player.item('episode-3');
player.item(2, { autoplay: false });
```

During `str setup`, if the queue is still empty, `fn item` parks the target as a pending selection instead of dropping it.
The ready pipeline applies that selection once the playlist exists.
In `str idle`, `str disposing`, or `str disposed`, a write stops after moving or parking the cursor.

Otherwise the write loads the active item.
It then plays when `key autoplay` is not `false`.
Pass `autoplay: false` to move the cursor without starting playback.

## Play after the source is set

`fn item` starts `fn load` and does not return a promise for you to await.
A separate `fn play` on the next line can run before the backend has set the element source.
That race is why a bare `item` plus `play` pair is unsafe.

Pass `{ autoplay: true }`, or omit `key autoplay`, so `fn play` runs only inside the resolved `fn load` continuation.
That is the race-free path to start a new item.
`fn playItem(target, opts?)` is the same path with `key autoplay` forced to `true`.

`fn playNow(items, start?, opts?)` replaces the queue, then plays from `start` or from the first item when `start` is omitted.
An empty `items` array is a silent no-op: no replacement, no cursor move.
`fn playNow` does not stop or unload the current item first; the following `fn item` load interrupts it.

`key source` and `key startAt` on those options thread through to load and play the same way as on `fn item`.

## Move by ordinal without loading

`fn seekToIndex(position)` counts from 1.
`seekToIndex(1)` selects the first item.
`seekToIndex(player.queueLength())` selects the last.

```ts
player.seekToIndex(1);
```

It fires the same `str beforeMutation` method `str current` as `fn item`.
It only moves the cursor.
It does not call `fn load` or `fn play`.

A position past the end is ignored.
A value that is not a positive integer throws `cls RangeError`.

## What the list announces

These are the list and cursor events this mixin wires.

A list change emits `str queue`.
Append, prepend, and insert emit `str queue:append`, `str queue:prepend`, and `str queue:insert`.
Remove, move, and clear emit `str queue:remove`, `str queue:move`, and `str queue:clear`.

Shuffle and sort emit `str queue:shuffle` and `str queue:sort`.
The cursor emits `str item` when it selects a new queue item.

```ts
player.on('queue', items => renderList(items));
player.on('item', ({ item, index }) => highlightRow(index));
```

## The backlog

`fn backlog` reads or replaces a second list beside the queue.
`fn backlogAppend`, `fn backlogRemove`, and `fn backlogClear` mutate it.

It emits `str backlog`, `str backlog:append`, `str backlog:remove`, and `str backlog:clear`.
This mixin does not drive the cursor from the backlog; you populate it yourself.
Backlog writes skip the ingest pipeline above.
