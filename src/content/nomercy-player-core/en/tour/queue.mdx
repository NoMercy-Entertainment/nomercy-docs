# The Queue

A queue is two things: an ordered list of items, and a cursor pointing at one of them.

Every method on this page moves one or the other.
The kit keeps both in a single `MediaList` per player, so there is no second copy of the list to fall out of step.

## The playlist becomes the queue

`setup({ playlist })` seeds the queue during the ready pipeline.

Pass an array and the items go straight in.
Pass a string and the player fetches it, expects a JSON array, and puts that in instead.

A fetch that fails, or a body that is not an array, emits `playlistError` and then `playlistReady` with `length: 0`.
Setup still reaches `ready`, with an empty queue.
`playlistReady` fires even when you configured no playlist at all, so a listener can rely on it.

The array form only seeds when the queue is still empty.

{/* partial */}
```ts
player.setup({ playlist: items });
player.queue(myAlreadyResolvedItems);
await player.ready();
```

Your `queue()` call wins there.
The config array is skipped rather than clobbering what you put in.

After ready, `loadQueue(url, parser?)` fetches a queue the same way.
It throws on failure, unlike the setup path, and emits `playlistResolveError` and `error` first.

## Reading and replacing the list

{/* partial */}
```ts
const items = player.queue();
player.queue(newItems);
```

`queue()` hands back the player's own array, not a copy.
Its type says read-only, and that is the contract to honor: change the list through the methods below, never by writing into what you were handed.

Replacing the list keeps the cursor on the same item when an item with that `id` is still in the new array.
Otherwise the cursor goes to the first item, or to nothing when the new array is empty.

## Every item is ingested on the way in

`queue()`, `queueAppend()`, `queuePrepend()` and `queueInsert()` all run each item through three steps before it lands.

1. `normalizePlaylistItem`, your player class's optional hook, where a library adapts a wire format of its own.
2. `transformPlaylistItem`, your config callback, on the normalized result.
3. Title token resolution, on the item's `title`.

A title token is `%` plus a letter plus digits, such as `%S2`.
`registerTitleTokens({ S: 'some.translation.key' })` maps the letter to a translation key, and the digits arrive as `number` for the translation to place.
An unregistered letter is left exactly as written, so a player that registers nothing changes no titles.

Token resolution leaves nothing behind for a second pass to find, and the kit expects your two callbacks to behave the same way.
Putting an already-queued item back into the queue then costs nothing.

## Where the cursor is

{/* partial */}
```ts
player.item();   // the item it points at, or undefined
player.index();  // its position, or -1 on an empty queue
```

`peekNext()` and `peekPrevious()` read the neighbors without moving anything.
Both are `undefined` at their respective end of the list.

`queueLength()` counts the items and `queueIndexOf(id)` finds one, returning `-1` when there is no such item.

## Changing the list under the cursor

Nine methods change the list: `queueAppend`, `queuePrepend`, `queueInsert`, `queueRemove`, `queueRemoveAt`, `queueMove`, `queueClear`, `queueShuffle` and `queueSort`.

`queueInsert`, `queueRemoveAt` and `queueMove` take zero-based indices.
`queueRemove` takes an item's `id`.
`queueSort` takes the same comparator `Array.prototype.sort` takes.

The cursor is adjusted on every one of them so it keeps pointing at the item it was on.

| What you do | What the cursor does |
| --- | --- |
| Add items before it | Moves up by that many positions. |
| Remove an item before it | Moves down one position. |
| Remove the item it is on | Stays put, so it now points at the following item. On the last item it clamps to the new final position. |
| Move, shuffle or sort | Follows its item to the item's new position. |
| Clear the queue | Goes to `-1`, and `item()` is empty. |

`queueRemoveAt` and `queueMove` ignore an index outside the list.
Nothing moves, and nothing is emitted.
`queueMove(2, 2)` and `queueShuffle()` on a one-item queue are silent for the same reason.

**`queueInsert` is the exception.** It clamps the index into `[0, length]` and inserts anyway.
So `queueInsert(item, 99)` on a three-item queue appends the item, and a negative index puts it at the front.

## Moving the cursor

`item(target)` moves the cursor and starts playing what it lands on.

{/* partial */}
```ts
player.item('episode-3');
player.item(2);
```

A target is an item, its `id`, a zero-based integer index, or a predicate.
A target that resolves to nothing leaves the cursor where it was.

**Only a whole number is read as an index.** A fractional number is matched against `id` instead.

**Playing is the default.** Pass `autoplay: false` to move the cursor without starting playback.

{/* partial */}
```ts
player.item('episode-3', { autoplay: false });
```

**`item()` returns nothing to await.** It starts a load and does not wait for it, so a `play()` on the next line runs against the source that is still mounted.

`playItem(target, opts?)` is that call with `autoplay: true` already set.
`playNow(items, start?, opts?)` replaces the queue and plays from `start`, or from the first item when you omit it.
Both route through `item()` internally, which is what keeps the `play()` inside the load's own continuation rather than racing it.

`playNow([])` does nothing at all: no replacement, no cursor move.

`next()` and `previous()` move this same cursor, and both resolve once the new item has loaded.

## Moving by ordinal

`seekToIndex(position)` counts from 1, so `seekToIndex(1)` is the first item and `seekToIndex(queueLength())` is the last.

{/* partial */}
```ts
player.seekToIndex(1);
```

**It moves the cursor and loads nothing.** That is the difference from `item()`, and it is what makes it the call for repositioning a list without interrupting what is playing.

A position past the end is ignored silently.
A position that is zero, negative or fractional throws a `RangeError`.

## Stopping a cursor move

Both `item(target)` and `seekToIndex(position)` fire `beforeMutation` first, with `method` set to `'current'`.

{/* partial */}
```ts
player.on('beforeMutation', (event) => {
	if (event.data.method === 'current' && isLocked())
		event.preventDefault();
});
```

A prevented move emits `mutationPrevented` carrying the same `method`, and the cursor does not move.

## What the queue announces

Each list method has an event of its own: `queue:append`, `queue:prepend`, `queue:insert`, `queue:remove`, `queue:move`, `queue:clear`, `queue:shuffle` and `queue:sort`.
Each one is followed by `queue`, which carries the whole list as its payload.
A cursor move emits `item`, carrying the item and its index.

{/* partial */}
```ts
player.on('queue', items => renderList(items));
player.on('item', ({ item, index }) => highlightRow(index));
```

**Replacing the list emits `queue` and not `item`**, even though the cursor lands on the first item.
Read the cursor yourself after a replacement rather than waiting for an event.

A method that changes nothing emits nothing, so an out-of-range remove is silent.

## The backlog

A second list runs alongside the queue, reached through `backlog()`, `backlogAppend()`, `backlogRemove()` and `backlogClear()`.
It emits `backlog`, `backlog:append`, `backlog:remove` and `backlog:clear` in the same shapes.

**Nothing fills it for you.** Playing past an item does not put it there, and `previous()` never reads it.

It is raw storage for a history your own code keeps.
Its contents skip the ingest pipeline above.

## Choosing an item before the queue exists

Calling `item(target)` between `setup()` and `ready()` addresses a queue that has not been seeded yet.

The choice is parked rather than dropped.
The pipeline applies it the moment the playlist lands, which is still inside `ready()`, so a deep link into episode four arrives in time.

## Shuffle order

`queueShuffle()` and shuffle mode both reorder through a strategy object, which defaults to a Fisher-Yates shuffle.

Replace it with `setup({ shuffleStrategy })` to decide the order yourself.
[Shuffle strategy](/nomercy-player-core/plugins-adapters/adapter-shuffle-strategy) has the contract.
