# Core: Typed Errors

Every failure the kit or a plugin raises is a `PlayerError`, never a bare thrown string, so a `catch` block can branch on a type instead of parsing a message.

## The hierarchy

`PlayerError` is the base. Every error carries:

- a stable `code`, such as `core:auth/forbidden` or `fillz:viz/canvas-init-failed`
- a `severity`: `'fatal' | 'error' | 'warning' | 'info'`
- a discriminated `scope`: `{ kind: 'core' }`, `{ kind: 'backend'; id }`, `{ kind: 'plugin'; id }`, and the rest
- an optional `cause` and `context`
- a user-facing `suggestion`

Subclasses narrow the category: `AuthError` (extends `NetworkError`, thrown on 401 and 403), `DrmError`, `MediaFormatError`, `NetworkError`, `ResourceError`, `StateError` for the wrong lifecycle phase, `StreamError`, `PluginError`.

`BrowserPolicyError` is the odd one: a restriction the browser enforces, such as a blocked autoplay policy, or an API it does not support like RemotePlayback or the audio-output picker.

`isHttp(century)` checks `context.httpStatus` against a 1xx to 5xx range, so no call site writes that comparison by hand.

Construct one with a factory rather than the raw constructor where the kit provides one: `stateError(code, message, context?)`, `mediaFormatError(...)`, `resourceError(...)`, `pluginError(...)`, `browserPolicyError(...)`. Each stamps the right `scope` and a sensible default `severity` for you.

## Severity tiers and the error event

Four severities map to four event channels: `fatal` (unrecoverable, the player is shutting down), `error` (recoverable, e.g. a sidecar failed to load), `warning` and `info` (observability only). Every one delivers a `PlayerErrorEvent`: the underlying `error`, its `severity` and `scope`, and DOM-style propagation control (`markHandled()`, `stopImmediatePropagation()`, `preventDefault()` to suppress a kit-side default action like auto-retry).

## Retry policy

`DEFAULT_RETRY_POLICY` is an exported table mapping error codes to a `RetryConfig` of `attempts`, `backoff`, `baseMs`, `maxMs` and `refreshFirst`.

Lookup runs from most to least specific: exact code, then category prefix, then an HTTP range (`'4xx'`, `'5xx'`), then the `'*'` wildcard.

Nothing consults it automatically. Neither `authFetch` nor `Plugin.fetch` reads it, and `Plugin.fetch()` defaults to `{ attempts: 0 }` unless you pass a `RetryConfig`.

In the table, `core:auth/forbidden` never retries, and `core:network/timeout` retries five times with exponential backoff.

To use it, pass an entry from the map, or your own config, as the per-call `retry` option on `Plugin.fetch()`.
