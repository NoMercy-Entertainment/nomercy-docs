# Core: Typed Errors

Every failure the kit or a plugin raises is a `PlayerError`, never a bare thrown string, so a `catch` block can branch on a type instead of parsing a message.

## The hierarchy

`PlayerError` is the base. Every error carries the same shape: a stable `code`, a `severity`, a discriminated `scope` naming where it came from, an optional `cause` and `context`, and a user-facing `suggestion`.

Subclasses narrow the category. There is one for auth, DRM, media format, network, a resource that failed to load, the wrong lifecycle phase, a stream fault, a plugin fault, and a browser policy restriction such as a blocked autoplay.

The full class hierarchy, every field, and the factory functions that construct one with the right `scope` and a sensible default `severity` are on [Reference: Errors](/nomercy-player-core/reference/errors).

## Severity tiers and the error event

Each severity maps to an event channel of the same name:

| Severity | Meaning |
| --- | --- |
| `fatal` | Unrecoverable. The player is shutting down. |
| `error` | Recoverable, for example a sidecar failed to load. |
| `warning` | Observability only. |
| `info` | Observability only. |

Every one delivers a `PlayerErrorEvent`: the underlying `error`, its `severity` and `scope`, and DOM-style propagation control. That control is three methods: `markHandled()`, `stopImmediatePropagation()`, and `preventDefault()` to suppress a kit-side default action like auto-retry.

## Retry policy

`DEFAULT_RETRY_POLICY` maps error codes to attempts, backoff, and whether to refresh auth first, looked up from most to least specific. Nothing consults it automatically: `Plugin.fetch()` defaults to no retry unless you pass a `RetryConfig`, an entry from the map or your own.

The full table, every code, and the lookup precedence are on [Reference: Errors](/nomercy-player-core/reference/errors#default-retry-policy).
