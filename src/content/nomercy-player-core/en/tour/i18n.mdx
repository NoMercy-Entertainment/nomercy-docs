# i18n

Use these methods when UI text must follow a language tag, or when you add strings of your own.
Reading a key and switching language are separate calls.
Merge your strings before you look them up, so the first `fn t` already sees them.

## Look up a key

`fn t` takes a key and returns the string for the active language.
A miss returns the key itself, so a gap stays readable instead of blank.

```ts
player.t('core.state.queueEmpty'); // 'There is nothing in the queue.'
```

Pass a second map when the template has `{name}` placeholders.
Each name in the map replaces its `{name}` in the stored string.

```ts
player.t('core.a11y.playing', { title: 'Big Buck Bunny' }); // 'Playing Big Buck Bunny'
```

The class form of `fn t` takes a plugin class, then a short key.
It looks under `plugin.<id>.` for you, so plugins never hand-write that prefix.

## Set the language

`fn language` with no argument returns the active BCP-47 tag.

```ts
player.language(); // 'en'
```

Pass a tag to switch.
Await the promise, because bundles for that tag and its parents finish loading before it resolves.

```ts
await player.language('pt-BR');
```

English core strings are ready without a fetch.
Other built-in bundles load for the language you switch to, and stay out of memory until then.

You can import the English map to spread into your own setup:

```ts
import { defaultTranslations, enTranslations } from '@nomercy-entertainment/nomercy-player-core';
```

`var enTranslations` is the flat key-to-string map.
`var defaultTranslations` wraps it as `{ en: enTranslations }`, which is the shape `key translations` takes.

A switch announces itself first as `str beforeLanguage` with the requested tag.
A listener may call `preventDefault()` to keep the current language, which then emits `str languagePrevented`.
Writing `var data.lang` redirects the switch to that tag instead.

`str language` fires afterward with the tag that won.

## Add your own strings

`fn addTranslations` merges a map of tag to key/value pairs into the live table.
Existing keys are overwritten.
Keys you omit stay put.

```ts
player.addTranslations({
  en: { 'demo.welcome': 'Welcome, {name}!' },
  nl: { 'demo.welcome': 'Welkom, {name}!' },
});
```

`fn translation` with a tag and key reads one stored entry.
Pass a third argument to write that one entry for the player's lifetime.

`fn removeTranslations` drops every key that starts with a prefix.
Pass a tag to limit the wipe to one language, or omit it to clear across all.

These methods are how you seed demo copy, override a built-in line, or clear a plugin namespace after you dispose it.

## Plugin bundles on a switch

Registered plugins can ship their own strings.
A static `key translations` field loads for each tag in the BCP-47 chain that is not loaded yet.
An instance `fn loadTranslations` hook runs for the target tag when that plugin has not answered it yet.

Keys from the hook are namespaced under `plugin.<id>.` for you.
Each plugin and tag pair is asked at most once per player.
