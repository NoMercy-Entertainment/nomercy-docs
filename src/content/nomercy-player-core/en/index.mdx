# nomercy-player-core

`nomercy-player-core` is the package the video and music players are built from.
You rarely install it yourself; pull in either library and the core comes along as a dependency.
It carries everything that has nothing to do with video or audio in particular: the queue, the auth pipeline, the plugin system, the typed event bus, i18n, storage, and an adapter port for every cross-cutting concern.
Those parts are the same whether you are playing a film or an album, so they live here once instead of twice, and a fix to any of them reaches both players at the same time.
You do not run the core on its own. It is the substrate the library packages stand on.

## What the core provides

- **Lifecycle machine**: 13-phase state machine from `idle` through `playing` to `disposed`
- **Plugin system**: typed `Plugin<P, O, E>` base class, dependency resolution, error quarantine, recovery policy
- **Event bus**: typed `BaseEventMap`, cancellable `before*` events, cross-plugin event routing
- **Auth pipeline**: bearer token injection, 401 refresh, 403 propagation
- **Queue engine**: append, prepend, remove, move, sort, shuffle, backlog
- **i18n**: `ITranslator` adapter, `t()` method, async language loading
- **Storage**: `IStorage` adapter with `LocalStorageBackend`, `MemoryStorageBackend`, `IndexedDBBackend`
- **Metrics**: `PlaybackMetrics` shape, `recordMetric()`, throttled `playback:metrics` event
- **Adapter ports**: pluggable interfaces for every cross-cutting concern

## When to depend on the core directly

Most consumers install `nomercy-video-player` or `nomercy-music-player`.
Both packages re-export the core's public API.
Install `nomercy-player-core` directly only if you:

- Are writing a library-level plugin that must work with both video and music players without importing either
- Are building a new library package on top of the core

```
npm install @nomercy-entertainment/nomercy-player-core@rc
```
