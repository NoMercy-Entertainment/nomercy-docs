# Build a Player: Compose the Methods

This is a four-step tutorial that assembles a player from the kit one capability at a time: compose the shared methods, wire a backend contract, add a plugin, add i18n. Each step is a complete, typechecked file that extends the one before it. By the end you'll have one class exhibiting all four.

## The shell

Every step in this tutorial starts from the same three ingredients [Quickstart](/nomercy-player-core/quickstart) introduces: extend `EventEmitter` so `.on()` / `.emit()` work, resolve the three-form constructor with `resolvePlayerConstructor` + `initPlayerCoreState`, then stamp `playerCoreMethods` onto the prototype with `composeMixins`. If you haven't read Quickstart yet, do that first, it explains why each of the three pieces exists. This page treats that explanation as done and moves straight to using the result as a foundation.

## Why this is the right starting point

`playerCoreMethods` is the full aggregate `NMVideoPlayer` and `NMMusicPlayer` compose onto their own prototypes, not a cut-down subset for demo purposes. That means `MinimalPlayer` above already has setup, the phase machine, the queue, volume, i18n, plugin registration, and auth, everything except a media backend. The next three steps don't add kit machinery, they add the pieces a consumer supplies: a backend, a plugin, and translations.

## What's next

Step 2 gives the kit something to talk to: a `backend()` method, the same integration point `NMVideoPlayer` uses for its `<video>` element.
