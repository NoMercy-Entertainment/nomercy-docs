# Compose the Methods

Stamp shared methods onto a class prototype and resolve mount versus reuse the same way `NMVideoPlayer` and `NMMusicPlayer` do.

## composeMixins

```ts
function composeMixins<T extends object>(prototype: T, ...modules: object[]): void;
```

`composeMixins` copies each module's own property descriptors onto `prototype` with `Object.getOwnPropertyDescriptors` and `Object.defineProperty`.
Getters and setters land as accessors.
They are not triggered during the copy.

Later modules win when two modules export the same key.
List more specific modules after more general ones.
Calling the same module twice is safe; the second call overwrites with identical descriptors.

## resolvePlayerConstructor

```ts
function resolvePlayerConstructor<C>(
	id: string | number | undefined,
	instances: Map<string, C>,
	className: string,
): PlayerCtorResolution<C>;

type PlayerCtorResolution<C>
	= | { kind: 'existing'; instance: C }
		| { kind: 'mount'; id: string; div: HTMLDivElement };
```

Pass the same three forms the video and music factories accept: a string id, a numeric registry index, or `undefined`.

- **`undefined`**: returns the first registered instance. Throws `core:player/no-element` when the registry is empty.
- **A number**: indexes insertion order. Throws `core:player/not-found` when the index is out of range.
- **A string**: returns `existing` when that id is already registered. Otherwise resolves `document.getElementById(id)`, requires a `<div>`, and returns `mount`. Throws `core:player/element-missing` or `core:player/element-not-div`.

The `document` lookup is guarded for SSR.
An invalid id type throws `core:player/invalid-id-type`.

On `mount`, call `initPlayerCoreState` with `{ className }` set to the same string you passed to `resolvePlayerConstructor`.
Then bind `playerId` and `container`, and register the instance.
On `existing`, return the registered instance.

## playerCoreMethods

`playerCoreMethods` is exported from `@nomercy-entertainment/nomercy-player-core`.
It is the `as const` tuple both real players spread into `composeMixins`.

It includes, in order: `lifecycleMethods`, `baseUrlAudioContextMethods`, `experimentalDescriptor`, `i18nMethods`, `cueParserMethods`, `transportMethods`, `timeMethods`, `volumeMethods`, `stateMethods`, `playerStateMethods`, `queueMethods`, `playQueueMethods`, `pluginRegistrationMethods`, `authMethods`, `streamRegistrationMethods`, `mediaTracksMethods`, `deviceMethods`, `audioOutputMethods`, `castMethods`, `abrMethods`, `metricsMethods`, `loadingMethods`, `containerClassEmitMethods`, `activityMethods`, and `preloadStrategyMethods`.

```ts
composeMixins(MyPlayer.prototype, ...playerCoreMethods);
```
