# Compose the Methods

Use this when your class should behave like the video and music players: shared methods on the prototype, and a constructor that either mounts a `el div` or hands back a player you already created.

## Add the methods

```ts
function composeMixins<T extends object>(prototype: T, ...modules: object[]): void;
```

Call `fn composeMixins` with your prototype and the bundles you want.
Getters and setters are copied as accessors.
They do not run during the copy.

When two bundles export the same name, the later bundle wins.
Put the more specific bundle after the more general one.
Calling the same bundle twice is safe.
The second call writes the same descriptors again.

## Mount or reuse

```ts
function resolvePlayerConstructor<C>(
	id: string | number | undefined,
	instances: Map<string, C>,
	className: string,
): PlayerCtorResolution<C>;
```

Pass a string id, a number, or nothing.

- Nothing returns the first player you already created.
- An empty registry throws `str core:player/no-element`.
- A number selects by the order you created players.
- An index past the end throws `str core:player/not-found`.
- A known string returns that player.
- A new string finds `fn document.getElementById` and requires a `el div`.
- A missing element throws `str core:player/element-missing`.
- A node that is not a `el div` throws `str core:player/element-not-div`.
- Any other id type throws `str core:player/invalid-id-type`.

The document lookup is skipped when there is no `var document`, so the same call can run during server render.

On a new mount, call `fn initPlayerCoreState` with `{ className }` set to the same string you passed to `fn resolvePlayerConstructor`.
Then store the id and the `el div`, and register the instance.
If that id was already registered, return the existing player instead.

## What you pass in

`var playerCoreMethods` is the set you spread into `fn composeMixins`.
It adds the shared behavior: lifecycle, queue, transport, time, volume, plugins, and auth.

```ts
composeMixins(MyPlayer.prototype, ...playerCoreMethods);
```
