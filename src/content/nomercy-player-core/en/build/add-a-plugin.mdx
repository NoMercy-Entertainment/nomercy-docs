# Add a Plugin

A plugin is extra behavior you add to a player, such as counting each play.
Use this page when you want a class you can ship onto a composed player.
[Plugins](/nomercy-player-core/tour/plugin-base) covers subclassing and lifecycle.
[Registration](/nomercy-player-core/handbook/registration) covers timing, checks, and removal.

## What you ship

Subclass `cls Plugin`.
Set a static `key id` and `key description`.
Add `key version` when you want a semver string on the class.
Override `fn use` to subscribe and start the work.
Pass that class to `fn addPlugin`, with options when the plugin needs them.
You do not construct the instance yourself.

| Piece | Role |
| --- | --- |
| `key id` | Stable name for events and storage |
| `key description` | A one-line summary for people; core does not read it |
| `fn use` | Subscribe and start the behavior |
| options on `fn addPlugin` | Config for that install |

Inside `fn use`, use the protected helpers.
`fn on` listens on the player or on another plugin by class.
`fn emit` fires under `plugin:<id>:`.
`fn dispose` is only for resources those helpers never tracked.

## Register, then set up

Call `fn addPlugin` before `fn setup` so install runs in the setup pipeline.
After setup, the same call still installs, and `fn ready` waits for it.

:::snippet{file="core-build-add-a-plugin" lines="98-102" live="false"}

`key plugins` on setup is sugar over that same `fn addPlugin` path.
Pass a class, or `{ plugin, opts }` when the plugin takes options.

## Hear what it emits

A consumer listens on the player for the namespaced name.
For id `play-counter` and event `milestone`, that name is `str plugin:play-counter:milestone`.
`fn getPlugin` returns the live typed instance, or `undefined` when it is missing.
