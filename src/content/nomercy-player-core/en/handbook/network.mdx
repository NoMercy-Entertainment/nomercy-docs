# Network

Use `fn authFetch` when a request needs auth headers, typed decoding, and a bounded retry loop.
Playlist URL loads share this same pipeline.
The [auth fetch recipe](/nomercy-player-core/recipes/auth-fetch) shows how to call it from your own code.

Import `fn authFetch`, `fn isAuthError`, and `fn isNetworkError` from `@nomercy-entertainment/nomercy-player-core`.
Every call needs `key url` and a required `key signal`.
`key auth` is optional.

## What one attempt does

Each loop pass builds one `Request`, races it against an optional `key timeoutMs`, then classifies the result.
There is no default HTTP timeout.
Omit `key timeoutMs`, or pass `0` or less, and only the abort signal can stop a hung fetch.

A thrown fetch with an aborted signal ends as `str core:network/aborted`.
A timeout or offline throw becomes a retry outcome and stashes a terminal error.

HTTP `401` refreshes once when that hook is set and the refresh budget is open, then retries without spending a retry slot.
A `401` with no budget left throws `str core:auth/unauthenticated`.
A `403` throws `str core:auth/forbidden` at once.

Other `4xx` statuses throw a matching network code with no retry.
A `5xx` status becomes a retry outcome and stashes the matching server code.
Success hands the response to the decoder.

Every failure ends with one of these codes:

| Cause | Code | Retried |
| --- | --- | --- |
| `401`, and the refresh hook threw | `str core:auth/refresh-failed` | No |
| `401`, no refresh left | `str core:auth/unauthenticated` | No |
| `403` | `str core:auth/forbidden` | No |
| `404` | `str core:network/not-found` | No |
| `408` | `str core:network/request-timeout` | No |
| `410` | `str core:network/gone` | No |
| `429` | `str core:network/rate-limited` | No |
| Any other `4xx` | `str core:network/client-error` | No |
| `500` | `str core:network/server-error` | While attempts remain |
| `502` | `str core:network/bad-gateway` | While attempts remain |
| `503` | `str core:network/service-unavailable` | While attempts remain |
| `504` | `str core:network/gateway-timeout` | While attempts remain |
| Any other `5xx` | `str core:network/server-error-other` | While attempts remain |
| No response within `key timeoutMs` | `str core:network/timeout` | While attempts remain |
| The network request failed | `str core:network/offline` | While attempts remain |
| The abort signal fired | `str core:network/aborted` | No |
| The body could not be decoded | `str core:network/parse-failed` | No |

A retried failure throws its code once the attempts run out.

## How the body is decoded

`key responseType` chooses the decode path after a successful status.
Omit it, or pass `str text`, and the body is the response string.
Pass `key parser` only on that text path; the callback turns the string into `T`.
`str json` calls `response.json()` and casts to `T`.
`str arrayBuffer` returns the binary buffer.

A thrown `key parser` or invalid JSON surfaces as `str core:network/parse-failed`.

## How the retry loop spends its budget

The retry loop keeps calling until a value returns, a throw ends the call, or the attempt budget is gone.
`cls RetryConfig` defaults to `{ attempts: 0 }`, so `key maxAttempts` is `1`.
With that default, a retryable failure still waits the backoff, then throws the stashed error.

Backoff is linear unless you set `key backoff` to `str exponential`.
`key baseMs` defaults to `500`.
`key maxMs` defaults to `30_000`.

A refresh retry uses `0` delay and does not consume an attempt slot.
The refresh budget is at most one, and only when `key refreshOnUnauthenticated` is set and `key retryAfterRefresh` is not `0`.

## Where fetch events land

Pass `key emit` when you want `str fetch:start`, `str fetch:retry`, and `str fetch:complete` on a bus.
Without `key emit`, those names are silent no-ops.

`key scope` picks the name shape when emit is present: `str plugin` with a plugin id, `str player` for the global names, or `str silent` for nowhere.
When `key pluginId` is set and `key scope` is omitted, the default is `str plugin`.
Otherwise the default is `str player`.

## Narrow a failure

Thrown values are `cls AuthError` or `cls NetworkError`.
`fn isAuthError` and `fn isNetworkError` are the type guards.
Check auth first when you need to tell the two apart.
