# Anatomy

Use this page when you need the shape of Player Core under a composed class.
The shared modules ship as one ordered tuple.
Two early accessors hold a URL prefix and a shared audio context.

## The shared tuple

`var playerCoreMethods` is every shared mixin in one `as const` list.
Spread it into `fn composeMixins` on your prototype.
Video and music players take the same list.

```ts
composeMixins(MyPlayer.prototype, ...playerCoreMethods);
```

Lifecycle and the base URL accessors come early in that list.
Adding a new shared mixin means appending it to that same list.
The core layer also re-exports the constructor helper, state seed, error helpers, and each mixin on its own.

## Base URL and audio context

After composition, `fn baseUrl` and `fn audioContext` live on the instance.

| Call | Role |
| --- | --- |
| `fn baseUrl` with no argument | Returns the prefix, or `undefined` |
| `fn baseUrl` with a string | Stores that prefix |
| `fn audioContext` | Returns the shared context, or `undefined` |

`fn baseUrl` does not need another `fn setup`.
A string argument replaces the stored prefix.
With no argument, you only read.

`fn audioContext` is read-only on the player.
Something else writes the context with `fn setPlayerAudioContext`.
Until that write, the getter returns `undefined`.
Plugins that need the Web Audio graph should read this instead of creating their own.

```ts
player.baseUrl();
player.baseUrl('https://api.example.com/files');
player.audioContext();
```
