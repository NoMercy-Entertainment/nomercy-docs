# Registration

A plugin is extra behavior you add, such as counting plays.
[Plugins](/nomercy-player-core/tour/plugin-base) covers subclassing and the first `fn addPlugin` call.
This page is the contract that call enforces: timing, checks, lookup, and removal.

## When the call runs

Before or during `fn setup`, `fn addPlugin` queues the class and returns the player.
After setup, the same call starts registration at once and returns without waiting.
Listen for `str plugin:installed` or `str plugin:failed`, bare or with the id in the name.
Call `fn ready` again when you need that in-flight install to finish.

After `fn dispose` has started, `fn addPlugin` throws `str core:lifecycle/use-plugin-after-dispose`.

## Checks that throw

`fn addPlugin` validates before it queues or installs.
These codes throw at the call site:

| Code | When |
| --- | --- |
| `str core:lifecycle/use-plugin-after-dispose` | Player disposing or disposed |
| `str core:plugin/duplicate-id` | Same `key id` already registered or queued |
| `str core:plugin/missing-dep` | Required dependency absent |
| `str core:plugin/version-mismatch` | Dependency older than `key minVersion` |
| `str core:plugin/incompatible-core-version` | Running core older than `key minCoreVersion` |

## Requires, replaces, and priority

Static `key requires` lists peers that must already be registered or queued.
Pass a class, or `{ plugin, optional, minVersion }`.
A missing optional dependency is allowed.
Queued peers satisfy the check, so call order among `fn addPlugin` calls only needs the dependency added first.

Static `key replaces` names an id to swap out.
If that id is registered, it is removed first.
If it is only queued, the queue entry is dropped.
If it is absent, install continues as new.

Static `key priority` sorts `fn enabledPlugins`: higher first, ties keep registration order.
Default is `0`.

Static `key minCoreVersion` pins the minimum Player Core version.
A lower running version throws `str core:plugin/incompatible-core-version`.

## Install steps and timeout

Registration constructs the instance, calls `fn initialize`, merges static translations, then awaits `fn use`.
A promise from `fn use` is capped by `key pluginInitTimeoutMs` on setup, default 30 seconds.
Past the cap, registration fails with `str core:plugin/init-timeout`.

A failure after the sync checks does not throw from `fn addPlugin`.
The half-built instance is disposed, `str plugin:failed` fires, and enabled dependents get `fn disable` with reason `dep-failed:<id>`.

## Look up and remove

`fn getPlugin` takes the class and returns a typed instance, or `undefined`.
`fn getPluginById` takes a string id when the class is out of scope.
`fn plugins` returns every registered instance in registration order.
`fn enabledPlugins` returns only enabled ones, ordered by priority.

`fn removePlugin` and `fn removePluginById` dispose the entry and emit `str plugin:disposed`.
Dependents are removed first by default.
Pass `{ cascade: false }` to throw `str core:plugin/has-dependents` instead.
A queued id is cleared so it never installs later.

```ts
player.addPlugin(PeerPlugin);
player.addPlugin(FeaturePlugin, { everyNPlays: 2 });
```
