# Emitting

Use this page when you need to cancel or reshape an action before it runs.
The same emit path also keeps container CSS classes current, and flips play state on `str fatal`.

## Before the action runs

Transport and plugins run a shared `before*` pass before they change state.
Listeners receive a mutable event object.
They can reshape `key data`, call `fn preventDefault`, stop later listeners, or `fn delay` on a promise.

```ts
player.on('beforePlay', (e) => {
  e.preventDefault();
});
```

Listeners run in subscription order.
`fn stopImmediatePropagation` skips the rest of that pass.
A throwing listener is logged and does not stop the others.

`fn delay` holds the action until every delayed promise settles.
They wait together.
Any rejection prevents the action.
So does a wait that exceeds the timeout, which defaults to 10 000 ms.

When the pass finishes, the caller gets an outcome.
Use `key data` from that outcome, not the object you started with.
If `key prevented` is true, abort and do not emit the success event.

This table lists the prevented reasons that pass returns.

| Reason | When it is set |
| --- | --- |
| `str listener-prevented` | A listener called `fn preventDefault`. |
| `str delay-rejected` | A delayed promise rejected. |
| `str delay-timeout` | The wait exceeded the timeout. |

While the pass runs, including any delayed wait, the event name sits on the dispatch stack.

## What emit updates first

`fn emit` still delivers to listeners.
Before that walk, two sync steps run.

`str fatal` sets play state to `str error` first.
Fatal listeners already see that settled state.
`str error`, `str warning`, and `str info` do not change play state.

Mapped events also update classes on the player container.
Playback swaps among `str playing`, `str paused`, `str stopped`, `str ended`, `str loading`, and `str buffering`.
`str play` and `str playing` add `str playing`.

`str pause`, `str stop`, and `str ended` add their matching class.
`str waiting` and `str stalled` add `str buffering` and drop `str playing`.
`str canplay` and `str time` drop `str buffering`.

`str mute`, `str fullscreen`, `str pip`, and `str theater` toggle from a boolean field on the payload.
`str activity` swaps `str active` and `str inactive`.

`str phase` with `key to` of `str ready` rests on `str paused`, or stays `str playing` when play state is already playing.
After that first ready, a later `str loading` phase leaves the resting class alone.

No container yet means the class step is a no-op.
Listeners still run.
