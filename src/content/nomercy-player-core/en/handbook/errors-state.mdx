# Errors and State

Use these helpers when a plugin must escalate a fault, pause its work, or expose a snapshot.
They stamp `var scope.kind` as `str plugin` with your id.
Catching typed `cls PlayerError` values belongs on [Errors](/nomercy-player-core/tour/errors).

## Raise or report

`fn throw` builds a `cls PlayerError`, surfaces it, then throws that same value.
Use it when the current operation cannot continue.
Severity defaults to `str error`.

`fn report` surfaces a fault and returns.
Your current flow continues.
Severity defaults to `str warning`.

Both take a `ThrowPayload`.
Fill `key code`, and optionally `key message`, `key cause`, `key context`, `key suggestion`, `key severity`, and `key id`.

```ts
this.throw({
	code: 'plugin:spectrum/bad-config',
	message: 'bars must be at least 1',
	suggestion: 'Pass bars: 32 or omit the option.',
});

this.report({
	code: 'plugin:spectrum/no-audio-graph',
	message: 'no audio graph found',
});
```

The player emits the severity channel (`str error`, `str warning`, `str info`, or `str fatal`).
For `str error` and `str warning`, it also emits `str plugin:error` or `str plugin:warning`.
The payload is `{ error, severity, scope, timestamp }`.

A raw `throw new Error(...)` skips the stamp and those events.

## Recover with onError

`key onError` maps a code string to a `PluginRecoveryAction`.
The map runs right after the fault is surfaced.

| Action | What runs |
| --- | --- |
| `str ignore` | Nothing further |
| `str disable` | `fn disable` with reason `onError:<code>` |
| `str retry-once` | Your `fn retryLastOperation` when present |
| `str fallback` | Your `fn activateFallback` when present |

Missing hooks for `str retry-once` or `str fallback` only log a warning.
You own those method bodies.

## Enable and disable

`fn enabled` reads the flag.
A new plugin starts enabled.

`fn enable` and `fn disable` flip it without unloading.
Both are safe to call again.
Disable may pass a `key reason`.
They emit `str plugin:enabled` or `str plugin:disabled`, bare and id-namespaced.

Listeners from `fn on` stay subscribed either way.
Check `fn enabled` inside your handlers when work should stop.

A failed dependency registration can also call `fn disable` with reason `dep-failed:<id>`.

## Snapshot and options

`fn state` returns a `PluginState` with `key id`, `key version`, `key enabled`, `key opts`, and `key runtime`.
Override `fn getRuntimeState` to fill `key runtime`.
The default is `{}`.

```ts
class PlayCounter extends Plugin {
	protected override getRuntimeState(): Record<string, unknown> {
		return { framesRendered: this.framesRendered };
	}
}
```

`fn options` with no argument returns a frozen shallow copy.
Pass a partial object to shallow-merge and announce the change.
That write emits `str plugin:opts:changed`, the id-namespaced twin, and plugin-scoped `str opts:changed`.

Writing `var this.opts` fields by hand skips those events.

## Logger and storage

`key logger` is a child logger prefixed with your id.
`key storage` prefixes keys as `nmplayer-<id>-`.
Both exist before `fn use` runs.
They follow the player's logger and storage adapters when those are set.
