# Recipe: Provide a Custom URL Resolver

Use `cls IUrlResolver` when a consumer needs a finished URL string and cannot take an `key authorization` header.
The [auth fetch recipe](/nomercy-player-core/recipes/auth-fetch) covers requests your own code fetches.
This recipe covers the cases that only accept a URL.

## The task

Your media host needs a signed `token` query on media URLs.
Poster and subtitle URLs from the same host stay unsigned.

Pass `key urlResolver` into `fn setup`.
That replaces the built-in resolve for later `fn resolveUrl` calls.
`key category` on the context names the consumer.
Call `key defaultResolve` for every category you leave alone.

:::snippet{file="core-recipes-custom-url-resolver" live="false"}
:::

The host in the sample stands for your own backend.

## Reading the result

`fn resolveUrl` returns a `cls ResolvedUrl`.

| Field | What it does |
| --- | --- |
| `key href` | The final string. |
| `key searchParams` | Reads the query. |
| `key ext` | Gates on file type. |

Prefer `key ext` over splitting on a dot.
The extension survives query strings and fragments.

`key relative` is `true` when the input stayed relative and no base URL could absolutize it.
A `true` value means the string you got is not an absolute URL.

## Swap it later

`fn urlResolver` with no argument returns the active custom resolver, or `undefined` when the built-in path is active.
Pass a function to replace it.
Pass `undefined` to revert.
The change applies on the next `fn resolveUrl` call.
