# Recipe: Swap an Adapter

Use this recipe when one built-in adapter should change for the whole player.
You name the field on `fn setup` and pass an instance the package already exports.
This walkthrough replaces storage with `cls IndexedDBBackend`.

## What you import

Import the backend from `@nomercy-entertainment/nomercy-player-core`.
The package root also exports `cls LocalStorageBackend` and `cls MemoryStorageBackend`.
Omit `key storage` and plugins get `cls LocalStorageBackend`.

| Export | Role |
| --- | --- |
| `cls LocalStorageBackend` | Default. Sync. Falls back to memory when blocked. |
| `cls IndexedDBBackend` | Opt-in. Async. Opens the database on the first call. |
| `cls MemoryStorageBackend` | In memory. Values are lost on reload. |

## Make the swap

Pass `key storage` on `fn setup` with `new IndexedDBBackend(...)`.
Plugins call `fn this.storage` and do not name which backend is active.
Each plugin gets a namespaced wrapper, so keys stay separate.

All three backends share the same five methods: `fn get`, `fn set`, `fn remove`, `fn getJSON`, and `fn setJSON`.
Await them in plugin code either way.
Sync backends resolve at once under `await`.

:::snippet{file="core-recipes-swap-an-adapter" live="false"}
:::

The sample plugin writes and reads JSON through that same surface.
You do not change call sites inside the plugin when the backend changes.

When IndexedDB is missing, `cls IndexedDBBackend` rejects with `str core:policy/indexedDBUnsupported`.
Use `cls LocalStorageBackend` or `cls MemoryStorageBackend` in that environment.
