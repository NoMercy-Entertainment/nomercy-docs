# Recipe: Register a Custom Cue Parser

Use this when your timed text is not one of the built-in formats.
You write a parser, register it on the player, and resolve it by URL.

## Write the parser

Import `cls ICueParser` and `fn createCueList` from `@nomercy-entertainment/nomercy-player-core`.
A parser needs three pieces.

| Piece | Role |
| --- | --- |
| `key id` | Name used to unregister later |
| `fn canParse` | Returns true when this format owns the URL |
| `fn parse` | Turns raw text into a cue list |

Returning true from `fn canParse` is a commitment.
Nothing else is tried for that URL.

## Register on the player

Pass `key cueParsers` in `fn setup`.
Player Core seeds its built-in parsers first, then yours.
A later match wins when more than one `fn canParse` accepts the same URL.

`fn registerCueParser` adds one after setup.
Pass `prepend: true` to put it at the low-priority end.
`fn unregisterCueParser` removes by `key id`.
Re-registering the same `key id` replaces the old entry.

## Prove the match

`fn resolveCueParser` takes a URL and returns the winning parser, or `undefined`.
Use it to confirm your format resolves without stealing a built-in extension you still need.
