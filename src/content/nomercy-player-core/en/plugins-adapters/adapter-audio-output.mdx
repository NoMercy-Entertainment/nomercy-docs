# AudioOutputState

`cls AudioOutputState` holds the selected device id on the player.
Three methods beside it list outputs, open the browser picker, and route sound.
They live on `cls IPlayer`.
There is no setup field that replaces them.

```ts
import type { IPlayer } from '@nomercy-entertainment/nomercy-player-core';
```

## Built-in adapter

The built-in surface is those three methods on a composed player.
`playerCoreMethods` includes them.

| Method | Behavior |
|---|---|
| `fn audioOutputs` | Resolves to `audiooutput` devices, or `[]` when enumeration is missing. |
| `fn selectAudioOutput` | Opens the browser picker. `str AbortError` or `str NotAllowedError` yields `null`. |
| `fn audioOutput` | Reads the active id, or routes with a `key deviceId`. |

`fn audioOutputs` never throws for a missing API.
It resolves to an empty array instead.

`fn selectAudioOutput` throws `cls BrowserPolicyError` with `str core:policy/audioOutputPickerUnsupported` when the picker is absent.
The throw message names Chrome 105 and later.
`str AbortError` and `str NotAllowedError` resolve to `null`.
Any other rejection is rethrown.

`audioOutput(deviceId)` calls `fn setSinkId` on the bound media element, then stores the id.
An empty string clears the stored id to `null`.
It throws `cls BrowserPolicyError` with `str core:policy/setSinkIdUnsupported` when the element is missing or has no `fn setSinkId`.

`audioOutput()` with no argument reads the live `key sinkId` when present, else the stored id.
An empty string reads back as `null`.

## Interface

```ts
interface AudioOutputState {
	_currentAudioOutputId: string | null;
}
```

`key _currentAudioOutputId` is written by `audioOutput(deviceId)`.
The three methods on `cls IPlayer` are:

```ts
audioOutputs(): Promise<MediaDeviceInfo[]>;
selectAudioOutput(): Promise<MediaDeviceInfo | null>;
audioOutput(): Promise<string | null>;
audioOutput(deviceId: string): Promise<void>;
```

## Custom implementation

These methods are not a setup adapter.
You do not pass a replacement object in.
For tests, `cls StubPlayer` already stubs all three.

```ts
import { StubPlayer } from '@nomercy-entertainment/nomercy-player-core/testing';

const player = new StubPlayer();

await player.audioOutputs();
await player.selectAudioOutput();
await player.audioOutput();
```

`fn audioOutputs` resolves to `[]`.
`fn selectAudioOutput` and a bare `fn audioOutput` resolve to `null`.
A write with a `key deviceId` resolves without routing.
