# Plugin: Message

`cls MessagePlugin` (id `str message`) puts a text surface on the player container for feedback the transport has no room for: a quality switch, a reconnect, a refused action. Transient messages hide themselves after a delay, a queue plays several in sequence, and a persistent message stays under a name you chose until you take it away.

The package root does not re-export the class, so it comes from the `plugins/message` subpath.

## Options

| Option | Type | Default | What it does |
|---|---|---|---|
| `key durationMs` | `ts number` | `ts 3000` | Delay used by `fn queue` and `fn displayMessage` when a message names none of its own. |
| `key mountSelector` | `ts string` | none | A selector for an element the plugin should use as the surface. |

## The surface

With no `key mountSelector`, the plugin creates a `<div>` inside the player container with the class `str nmplayer-message-toast`. It carries `ts role="status"` and `ts aria-live="polite"`, so a screen reader announces updates without taking focus. It stays hidden until something is shown, and it goes away when the plugin disposes.

`key mountSelector` hands that job to an element you already have. The plugin runs `ts document.querySelector` across the whole page, stamps the same two attributes onto whatever it finds, and treats that element as the surface from then on. Showing a message replaces its contents.

Point it at an empty element you own, anywhere in the document. The attributes and the last text stay behind after teardown.

No stylesheet ships with the plugin. Both classes are yours to style.

## Transient messages

`fn show` takes the text and, as a second argument, the milliseconds to keep it up. That second argument defaults to `ts 3000` on its own. `key durationMs` is the setting for the other two entry points rather than for this one:

```ts
toast.show('Quality switched to 1080p');
toast.show('Reconnecting', 8000);
```

`fn displayMessage` is the form that takes either a string or `ts { text, durationMs }`, and it does read `key durationMs` as its fallback. `fn queue` takes an array of those same two shapes and plays them back to back, each for its own delay:

```ts
toast.queue(['Buffering', { text: 'Reconnected', durationMs: 2000 }]);
```

A new `fn show` replaces whatever is on screen and restarts the timer. Calling `fn queue` again, or `fn clear`, cancels a run already in flight.

## Persistent messages

`fn displayPersistent` takes the text and an id. It appends a `<div>` with the class `str nmplayer-message-persistent` and a `key data-persistent-id` attribute holding that id, with the same two ARIA attributes as the toast.

Nothing hides it, and `fn clear` leaves it alone. `fn removePersistent` with the same id takes it away, and `fn dispose` removes every one that is left.

Calling `fn displayPersistent` twice with one id updates the text in place rather than stacking a second element. That is what makes it usable for a status that keeps changing while it stays up.

## Rules & restrictions

- The transient surface is single-slot. There is one toast, and a second message takes the first one's place rather than sitting under it. Persistent messages are the ones that coexist.
- `fn show` expects a string. Hand it an object and the object is what appears.
- `fn clear` cancels the queue and hides the toast, and touches no persistent message.
- Both element classes are namespaced on the plugin id, so nothing else in the kit claims them.

## How to extend it

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player';
import { MessagePlugin } from '@nomercy-entertainment/nomercy-player-core/plugins/message';

const player = nmplayer('player');

player.addPlugin(MessagePlugin, { durationMs: 4000 });
player.setup({ playlist: [] });
await player.ready();

const toast = player.getPlugin(MessagePlugin);

toast?.show('Quality switched to 1080p', 4000);
toast?.queue(['Buffering', { text: 'Reconnected', durationMs: 2000 }]);

player.on('backend:waiting', () => toast?.displayPersistent('Buffering', 'buffering'));
player.on('play', () => toast?.removePersistent('buffering'));
```

Every message the kit itself shows goes through `fn t` first, so a subclass that translates its own text follows the same route:

```ts
import { MessagePlugin } from '@nomercy-entertainment/nomercy-player-core/plugins/message';

class QualityMessagePlugin extends MessagePlugin {
  announceQuality(height: number): void {
    this.show(this.t('quality.switched', { height: String(height) }));
  }
}
```
