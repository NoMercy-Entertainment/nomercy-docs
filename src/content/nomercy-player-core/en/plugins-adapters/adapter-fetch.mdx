# IFetch

Use `cls IFetch` when a helper of yours sends HTTP requests and a test must swap the transport.
It is a call signature with the shape of the global `fn fetch`, taking a string URL.

There is no `key fetch` option in `fn setup`.
The player and `fn authFetch` call the global `fn fetch` directly, so this type never reaches the player.

:::snippet{file="core-adapter-fetch" lines="17-18" live="false"}
:::

## Built-in adapter

`var defaultFetch` is the shipped `cls IFetch`.
It forwards the URL and the options to the global `fn fetch` and returns its promise.
Nothing inside the package calls it.

## Usage

Type the transport parameter as `cls IFetch`, and pass `var defaultFetch` in the app.

:::snippet{file="core-adapter-fetch" lines="20-32" live="false"}
:::

The host in the sample stands for your own API.

## Interface

`cls IFetch` has one call signature and no members.

| Part | Type |
|---|---|
| `key url` | `string` |
| `key opts` | `RequestInit`, optional |
| Return | `Promise<Response>` |

`RequestInit` and `Response` are the standard fetch types from the browser's own DOM lib, not something this package defines.

## Custom implementation

Write your own `cls IFetch` when a test must answer without a network.
The helper above takes it unchanged.
