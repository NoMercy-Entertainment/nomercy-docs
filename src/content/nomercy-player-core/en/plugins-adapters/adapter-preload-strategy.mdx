# Adapter: Preload Strategy

`cls IPreloadStrategy` answers two questions about the item after the one playing: whether the boundary is close enough to act on, and which of that item's assets belong in the list.

Swap it to move the moment, to shorten the list on a metered connection, or to build the list from fields of your own that the shipped strategies know nothing about. [Adapters](/nomercy-player-core/tour/adapters) puts the port beside the others.

## The interface

```ts
interface IPreloadStrategy {
	shouldPreload(context: PreloadContext): boolean;
	assetsToPreload(item: BasePlaylistItem): PreloadAsset[];
	cancel(): void;
}
```

`cls PreloadContext` is a read-only snapshot of three fields, so a strategy never reaches into player state: `key currentTime` and `key duration` in seconds, and `key nextItem`, which is `ts null` at the end of the queue.

A `cls PreloadAsset` is a `key url` and a `key category`. The category names the kind of file, and the shipped strategies use `str media`, `str poster`, `str subtitle`, `str sprite`, `str lyrics`, `str chapter` and `str font`. Any string is accepted, so a category of your own passes through.

## What the player does with it

`fn shouldPreload` is asked on every `str time` event while a next item exists. The first `ts true` fires the pass and the player stops asking until the cursor moves, so a strategy needs no throttle of its own.

The pass then calls `fn assetsToPreload` once and works through the answer:

| Event | When | Payload |
|---|---|---|
| `str preloadStart` | Immediately, before any request | The `key item`, and every asset as a `key url` and `key category` |
| `str preloadProgress` | Once per asset | The `key item`, plus `key loaded` and `key total` |
| `str preloadComplete` | After the last asset, or at once for an empty list | The `key item` |
| `str preloadError` | When an asset's URL cannot be turned into a request | The `key item` and the `key error` |

Each asset is asked for with a single `HEAD` request at `key mode` `str no-cors`, carrying no headers. Hanging your own warming on `str preloadStart` is what gives you the shape of the request, so an asset behind a bearer token is fetched the way the rest of your application fetches one.

A cursor change ends the pass. The player calls `fn cancel`, rearms `fn shouldPreload` for the new item, and drops any progress still in flight from the old one without emitting for it.

## Default implementation

`cls DefaultPreloadStrategy` answers `ts true` once `key currentTime` reaches `key duration` minus its lead, which is ten seconds unless `key preloadLeadSeconds` says otherwise. It answers `ts false` with no next item and `ts false` while `key duration` is still zero. Its own asset list is empty.

Both shipped players extend it and supply the list:

| Player | Assets, in order |
|---|---|
| Video | the item's `key url` as `str media`, its poster image, `key previewSpriteUrl` as `str sprite`, every subtitle sidecar, every chapter track file, and every font file |
| Music | the item's `key url` as `str media`, its cover image as `str poster`, and `key lyricsUrl` as `str lyrics` |

Each of them is constructed with the same `key preloadLeadSeconds` the config carries, and a `key preloadStrategy` you pass replaces it outright.

## Where to import it from

```ts
import { DefaultPreloadStrategy } from '@nomercy-entertainment/nomercy-player-core';
import type { IPreloadStrategy, PreloadAsset, PreloadContext } from '@nomercy-entertainment/nomercy-player-core';
```

All four are on the `./adapters/preload` subpath as well.

## Rules & restrictions

- `fn cancel` has to abort whatever this strategy started. The player calls it on every cursor change and again inside `player.setPreloadStrategy(next)`, and it is the only signal a strategy gets that its work is unwanted.
- `player.preloadStrategy()` reads back the instance in force, and `player.setPreloadStrategy(next)` replaces it. The swap takes effect on the following `str time` tick.
- Extending `cls DefaultPreloadStrategy` and overriding `fn assetsToPreload` keeps the lead-second timing and the abort handling. Implementing the interface from scratch means owning both.
- `fn assetsToPreload` runs once per cursor cycle, so building the list is a cheap synchronous job rather than a place to fetch anything.

## How to extend it

This one holds off until five seconds remain and asks for artwork alone:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player'; // nomercy-music-player's factory works identically
import type { IPreloadStrategy } from '@nomercy-entertainment/nomercy-player-core';

const artworkOnly: IPreloadStrategy = {
	shouldPreload: ctx => ctx.duration > 0 && ctx.duration - ctx.currentTime <= 5,
	assetsToPreload: item => (item.image ? [{ url: item.image, category: 'poster' }] : []),
	cancel: () => {},
};

const player = nmplayer('player');

player.setup({ preloadStrategy: artworkOnly });
```
