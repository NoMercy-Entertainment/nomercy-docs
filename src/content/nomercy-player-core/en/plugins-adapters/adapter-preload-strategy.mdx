# IPreloadStrategy

Use `cls IPreloadStrategy` when you want to change when the next queue item warms up, or which of its assets are requested.
The strategy answers two questions: is it time yet, and what should load.
Pass one to `fn setup` as `key preloadStrategy`, or swap it later with `fn setPreloadStrategy`.

:::snippet{file="core-adapter-preload-strategy" lines="16-22" live="false"}
:::

## Built-in adapter

Without `key preloadStrategy`, Player Core builds a `cls DefaultPreloadStrategy` with `key preloadLeadSeconds`, which is 10 by default.
It answers yes once the current time is within that many seconds of the end.
It answers no when there is no next item, or when the duration is not known yet.

Its `fn assetsToPreload` returns an empty array.
With no assets, the player emits `str preloadStart` and then `str preloadComplete` at once.

:::snippet{file="core-adapter-preload-strategy" lines="24-30" live="false"}
:::

## Usage

The player asks `fn shouldPreload` on every `str time` event.
`key nextItem` is `null` when nothing is queued, and a yes then starts nothing.
After a yes with a next item queued, it stops asking until the current item changes.
Then it calls `fn assetsToPreload` once and requests each asset.

:::snippet{file="core-adapter-preload-strategy" lines="67-78" live="false"}
:::

The player reports progress through four events.

| Event | Payload |
|---|---|
| `str preloadStart` | `key item`, and `key assets` with each `key url` and `key category` |
| `str preloadProgress` | `key item`, `key loaded`, `key total` |
| `str preloadComplete` | `key item` |
| `str preloadError` | `key item`, and the error |

Each asset is requested with a `str HEAD` request in `str no-cors` mode, through the global `fn fetch`.
When the current item changes, the player calls `fn cancel` and drops the results of requests still in flight.

## Interface

The table lists every member of `cls IPreloadStrategy`.

| Member | Behavior |
|---|---|
| `fn shouldPreload` | Takes a `cls PreloadContext` and returns whether to start. |
| `fn assetsToPreload` | Takes the next item and returns a `cls PreloadAsset` array. |
| `fn cancel` | Called when the current item changes and when the strategy is replaced. |

A `cls PreloadContext` holds `key currentTime` and `key duration` in seconds, and `key nextItem` or `null`.
A `cls PreloadAsset` holds a `key url`, a `key category` string, and an optional `key mode`.
The player does not read `key mode` yet ([#18](https://github.com/NoMercy-Entertainment/nomercy-player-core/issues/18)).
