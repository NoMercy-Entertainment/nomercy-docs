# Adapter: Preload Strategy

`IPreloadStrategy` controls when the player starts fetching assets for the next queue item, and which assets those are.

## The interface

```ts
interface IPreloadStrategy {
	shouldPreload(context: PreloadContext): boolean;
	assetsToPreload(item: BasePlaylistItem): PreloadAsset[];
	cancel(): void;
}
```

`PreloadContext` is a stateless snapshot of `currentTime`, `duration` and `nextItem`, so a strategy never reaches into private player state.

`PreloadAsset` is `{ url, category, mode? }`.

`category` mirrors `UrlCategory`: `'media'`, `'poster'`, `'subtitle'`, `'sprite'`, `'lyrics'`, or a custom string. The auth pipeline uses it to attach the right headers per asset.

`mode` is `'metadata'`, headers only and the default, which suits manifests and sidecars. Or `'auto'`, a full fetch, which suits small images and short intros.

## Rules & restrictions

- `shouldPreload` is called on every `time` event while a next item is queued. Once it returns `true`, the player suppresses further calls until the cursor moves, so an implementation needs no debounce of its own.
- `cancel()` is called when the cursor jumps unexpectedly: a shuffle, a manual `item()`, an explicit `next()` before the end. It has to abort any in-flight prefetch this strategy started, rather than leave it running against an item nobody wants.

## Default implementation

`DefaultPreloadStrategy` fires at `duration - preloadLeadSeconds` (10s lead by default) and returns an empty asset list of its own. Music and video players layer domain-specific asset lists on top by providing their own `assetsToPreload`.

## How to extend it

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player'; // nomercy-music-player's factory works identically

const player = nmplayer('player');

player.setup({
	preloadStrategy: {
		shouldPreload: ctx => ctx.duration - ctx.currentTime <= 5,
		assetsToPreload: item => [{ url: item.image ?? '', category: 'poster', mode: 'auto' }],
		cancel: () => {},
	},
});
```
