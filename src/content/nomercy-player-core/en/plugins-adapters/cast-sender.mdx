# Plugin: Cast Sender

`cls CastSenderPlugin` (id `str cast-sender`) carries player transport onto an open Chromecast session, and mirrors the receiver's state back onto the player.

It is a shared base class rather than a finished plugin. `nomercy-video-player` and `nomercy-music-player` each ship a subclass supplying the two things that differ per medium. Register the subclass from the package you are already using, and reach for the base when you are writing a third.

Everything below is the sender side. It was read from the published build and driven under a DOM stub. No Chromecast device was in the loop, so the page says what the plugin sends and never what a receiver puts on screen.

## Options

| Option | Type | Default | What it does |
|---|---|---|---|
| `key resumeLocalOnDisconnect` | `ts boolean` | `ts true` | After the receiver drops, seek the local player to the receiver's last position and restore its play state. |
| `key defaultContentType` | `ts string` | the subclass's `fn defaultContentType` | Content type sent when the item carries neither `key mime` nor `key contentType`. |
| `key live` | `ts boolean` | `ts false` | Writes `str LIVE` rather than `str BUFFERED` into the load request's `key streamType`. |

## The two per-medium hooks

`fn defaultContentType` answers a MIME type. `fn buildMetadata` turns the current item into a `ts chrome.cast.media` metadata object, using the constructors handed to it as its second argument.

| Class | `fn defaultContentType` | Fields `fn buildMetadata` reads |
|---|---|---|
| `cls CastSenderPlugin` in core | `str application/octet-stream` | `key title`, falling back to `key name` |
| The `nomercy-video-player` subclass | `str video/mp4` | `key title`, `key show`, `key season`, `key episode`, `key poster` |
| The `nomercy-music-player` subclass | `str audio/mpeg` | `key name`, `key artist`, `key album`, `key image`, `key cover` |

Each reads that fixed list and nothing else. An item carrying your own fields needs your own override. Both subclasses resolve their image through `fn resolveUrl` under the `str poster` category, so a signing or auth resolver applies to the artwork as well.

## Events

The plugin's own events reach the player bus under a `str plugin:cast-sender:` prefix, which is the name a listener has to spell out:

```ts
player.on('plugin:cast-sender:cast:connected', (data: { deviceName: string }) => {
  console.log(`casting to ${data.deviceName}`);
});
```

| Event | Payload |
|---|---|
| `str plugin:cast-sender:cast:connected` | `key deviceName`, or `str Cast device` when the SDK reports no friendly name |
| `str plugin:cast-sender:cast:disconnected` | none |
| `str plugin:cast-sender:cast:error` | `key error`, always an `cls Error` |
| `str plugin:cast-sender:cast:remote-state` | `key time`, and `key state` as `str playing`, `str paused` or `str buffering` |
| `str plugin:cast-sender:cast:media-changed` | `key contentId`, and only when the receiver switched to something the plugin did not send |
| `str plugin:cast-sender:unsupported` | `key reason` |

Receiver state also arrives as ordinary player events, so a transport UI keeps following along while casting:

- a remote pause or resume emits `str pause` or `str play`, tagged with `key source` `str cast`
- a remote position change emits `str time`
- newly loaded media info emits `str mediaReady`
- connect and disconnect both emit `str castState`

## What the bridge forwards

| Player event | Call made on the session |
|---|---|
| `str item` | `fn loadMedia`, with the resolved URL, the content type and the built metadata |
| `str play` and `str pause` | `fn playOrPause`, only when the receiver's state differs from the one wanted |
| `str stop` | `fn stop` |
| `str seek` | `key currentTime`, clamped at zero, then `fn seek` |
| `str volume` | `key volumeLevel`, the kit's 0-100 level divided by 100 and clamped into 0-1 |
| `str mute` | `fn muteOrUnmute`, only when the receiver's mute state differs |

An event already tagged `key source` `str cast` is skipped, which is what keeps the mirror from looping.

## Rules & restrictions

- `fn connect` needs `ts cast.framework` already on the page. The plugin never injects the SDK. With the global absent it emits `str plugin:cast-sender:unsupported` with a reason of `str cast-sdk-missing`, then throws a `cls BrowserPolicyError` carrying `str core:policy/castUnavailable`.
- The receiver app id is not a plugin option. `fn connect` asks `ts cast.framework.CastContext.getInstance()` for a session and configures nothing, so a custom receiver is set on the SDK's own context before you call it.
- `player.transferTo('cast')` is a separate route to the same SDK. It requests a session itself and reads the `key cast` block of the setup config, including `key receiverApplicationId`, `key autoLoad` and `key scriptUrl`. It goes nowhere near this plugin. Pick one of the two per application.
- Every forwarder is a no-op while no session is open, so registering the plugin early costs nothing until `fn connect` resolves.
- `fn disconnect` is safe to call when already disconnected. It ends the session, drops the receiver listeners and emits `str plugin:cast-sender:cast:disconnected`.
- The base class ships its own strings in English and Dutch. A subclass's own bundle is discovered by `fn translationsFromGlob` and merged over it, base first, so a subclass wins any key it shares.

## How to extend it

Subclass the base and override the two hooks. This is what both media packages do, and neither of them reimplements the session handling:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player';
import { CastSenderPlugin } from '@nomercy-entertainment/nomercy-player-core';
import type { BasePlaylistItem, ChromeCastMediaCtors, IPlayer } from '@nomercy-entertainment/nomercy-player-core';

interface NewsItem extends BasePlaylistItem {
  headline?: string;
}

class NewsCastSender extends CastSenderPlugin<IPlayer, NewsItem> {
  protected override defaultContentType(): string {
    return 'application/x-mpegURL';
  }

  protected override async buildMetadata(item: NewsItem, ctors: ChromeCastMediaCtors) {
    const meta = new ctors.GenericMediaMetadata();
    meta.title = item.headline ?? '';
    return meta;
  }
}

const player = nmplayer('player');

player.addPlugin(NewsCastSender, { live: true });
player.setup({ playlist: [] });
await player.ready();

await player.getPlugin(NewsCastSender)?.connect();
```
