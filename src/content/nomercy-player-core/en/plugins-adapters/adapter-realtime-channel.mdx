# Adapter: Realtime Channel

`IRealtimeChannel` is a protocol-agnostic realtime connection handle. `RealtimeFactory` is the function shape that creates one, swappable globally or per call.

Supply your own factory when the player has to share a live connection with the rest of your app, or speak something other than a bare WebSocket: a SignalR hub, Socket.IO, or a transport that reconnects on its own. Watch-party sync and remote-control sessions are the usual reasons.

The built-in adapter wraps one native `WebSocket` and never reconnects, so reconnection is a property of the factory you supply, not of the kit.

## The interfaces

```ts
interface IRealtimeChannel {
	send(data: string | ArrayBuffer | Blob): void;
	close(code?: number, reason?: string): void;
	on(event: 'open' | 'message' | 'close' | 'error', fn: (data?: unknown) => void): void;
	off(event: 'open' | 'message' | 'close' | 'error', fn: (data?: unknown) => void): void;
	readonly readyState: 'connecting' | 'open' | 'closing' | 'closed';
}

type RealtimeFactory = (url: string, opts?: RealtimeFactoryOptions) => IRealtimeChannel;
```

`RealtimeFactoryOptions` carries these fields:

| Field | Purpose |
| --- | --- |
| `protocols` | WebSocket sub-protocol strings. |
| `reconnect`, `baseDelayMs`, `maxDelayMs` | Reconnection knobs forwarded to the factory. Only a factory that implements reconnection reads them; the built-in native adapter does not. |
| `factory` | A per-call override, for one connection that uses a different transport without changing the global default. |

## Rules & restrictions

- Call `send()` only when `readyState === 'open'`. The underlying transport throws otherwise. The port does not buffer or queue messages for you.

The factory that actually runs is resolved in this order:

1. A per-call `opts.factory`.
2. The player's configured `websocketFactory`.
3. The built-in `nativeWebSocketAdapter`, as the final fallback.

## Default implementation

`nativeWebSocketAdapter` wraps the browser's native `WebSocket`. It never reconnects: a factory you supply is what reads the reconnect knobs and acts on them.

## How to extend it

Global swap, for every realtime connection the player opens:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player'; // nomercy-music-player's factory works identically

const player = nmplayer('player');

player.setup({ websocketFactory: signalRFactory });
```

Per-call override, inside a plugin, for one connection using a different transport:

```ts
this.websocket(url, { factory: socketIoFactory });
```
