# Adapter: Shuffle Strategy

`cls IShuffleStrategy` decides the permutation `fn queueShuffle` applies to the queue. One method, and the queue does the rest.

Swap it when uniform random is the wrong answer for your app. Weight it by rating, group it so an album stays together, or seed it so two devices land on the same order. The default is an unbiased Fisher-Yates shuffle.

## The interface

```ts
interface IShuffleStrategy {
	order<T extends BasePlaylistItem>(items: ReadonlyArray<T>, currentIndex: number): T[];
}
```

`items` is the queue as it stands, read-only. `currentIndex` is the zero-based position of the playing item inside it. Return a permutation: the same items, no drops, no duplicates.

## What the queue does around you

`fn queueShuffle` calls `fn order`, installs the result, then re-finds the playing item and points the cursor at it. The match is on `key id`, so a strategy is free to hand back fresh objects as long as each carries the id it came with.

An item missing from the result leaves the cursor on the index it already held, which is now a different track. That is the one thing the permutation contract asks you not to do.

`fn order` runs only when the queue holds two items or more, and a queue holding anything keeps its cursor on one of them. So `currentIndex` is a real position every time the queue calls you.

The player emits `str queue:shuffle` and then `str queue` once the new order is in place.

## Default implementation

`cls FisherYatesShuffle` is an unbiased uniform-random permutation, and `fisherYatesShuffle` is the shared instance the queue uses when `fn setup` names no other. It ignores `currentIndex`, so the playing item moves with everything else.

Both names come from the package root and from `./adapters/shuffle-strategy`, which makes the default reusable inside a strategy of your own.

## Rules & restrictions

- `fn order` is synchronous and its return value is installed as-is. There is no hook for an asynchronous ordering.
- The strategy is read at `fn setup` and holds for the life of the player. Each `fn queueShuffle` asks it again, so a stateful strategy sees every call.
- `currentIndex` is offered rather than imposed. Pinning the playing item, leaving it in place, or shuffling it along with the rest are all valid.

## How to extend it

```ts
import { fisherYatesShuffle } from '@nomercy-entertainment/nomercy-player-core';
import type { IShuffleStrategy } from '@nomercy-entertainment/nomercy-player-core';

const pinCurrentFirst: IShuffleStrategy = {
	order: (items, currentIndex) => {
		const current = items[currentIndex];
		const rest = items.filter((_, index) => index !== currentIndex);
		return [current, ...fisherYatesShuffle.order(rest, -1)];
	},
};

player.setup({ shuffleStrategy: pinCurrentFirst });
```
