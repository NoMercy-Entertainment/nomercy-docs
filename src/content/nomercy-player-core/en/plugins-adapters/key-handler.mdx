# Plugin: Key Handler

`cls KeyHandlerPlugin` (id `str key-handler`) is a keyboard router: one `str keydown` listener that turns each event into a canonical combo string and looks it up in a binding map. Fourteen bindings ship with it, your own merge on top, and each callback receives the player.

The package root does not re-export the class, so it comes from the `plugins/key-handler` subpath.

## Options

| Option | Type | Default | What it does |
|---|---|---|---|
| `key scope` | `ts 'document' \| 'container' \| HTMLElement` | `str document` | Where the listener attaches. |
| `key bindings` | `ts Record<string, (player) => void>` | none | Your own combo-to-callback map. |
| `key extend` | `ts boolean` | `ts true` | Merge `key bindings` on top of the defaults. `ts false` clears the defaults first. |
| `key when` | `ts (event: KeyboardEvent) => boolean` | none | Extra gate. Returning `ts false` suppresses that event entirely. |
| `key cooldownMs` | `ts number` | `ts 300` | Minimum gap between fires. `ts 0` disables throttling. |
| `key disableMediaControls` | `ts boolean` | `ts false` | Makes every hardware media binding a no-op. |

## The default bindings

| Combo | Action |
|---|---|
| `ts ' '` | `fn togglePlayback` |
| `str ArrowLeft` and `str ArrowRight` | `fn rewind` and `fn forward`, five seconds each |
| `str ArrowUp` and `str ArrowDown` | `fn volumeUp` and `fn volumeDown`, five points each |
| `str m` | `fn toggleMute` |
| `str MediaPlay`, `str MediaPause`, `str MediaPlayPause`, `str MediaStop` | the matching transport call, with `fn pause` standing in when the player has no `fn stop` |
| `str MediaRewind` and `str MediaFastForward` | `fn rewind` and `fn forward`, five seconds each |
| `str MediaTrackNext` and `str MediaTrackPrevious` | `fn next` and `fn previous` |

The space bar binds under `ts ' '`, the single character the browser puts in `key key`, and that is the string to unbind or replace. `str Space` is a different combo that no keyboard produces.

`key disableMediaControls` gates the eight hardware bindings and leaves the other six alone.

## How a combo is built

Every event is reduced to one string before the lookup, and every binding is reduced the same way when you register it.

- A single character is lowercased, so `str P` and `str p` are one entry. Longer names keep their case, so `str ArrowLeft` stays as written.
- Held modifiers are folded onto the front in a fixed order: alt, then ctrl, then shift. `str shift+ArrowLeft` and `str ArrowLeft` are two independent bindings, and the bare one fires only when none of the three is held.
- The modifier prefixes are case-insensitive when you write them, so `str Shift+arrowleft` registers the same entry as `str shift+ArrowLeft`.
- A trailing `str +` is read as the key, so `str +` and `str shift++` both parse.

A character that needs shift on the physical keyboard, such as `str ?`, always arrives with the shift flag set. Bind the `str shift+` form for those; the bare form never matches.

The meta key is not folded in. On macOS a combination pressed with command reaches the bare binding, so `str Cmd+ArrowLeft` rewinds. Gate those through `key when` if that is not what you want.

## Rules & restrictions

- The cooldown is one window shared by every binding, not one per key. At the default of 300 ms, two different keys pressed in quick succession fire once between them. Set `key cooldownMs` to `ts 0` when you want each press to land.
- Nothing fires while the event target is an `<input>`, a `<textarea>`, a `<select>` or any element with `ts contenteditable` set. The player never takes a keystroke from a form beside it.
- The window is consumed only when a binding actually fires. A key typed into a form, one `key when` turned away and one nothing is bound to all leave it untouched.
- `str container` attaches the listener to the player container, which receives a `str keydown` only while it or a descendant holds focus. Nothing in the kit makes the container focusable, so give it a `key tabindex` when you pick that scope.
- `fn bindings` answers a snapshot `cls Map`. Its keys are the canonical combos currently registered, which is the reliable way to see what a subclass or a merge left in place.
- Registering the same combo again replaces the previous callback. `fn replace` is a second name for `fn bind` and behaves identically.

## How to extend it

Add bindings through the option, then keep editing at runtime:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player';
import { KeyHandlerPlugin } from '@nomercy-entertainment/nomercy-player-core/plugins/key-handler';

const player = nmplayer('player');

player.addPlugin(KeyHandlerPlugin, {
  cooldownMs: 0,
  bindings: {
    'l': p => p.forward(10),
    'shift+ArrowLeft': p => p.rewind(30),
  },
});
player.setup({ playlist: [] });
await player.ready();

const keys = player.getPlugin(KeyHandlerPlugin);

keys?.bind('k', p => p.pause());
keys?.unbind('m');
console.log([...(keys?.bindings().keys() ?? [])]);
```

To replace a whole group rather than one key, subclass and override its group method. The four are `fn addPlaybackKeys`, `fn addNavigationKeys`, `fn addVolumeKeys` and `fn addMediaKeys`, and each installs only its own bindings:

```ts
import { KeyHandlerPlugin } from '@nomercy-entertainment/nomercy-player-core/plugins/key-handler';

class WideSeekKeyHandler extends KeyHandlerPlugin {
  protected override addNavigationKeys(): void {
    this.bind('ArrowLeft', p => p.rewind(30));
    this.bind('ArrowRight', p => p.forward(30));
  }
}
```
