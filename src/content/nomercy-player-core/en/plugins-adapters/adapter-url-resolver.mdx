# Adapter: URL Resolver

[Recipe: Provide a Custom URL Resolver](/nomercy-player-core/recipes/custom-url-resolver) walks through a full worked example. This page is the reference for the port itself.

## The interface

```ts
interface IUrlResolver {
	(url: string, ctx: UrlResolverContext): Promise<ResolvedUrl> | ResolvedUrl;
}
```

`UrlResolverContext` carries `auth`, `baseUrl`, a `category` hint (`'media'`, `'subtitle'`, `'font'`, `'poster'`, `'sprite'`, `'lyrics'`, `'cast'`, `'license'`, or any custom string a plugin passes), and `defaultResolve(url)`, the built-in behavior, so a custom resolver can delegate for categories it doesn't need to touch instead of reimplementing the default from scratch.

## ResolvedUrl

The return shape:

- `href`: the final string. Pass it to a `<video>.src`, a Worker, or a Cast receiver.
- `raw`: the unparsed input.
- `scheme`, `origin`, `pathname`, `search`, `hash`, and `searchParams` for the query.
- `ext`: the lowercase extension with no leading dot. Gate on file type with this rather than splitting on `.`, which breaks on query strings.
- `relative`: `true` when the input was relative and no `baseUrl` was available to absolutize against.

## Rules & restrictions

- The default implementation is `auth.transformUrl(url)` followed by structured parsing, and that is what `ctx.defaultResolve` calls. A custom resolver replacing the field outright still has that behaviour one call away.
- This port is for URLs handed to something that is not `fetch()`. If you call `fetch` yourself, use [authFetch](/nomercy-player-core/recipes/auth-fetch): it sets the `Authorization` header rather than encoding credentials into the URL.

## How to extend it

Swap it at `setup({ urlResolver })`, or at runtime via `player.urlResolver(fn)` / `player.urlResolver(undefined)` to revert. See the [recipe](/nomercy-player-core/recipes/custom-url-resolver) for a complete category-branching example.
