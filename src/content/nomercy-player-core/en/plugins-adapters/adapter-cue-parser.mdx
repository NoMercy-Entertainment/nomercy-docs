# ICueParser

Use `cls ICueParser` when timed text arrives in a format you need to claim.
Each parser has an `key id`, a `fn canParse` gate, and a synchronous `fn parse` that returns a cue list.

```ts
import {
	CueParserRegistry,
	createCueList,
	parseLrc,
} from '@nomercy-entertainment/nomercy-player-core';
import type { ICueParser } from '@nomercy-entertainment/nomercy-player-core';
```

`cls CueParserRegistry` and the parse helpers also live on the `adapters/cue-parser` path.
`cls ICueParser` is on the package root and on that path.

## Built-in adapter

`cls CueParserRegistry` is the ordered list you construct yourself, or that the player owns.
Resolution walks newest first.
`fn register` with the same `key id` replaces that entry.
Pass `prepend: true` to park a parser at the low-priority end.

During `fn setup`, Player Core seeds three parsers by id.
You do not import those parser objects.
You address them with `fn unregisterCueParser` and by registering the same `key id` again.

| Id | Claims |
|---|---|
| `str lrc` | `.lrc`, or content type `application/x-lrc`, `application/x-lyrics`, or `text/lrc` |
| `str vtt` | `.vtt` or `text/vtt`, unless the URL looks like a sprite sheet |
| `str sprite-vtt` | A URL that ends in `sprite.vtt` or `sprites.vtt`; a query string may follow |

The package exports `fn parseLrc`, `fn parseVttSubtitles`, `fn parseVttSprite`, and `fn parseVtt` so a custom parser can reuse those readers.

On a player, `fn registerCueParser`, `fn unregisterCueParser`, and `fn resolveCueParser` wrap that registry.
`fn resolveCueParser` takes a URL only.
Pass `key cueParsers` at setup, or call `fn registerCueParser` at runtime, to outrank a seeded parser for the same URL.

## Interface

```ts
interface ICueParser<T = unknown> {
	readonly id: string;
	canParse(url: string, contentType?: string): boolean;
	parse(raw: string, opts?: { baseUrl?: string }): CueList<T>;
}
```

`fn canParse` returning `true` is a commitment.
The registry returns the first match and does not fall through.
`fn parse` receives the full file as a string.
Fetching is the caller's job.
Optional `key baseUrl` helps relative references inside cue bodies.

## Custom implementation

Any object with the three members is a parser.
Hand it to `fn setup` through `key cueParsers`, or call `fn registerCueParser` later.

```ts
import { createCueList } from '@nomercy-entertainment/nomercy-player-core';
import type { ICueParser } from '@nomercy-entertainment/nomercy-player-core';

const beats: ICueParser<{ label: string }> = {
	id: 'demo:beats',
	canParse: url => url.endsWith('.beats'),
	parse: (raw) => {
		const rows = raw.split(/\r?\n/).filter(Boolean);
		return createCueList(
			rows.map((row) => {
				const [at, ...rest] = row.split(/\s+/);
				const start = Number(at);
				return {
					start,
					end: start,
					payload: { label: rest.join(' ') },
				};
			}),
		);
	},
};

player.setup({ cueParsers: [beats] });
```
