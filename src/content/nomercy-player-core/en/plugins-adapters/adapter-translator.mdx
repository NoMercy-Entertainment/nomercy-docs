# Adapter: Translator

`ITranslator` is the whole translation engine behind `t()`. The kit ships `DefaultTranslator`, which carries the built-in `core.*` strings.

Swap it when your app already runs an i18n engine and you want one source of truth: i18next, FormatJS, or ICU MessageFormat. The player then reads its strings from the same place the rest of your interface does.

[i18n](/nomercy-player-core/tour/i18n) covers how translation resolution works day to day. This page is the reference for the port a whole engine swap replaces.

## The interface

```ts
interface ITranslator {
	t(key: string, vars?: Record<string, string>): string;
	language(): string;
	language(lang: string): Promise<void>;
	addTranslations(bundle: Translations): void;
	translation(lang: string, key: string): string | undefined;
	translation(lang: string, key: string, value: string): void;
	removeTranslations(prefix: string, lang?: string): void;
	dispose(): void;
}
```

## Default implementation

`DefaultTranslator` is a key plus `{var}` interpolation lookup over a merged bundle table.

It is seeded with the kit's own `core.*` strings. English loads eagerly; every other kit locale loads the first time `language(lang)` switches to it.

`DefaultTranslatorOptions`:

- `language`: the initial tag, `'en'` by default
- `translations`: initial bundles
- `loadTranslations`: async loader for a tag not yet fetched
- `onMissingTranslation`: custom fallback for an unresolved key
- `fallbackLanguage`: final fallback, `'en'` by default. Pass `null` to rely on the BCP-47 parent chain alone.

## Rules & restrictions

- `removeTranslations(prefix, lang?)` is what the kit calls on plugin dispose, for `plugin.<id>.` prefixed keys. A custom engine has to implement it correctly, or plugin translations never get cleaned up.
- `language(lang)` returns a `Promise<void>`, because a real engine may await a loader before the new bundle is ready. Callers `await` it rather than assuming the switch is synchronous.

## How to extend it

Swap the whole engine when you need pluralization, gender, or ICU MessageFormat.

Pass your own `translator` and the kit uses it as-is, handing it none of the translation config. Your engine owns its translation state end to end.

So wire `translations`, `loadTranslations` and `language` into your adapter before you pass it. Those options seed the built-in `DefaultTranslator` only:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player'; // nomercy-music-player's factory works identically

const player = nmplayer('player');

player.setup({ translator: myI18nextAdapter });
```

Adapters for i18next and FormatJS are meant to live as separate packages outside the kit (`@nomercy/translator-i18next`, `@nomercy/translator-formatjs`), consumers pull only the engine they want.
