# Equalizer

`cls EqualizerPlugin` gives a listener tone control. It builds ten `cls BiquadFilterNode` filters and one pre-gain `cls GainNode`, then inserts all eleven into [Audio Graph](/nomercy-player-core/plugins-adapters/audio-graph)'s chain.

Reach for it when you want a preset picker, a band-by-band panel, or a single curve that follows a listener between sessions.

The plugin id is `str equalizer`. `cls EqualizerPlugin` and `fn equalizerPlugin` are the same class, both exported from the package root.

## The bands

The default set is eleven entries. The first is the `str Pre` pseudo-band, and the ten after it are frequencies in hertz: 70, 180, 320, 600, 1000, 3000, 6000, 12000, 14000 and 16000.

Each frequency becomes a `cls BiquadFilterNode` of type `str peaking` at Q 1, and its `key gain` is in decibels. Give a band its own `key type` or `key q` to change that.

`str Pre` is a `cls GainNode` rather than a filter, and its value is not decibels. The node's gain is the band's value plus one, so 0 is unity and the slider runs from -1 to 3.

A peaking filter at Q 1 is wide, so one band always moves its neighbors. Measured against the published build, the 600 Hz band at +12 dB also lifts 440 Hz by 8.29 dB and 1 kHz by 5.65 dB, and at -12 dB it cuts the same two frequencies by the same amounts.

## Methods

| Method | Returns |
|---|---|
| `fn bands` | A copy of every band, `str Pre` first. |
| `band(frequency)` | The gain in decibels stored for that band, and 0 for a frequency that is not one of them. |
| `band(frequency, gain)` | Nothing. Writes the band and ramps its filter. A single `cls EqBand` works in place of the pair. |
| `preGain()` and `preGain(value)` | The pre-gain, and the setter for it. |
| `q(frequency)` and `q(frequency, value)` | That band's Q, and the setter. A value under 0.0001 is raised to it. |
| `preset()` and `preset(target)` | The selected preset name, and the setter. |
| `fn presets` | Every preset: the nineteen built-ins, then your custom ones, then anything from `key presets`. |
| `fn sliderValues` | A `key pre` and a `key band` range, each carrying `key min`, `key max`, `key step`, `key default` and `key totalSteps`. |
| `bandSliderMin(frequency)`, `fn bandSliderMax`, `fn bandSliderStep` | That band's slider bounds. |
| `bandSliderValue(frequency)` | That band's current position as a percentage. |
| `fn reset` | Nothing. Returns every band to the configured set and clears the preset. |
| `addCustomPreset(preset)` and `removePreset(name)` | Nothing. Adds or drops a preset of your own. |
| `fn save` and `fn restore` | Nothing. Writes the curve to storage, and reads it back. |

## Presets

Nineteen curves ship with the plugin: `str Custom`, `str Classical`, `str Club`, `str Dance`, `str Flat`, `str Laptop speakers/headphones`, `str Large hall`, `str Party`, `str Pop`, `str Reggae`, `str Rock`, `str Soft`, `str Ska`, `str Full Bass`, `str Soft Rock`, `str Full Treble`, `str Full Bass & Treble`, `str Live` and `str Techno`.

Each one carries a value for all ten frequencies and none for `str Pre`, so applying a preset leaves the pre-gain where the listener put it.

## Options

| Option | Type | Default | Purpose |
|---|---|---|---|
| `key bands` | `ReadonlyArray<EqBand>` | the eleven above | Your own band set. Element 0 has to be the `str Pre` entry. |
| `key preset` | `string` | none | A preset applied while the plugin wires itself up. |
| `key presets` | `ReadonlyArray<EqPreset>` | none | Extra presets alongside the built-ins. |
| `key sliderValues` | `EqSliderValues` | pre -1 to 3, band -12 to 12, step 0.01 | The ranges `fn sliderValues` hands a UI. |
| `key persistKey` | `string` | none | Storage key. Leave it out and nothing is stored. |
| `key autoLoad` | `boolean` | `true` | Read the stored curve back while wiring up. |
| `key autoSave` | `boolean` | true once `key persistKey` is set | Write after every change. |
| `key smoothingTimeConstantSeconds` | `number` | `0.05` | Ramp time for a gain change, so a slider drag makes no click. |

An `cls EqBand` carries a required `key frequency` and `key gain`, plus an optional `key q` and `key type`. An `cls EqPreset` is a `key name` and a `key values` array of bands, and a preset only touches the frequencies it lists.

`cls EqBand` and `cls EqPreset` come from the package root. `cls EqSliderValues` and `cls SliderRange` come from the `str @nomercy-entertainment/nomercy-player-core/plugins/equalizer` subpath.

## Events

A plugin event reaches the player under the plugin's own id, so the name to listen for is `str plugin:equalizer:change`.

| Event | Payload |
|---|---|
| `str ready` | none |
| `str band:changed` | `{ band }` |
| `str preset:changed` | `{ name }` |
| `str change` | `{ bands, selectedPreset }` |
| `str saved` | none |

`str change` follows every `str band:changed` and every `str preset:changed`, so a panel that redraws itself whole can listen to that one alone.

## Rules & restrictions

- Register [Audio Graph](/nomercy-player-core/plugins-adapters/audio-graph) first. Registering this plugin ahead of it throws a `cls PluginError` with code `str core:plugin/missing-dep`.
- `bands[0]` has to be the `str Pre` entry. A filter is matched to a band by its position after that first slot, so a band set opening on a real frequency puts every filter one place out.
- `band(frequency, gain)` addresses a band by its exact frequency. One that is not in `key bands` writes nothing and moves no filter, though the events still fire. Measured with `band(500, 9)` against the default set.
- Setting any band clears the selected preset, so `fn preset` reads back undefined until another one is picked.
- A preset name matching nothing is ignored. `fn preset` also takes an `cls EqPreset` object, or a JSON string holding one.
- Pre-gain snaps to zero within 0.05 either way, so a slider settles at the middle rather than resting at 0.04.
- A read-back is exact and immediate, while the filter itself ramps. `band(600, -12)` reads back -12 with the node still on its way there.
- Persistence goes through the plugin's own namespaced storage, never raw `localStorage`. With `persistKey: 'my-app-eq'` the record lands under the key `str nmplayer-equalizer-my-app-eq` and holds the bands, the selected preset and your custom presets. Swapping the [storage adapter](/nomercy-player-core/plugins-adapters/adapter-storage) moves it with everything else.

## Building on it

Register both plugins before `fn setup`, in this order, and read the equalizer back once `fn ready` has resolved.

```ts
import { AudioGraphPlugin, EqualizerPlugin } from '@nomercy-entertainment/nomercy-player-core';

player.addPlugin(AudioGraphPlugin);
player.addPlugin(EqualizerPlugin, { persistKey: 'my-app-eq' });

await player.ready();

const equalizer = player.getPlugin(EqualizerPlugin);

equalizer?.preset('Rock');
equalizer?.band(1000, 4);
```

`fn preset` applies a whole curve at once. The `fn band` call after it moves one filter and drops the preset name, which is what a listener touching a single slider expects. With `key persistKey` set both calls are stored on their own, so `fn save` is only needed when you turn `key autoSave` off.
