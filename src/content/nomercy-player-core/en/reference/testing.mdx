# Reference: Testing

Catalog of the helpers exported from Player Core's testing entry.

None of these symbols appear on the package root.
`src/index.ts` does not re-export them.
The package exports map exposes them only as `./testing`, so the import path is `@nomercy-entertainment/nomercy-player-core/testing`.

```ts
import {
  StubPlayer,
  createStubPlayer,
  describePlugin,
  describePluginAgainst,
  runIPlayerContract,
  assertNoListenerLeak,
  assertNoListenerLeakOverCycles,
  countAllListeners,
  mockFetch,
} from '@nomercy-entertainment/nomercy-player-core/testing';
```

`describePlugin`, `describePluginAgainst`, and `runIPlayerContract` read Vitest globals (`describe`, `it`, `beforeEach`, `afterEach`, and for the contract also `expect`) from `globalThis` at runtime.
A project that calls them needs `test.globals: true` in its Vitest config.

## StubPlayer

`StubPlayer` is a lightweight `IPlayer` test double for plugin and unit tests.
It drives plugin lifecycles and event subscriptions without a browser media element or a network stack.
`createStubPlayer` is the factory form of the same constructor.

These exports construct that double.

| Export | Signature | One job |
|---|---|---|
| `StubPlayer` | `class StubPlayer extends EventEmitter<BaseEventMap> implements IPlayer<BaseEventMap>` with `constructor(opts?: { id?: string; container?: HTMLElement; phase?: PlayerPhase; translations?: Translations })` | In-process `IPlayer` stand-in with a real event emitter, phase, i18n, cue parsers, and experimental overrides. |
| `createStubPlayer` | `(opts?: ConstructorParameters<typeof StubPlayer>[0]) => StubPlayer` | Same as `new StubPlayer(opts)`. |

These methods exist on the stub for tests and are not part of everyday `IPlayer` usage.

| Method | Signature | One job |
|---|---|---|
| `setPhase` | `(next: PlayerPhase) => void` | Force a phase change and emit `phase`. |
| `pushDispatch` | `(name: string) => void` | Push a name onto the dispatch stack. |
| `popDispatch` | `() => string \| undefined` | Pop the innermost dispatch name. |
| `setAudioContext` | `(ctx: AudioContext \| undefined) => void` | Inject a mock `AudioContext`. |
| `cueParsers` | `() => ReadonlyArray<ICueParser>` | List registered cue parsers. |
| `reset` | `() => void` | Restore constructed defaults and clear listeners. |

The stub does not track plugin registration.
`getPlugin` and `getPluginById` always return `undefined`.
`addPlugin` is a no-op that returns `this`.
`describePlugin` wires the plugin itself; override or mock registration only when a plugin calls `addPlugin` or `getPlugin` inside `use()`.

## describePlugin

`describePlugin` runs an author suite against a fresh `StubPlayer` and a fresh plugin instance per test.
It calls `initialize`, loads static translations the way production registration does, awaits `use()`, then on teardown calls `dispose` and asserts no listener leak unless skipped.

This table is the author-facing API for that harness.

| Export | Signature | One job |
|---|---|---|
| `describePlugin` | `<C extends typeof Plugin<any, any, any>>(PluginClass: C, fn: (ctx: PluginTestContext<C>) => void, opts?: DescribePluginOptions<C>) => void` | Wrap a plugin suite on `StubPlayer` with per-test setup, teardown, and leak assertion. |
| `PluginTestContext<C>` | `{ player: StubPlayer; plugin: InstanceType<C> }` | Values handed to `fn`, reset between tests. |
| `DescribePluginOptions<C>` | `{ opts?; skipLeakAssertion?: boolean; createPlayer?: () => StubPlayer }` | Plugin options for `initialize`, optional leak skip, optional custom stub factory. |

## describePluginAgainst

`describePluginAgainst` runs the same style of author suite against a real `IPlayer` from a required factory, not `StubPlayer`.
It registers through the player's `addPlugin`, reads the instance back with `getPlugin`, removes the plugin on teardown, then disposes unless a custom `teardown` is supplied.

This table is the author-facing API for the real-player harness.

| Export | Signature | One job |
|---|---|---|
| `describePluginAgainst` | `<C extends typeof Plugin<any, any, any>, P extends IPlayer>(PluginClass: C, fn: (ctx: PluginAgainstTestContext<C, P>) => void, opts: DescribePluginAgainstOptions<C, P>) => void` | Wrap a plugin suite on a real player factory with leak assertion. |
| `PluginAgainstTestContext<C, P>` | `{ player: P; plugin: InstanceType<C> }` | Values handed to `fn` for the real player type `P`. |
| `DescribePluginAgainstOptions<C, P>` | `{ player: () => P \| Promise<P>; teardown?: (player: P) => void \| Promise<void>; opts?; skipLeakAssertion?: boolean }` | Required player factory plus optional teardown, plugin options, and leak skip. |

## runIPlayerContract

`runIPlayerContract` registers a shared behavioral suite for one concrete `IPlayer` implementation.
Every test calls a method and asserts the effect, not only the shape.

Pass a label, a create factory, and an optional teardown.

This table is the function that registers that suite.

| Export | Signature | One job |
|---|---|---|
| `runIPlayerContract` | `<P extends IPlayer<BaseEventMap>>(opts: { create: () => P \| Promise<P>; label: string; teardown?: (player: P) => void \| Promise<void> }) => void` | Prove one player satisfies the shared `IPlayer` behavior contract. |

The suite covers identity, the event surface, phase and `dispatching`, `baseUrl`, `audioContext`, experimental overrides, i18n, and the cue parser registry.
Library-specific transport, queue, fullscreen, and similar behavior stay in each library's own tests.

## Listener-leak harness

The leak harness snapshots total live listeners before setup, after setup, and after teardown, then fails when the count does not return to baseline.
It depends on `listenerCount()` on the player object; players built on `EventEmitter` expose that method.
See [Adapter: Event Bus](/nomercy-player-core/plugins-adapters/adapter-event-bus) for that surface.

These exports measure and assert listener cleanup.

| Export | Signature | One job |
|---|---|---|
| `countAllListeners` | `(player: IPlayer) => number` | Return `player.listenerCount()`, or throw `TypeError` if that method is missing. |
| `assertNoListenerLeak` | `(opts: { subjectId: string; player: IPlayer; setup: () => void \| Promise<void>; exercise?: () => void \| Promise<void>; teardown: () => void \| Promise<void> }) => Promise<LeakAssertionResult>` | Run setup, optional exercise, and teardown; throw when listeners remain. |
| `assertNoListenerLeakOverCycles` | `(opts: { subjectId: string; player: IPlayer; setup: () => void \| Promise<void>; exercise?: () => void \| Promise<void>; teardown: () => void \| Promise<void>; cycles?: number }) => Promise<LeakAssertionResult[]>` | Repeat `assertNoListenerLeak` for `cycles` iterations (default `5`). |
| `LeakAssertionResult` | `{ subjectId: string; listenersBefore: number; listenersAfterSetup: number; listenersAfterTeardown: number; leaked: number }` | Numbers from one assertion pass; `leaked > 0` means retention after teardown. |

## mockFetch

`mockFetch` builds a drop-in replacement for `Plugin.fetch` that records calls and returns queued bodies without hitting the network.
Assign `mock.fetch` onto the plugin under test.

These types describe that mock.

| Export | Signature | One job |
|---|---|---|
| `mockFetch` | `() => MockFetch` | Create a fresh mock with empty call history and an empty response queue. |
| `MockFetch` | `{ fetch: <T = string>(url: string, options?: FetchOptions<T>) => Promise<T>; calls: MockFetchCall[]; respondWith(body: unknown): void; reset(): void }` | Recorded fetch stand-in with FIFO responses and reset. |
| `MockFetchCall` | `{ url: string; options: FetchOptions<unknown> \| undefined }` | One recorded call, in order. |
| `MockFetchResponse` | `{ body: unknown }` | Shape of a queued response body carrier. |

An exhausted response queue resolves `undefined` cast to `T`.

## PlayerTestInternals

`PlayerTestInternals` is a type-only cast target for a few real-player internals used in package unit tests.
Public methods and events stay on the typed player surface; this interface covers `_phase`, `_cueParsers`, `pushDispatch`, and `popDispatch`.

Cast with `as unknown as PlayerTestInternals`, never `as any`.

This table is the shape of that cast.

| Export | Signature | One job |
|---|---|---|
| `PlayerTestInternals` | `{ _phase: PlayerPhase; _cueParsers: CueParserRegistry; pushDispatch(name: string): void; popDispatch(): string \| undefined }` | Typed access to internals tests probe directly. |
