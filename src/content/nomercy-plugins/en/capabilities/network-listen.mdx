# `network.listen`

Listening sockets, inbound connections and UPnP port mapping.

## What it covers

| | |
| --- | --- |
| Facade | `IPluginContext.Net.ListenAsync` |
| Scope | port or range |
| Trust | medium |
| Revocable while the plugin runs | no |

The owner is asked before this is granted, and the grant names its scope.

Taking this grant away needs the plugin restarted. What it already holds cannot be handed back mid-run.

## Asking for it

Name it in the manifest:

```json
{
  "capabilities": [
    { "name": "network.listen", "scope": "8000-8100" }
  ]
}
```

The scope is port or range. A call outside it is refused with the grant's own name in the message, so the author reads which scope to widen rather than that something went wrong.

## When it refuses

| Code | Severity | What happened |
| --- | --- | --- |
| `PLUGIN_LISTENER_UNDECLARED` | blocked | The plugin bound a listening socket without network.listen. |
| `PLUGIN_ROUTER_DECLINED` | blocked | The router refused to forward the port, which no change to the plugin can fix. |
| `PLUGIN_NO_ROUTER_FOUND` | blocked | No router on this network answered a port-forwarding request. |

Every refusal carries what the plugin did, why the server said no, and how to fix it. Read all three before changing code.


## What the analyzer catches first

| Rule | What it says |
| --- | --- |
| `NMP0003` | Listening on a port the host did not open cannot be closed when the plugin stops. Use context.Net.ListenAsync. |

These fire at build time, so the author sees them before the server ever refuses.
