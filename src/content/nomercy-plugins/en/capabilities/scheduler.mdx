# `scheduler`

Named cron jobs, one-shot jobs and run-now from the settings page.

## What it covers

| | |
| --- | --- |
| Facade | `IPluginContext.Scheduler` |
| Scope | (always) |
| Trust | low |
| Revocable while the plugin runs | yes |

The owner grants this without being asked a second time.

Taking this grant away stops the next call. The plugin keeps running.

## Asking for it

Name it in the manifest:

```json
{
  "capabilities": [
    { "name": "scheduler", "scope": "*" }
  ]
}
```

The scope is (always). A call outside it is refused with the grant's own name in the message, so the author reads which scope to widen rather than that something went wrong.

## When it refuses

| Code | Severity | What happened |
| --- | --- | --- |
| `PLUGIN_SCHEDULER_WORKER_CRASHED` | degraded | A supervised worker crashed and the host restarted it. |

Every refusal carries what the plugin did, why the server said no, and how to fix it. Read all three before changing code.


## What the analyzer catches first

| Rule | What it says |
| --- | --- |
| `NMP0013` | A long cycle is awaited inside a request. Use context.Scheduler.RunNowAsync. |
| `NMP0016` | IScheduledTaskPlugin is obsolete. Register jobs through context.Scheduler. |

These fire at build time, so the author sees them before the server ever refuses.
