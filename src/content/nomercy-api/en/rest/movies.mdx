# Movies

Everything about a single film hangs off its id. The id is the film's TheMovieDB id, so the same number identifies it everywhere in the system.

## Reading

| Method | Path | Needs |
|--------|------|-------|
| GET | `/api/v1/movie/{id}` | MediaAccess |
| GET | `/api/v1/movie/{id}/available` | MediaAccess |
| GET | `/api/v1/movie/{id}/watch` | MediaAccess |

`available` answers whether the server actually holds a playable file. `watch` returns what a player needs to start.

## User actions

| Method | Path | Needs |
|--------|------|-------|
| POST | `/api/v1/movie/{id}/like` | MediaAccess |
| POST | `/api/v1/movie/{id}/watch-list` | MediaAccess |

Both act for the calling user, not for the server.

## Managing

| Method | Path | Needs |
|--------|------|-------|
| POST | `/api/v1/movie/{id}/add` | Moderator |
| POST | `/api/v1/movie/{id}/refresh` | Moderator |
| POST | `/api/v1/movie/{id}/rescan` | Moderator |
| DELETE | `/api/v1/movie/{id}` | Moderator |

`add` takes an optional `libraryId` and puts the film in that library.

`refresh` fetches the details and artwork again. `rescan` looks at the files on disk again. A wrong title is usually a refresh; a file the server has not noticed is a rescan.
