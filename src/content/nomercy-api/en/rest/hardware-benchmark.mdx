# Hardware benchmark

The benchmark measures what your machine actually manages, rather than what its parts claim. The result is what the server uses when choosing an accelerator.

## The cached result

| Method | Path | Needs |
|--------|------|-------|
| GET | `/api/v1/dashboard/hardware/benchmark` | Moderator |
| POST | `/api/v1/dashboard/hardware/benchmark/run` | Owner |

The result is kept, so reading it is cheap. Running it again is owner-only, because it puts the machine under load for as long as it takes.

## The encoder view

| Method | Path | Needs |
|--------|------|-------|
| GET | `/api/v1/encoder/capabilities` | Moderator |
| GET | `/api/v1/encoder/hardware/utilization` | Moderator |
| POST | `/api/v1/encoder/hardware/benchmark` | Moderator |
| GET | `/api/v1/encoder/hardware/benchmark` | Moderator |
| GET | `/api/v1/encoder/hardware/benchmark/{jobId}` | Moderator |

`capabilities` lists what this machine can do: which accelerators are present and what each can encode and decode.

`utilization` is the live picture while encoding runs.

Starting a benchmark here returns a job id. Poll that id for the result, rather than holding the request open.
