`NMCombobox` is the component your server names when it wants a combobox.
Like every NM component it accepts children and takes its box from the payload, so you can place
one inside a dashboard without it needing to know where it was placed.

## Sending one

A component arrives inside the standard envelope. The `component` field names it and `props` is
everything below.

```json
{
  "id": "combobox-1",
  "component": "NMCombobox",
  "props": {
    "id": "combobox-1",
    "size": "lg",
    "box": { "margin": { "y": "4" }, "padding": { "all": "3" } }
  }
}
```

The same thing from a server, or from a plugin, using the generated builder:

```csharp
NMComboboxProps props = new()
{
    Id = "combobox-1",
    Size = "lg",
    Box = new() { Margin = new() { Y = NmSpace.X4 }, Padding = new() { All = NmSpace.X3 } },
};

// In a plugin, the record becomes a node the client draws:
PluginComponent node = PluginDesign.Node("combobox-1", props);
```

## Options

Every option is optional. Leave one out and the component uses the default in the last column,
which is the same default on every platform.

| Option | Accepts | Default | What it does |
| --- | --- | --- | --- |
| `filterText` | text | `` | Current filter / typed text |
| `isLoading` | `true` , `false` | `false` | Show spinner instead of chevron |
| `multiple` | `true` , `false` | `false` | Enable multi-select tag mode |
| `placeholder` | text | `Search...` | Input placeholder text |
| `selected` | text | `` | Currently selected option (single-select mode) |
| `selectedItems` | text | `[]` | Currently selected options (multi-select mode) |
| `size` | `sm` , `md` , `lg` | `md` | Field and option item size |

## Children

Anything you nest under `items` renders inside it.

## What it reports

These are the moments the component tells the client about. In a payload you respond to them
with an `action`, which names an intent rather than carrying code.

| Event | Carries | When |
| --- | --- | --- |
| `select` | `{ value: string }` | Fired when an option is selected |
| `clear` | void | Fired when the clear button is clicked |
| `input` | `{ value: string }` | Fired on every keystroke in the input |
| `open` | void | Fired when listbox opens |
| `close` | void | Fired when listbox closes |

## Accessibility

You do not have to do anything to get this. It is built in, and the list is here so you know what
you can count on and what you would be breaking if you overrode it.

| Attribute | Why |
| --- | --- |
| `role="combobox"` | On the input element itself (ARIA 1.2 pattern) |
| `aria-autocomplete="list"` | On the input , options are filtered as you type |
| `aria-expanded` | On the input; reflects open/closed state of the listbox |
| `aria-controls` | On the input; references the listbox element id |
| `aria-haspopup="listbox"` | On the input; indicates the popup is a listbox |
| `aria-activedescendant` | On the input; points to the highlighted option id while navigating, without moving DOM focus |
| `role="listbox"` | On the dropdown list |
| `role="option"` | On each option item |
| `aria-selected` | Marks the currently selected option (or selected options in multi mode) |
| `aria-multiselectable` | Set to "true" on the listbox in multi-select mode |
| `aria-label` | On the clear button and each tag-remove button (e.g. "Remove Accessibility") |

### Keyboard and remote

Each of these works with a keyboard on web and with a D-pad on television.

| Key | What happens |
| --- | --- |
| `Type` | Opens the listbox and filters options as you type |
| `Arrow Down` | Opens the listbox (highlighting the first option), or moves the highlight down |
| `Arrow Up` | Opens the listbox (highlighting the last option), or moves the highlight up |
| `Home / End` | Jumps the highlight to the first / last option |
| `Enter` | Selects the highlighted option |
| `Escape` | Closes the listbox and returns focus to the input |
| `Backspace` | In multi-select, with an empty input, removes the last selected tag |
| `Tab` | Closes the listbox and moves focus to the next element |

## Placing it

Padding, margin, width, alignment and order all come from `box`, which every component accepts.
A parent decides where this component sits and how much room it takes; the component decides how
its own children are arranged. See [the box](/nm-components/box) for the full vocabulary.
