`NMSelect` is the component your server names when it wants a select.
Like every NM component it accepts children and takes its box from the payload, so you can place
one inside a dashboard without it needing to know where it was placed.

## Sending one

A component arrives inside the standard envelope. The `component` field names it and `props` is
everything below.

```json
{
  "id": "select-1",
  "component": "NMSelect",
  "props": {
    "id": "select-1",
    "size": "lg",
    "box": { "margin": { "y": "4" }, "padding": { "all": "3" } }
  }
}
```

## Options

Every option is optional. Leave one out and the component uses the default in the last column,
which is the same default on every platform.

| Option | Accepts | Default | What it does |
| --- | --- | --- | --- |
| `disabled` | `true` , `false` | `false` | Whether the select is disabled |
| `error` | `true` , `false` | `false` | Whether the select has a validation error |
| `placeholder` | text | `Select...` | Placeholder text shown when no option is selected |
| `size` | `sm` , `md` , `lg` | `md` | The size of the select field |

## Children

Anything you nest under `items` renders inside. The design system also names these places to put content:

| Slot | What goes there |
| --- | --- |
| `label` | Label component with required/optional markers |
| `helper` | Helper text component with error state support |

## What it reports

These are the moments the component tells the client about. In a payload you respond to them
with an `action`, which names an intent rather than carrying code.

| Event | Carries | When |
| --- | --- | --- |
| `change` | `{ value: string }` | Fired when the selected value changes |

## Accessibility

You do not have to do anything to get this. It is built in, and the list is here so you know what
you can count on and what you would be breaking if you overrode it.

| Attribute | Why |
| --- | --- |
| `role="combobox"` | Applied to the trigger button |
| `aria-expanded` | Indicates whether the dropdown menu is open |
| `aria-haspopup="listbox"` | Indicates the popup is a listbox |
| `aria-controls` | Links trigger to the dropdown menu by ID |
| `aria-activedescendant` | On the trigger; points to the highlighted option id while navigating |
| `role="listbox"` | Applied to the dropdown menu container |
| `role="option"` | Applied to each menu item |
| `aria-selected` | Indicates the currently selected option |
| `aria-invalid` | Set to "true" when select has validation errors |
| `data-state` | Set to "open" or "closed" for styling hooks |

### Keyboard and remote

Each of these works with a keyboard on web and with a D-pad on television.

| Key | What happens |
| --- | --- |
| `Space / Enter` | Opens the menu when closed; selects the highlighted option when open |
| `Arrow Down / Up` | Opens menu (when closed) or navigates between options (when open) |
| `Home` | Moves focus to first option (when menu is open) |
| `End` | Moves focus to last option (when menu is open) |
| `Escape` | Closes the dropdown and returns focus to trigger |
| `Tab` | Closes menu and moves focus to next element |
| `Type character` | Typeahead: jumps to option starting with typed character(s) |

## Placing it

Padding, margin, width, alignment and order all come from `box`, which every component accepts.
A parent decides where this component sits and how much room it takes; the component decides how
its own children are arranged. See [the box](/nm-components/box) for the full vocabulary.
