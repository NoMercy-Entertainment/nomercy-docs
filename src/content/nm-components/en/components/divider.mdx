`NMDivider` is the component your server names when it wants a divider.
Like every NM component it accepts children and takes its box from the payload, so you can place
one inside a dashboard without it needing to know where it was placed.

## Sending one

A component arrives inside the standard envelope. The `component` field names it and `props` is
everything below.

```json
{
  "id": "divider-1",
  "component": "NMDivider",
  "props": {
    "id": "divider-1",
    "badgeSize": "lg",
    "badgeVariant": "outline",
    "box": { "margin": { "y": "4" }, "padding": { "all": "3" } }
  }
}
```

## What it does

These are the behaviours the design system specifies for it, so you can rely on all of them
being present on web, on mobile and on television.

- Two orientations: horizontal (default) and vertical via mom-divider--vertical on hr
- Three line styles: solid, dashed, and dotted
- Optional label or content slot for text, badge, button, or button group
- Content placement: left, center, or right alignment
- Semantic <hr> element for horizontal dividers without content
- role="separator" for vertical dividers when using non-hr elements
- Flexible content slot accepts any child element
- CSS pseudo-elements (::before/::after) form flanking lines

## Options

Every option is optional. Leave one out and the component uses the default in the last column,
which is the same default on every platform.

| Option | Accepts | Default | What it does |
| --- | --- | --- | --- |
| `badgeColor` | text | `slate` | Badge color |
| `badgeSize` | `sm` , `md` , `lg` | `sm` | Badge size |
| `badgeVariant` | `ghost` , `solid` , `outline` | `ghost` | Badge variant |
| `btnSize` | `sm` , `md` , `lg` , `xl` , `2xl` | `md` | Button size |
| `btnState` | `default` , `disabled` , `loading` | `default` | Button state |
| `btnVariant` | `primary` , `secondary` , `secondary-color` , `tertiary` , `tertiary-color` , `link` , `link-color` , `destructive` | `secondary` | Button variant |
| `content` | `text` , `badge` , `button` , `button-group` | `text` | Type of content |
| `labelText` | text | `Divider` | Text label content |
| `line` | `solid` , `dashed` , `dotted` | `solid` | Line style |
| `placement` | `left` , `center` , `right` | `center` | Content placement |

## Children

Anything you nest under `items` renders inside it.

## Accessibility

You do not have to do anything to get this. It is built in, and the list is here so you know what
you can count on and what you would be breaking if you overrode it.

| Attribute | Why |
| --- | --- |
| `<hr>` | Semantic horizontal rule; screen readers announce as separator/thematic break |
| `role="separator"` | Use on vertical dividers (or non-hr elements) to expose as separator |
| `aria-orientation="vertical"` | Indicates vertical orientation for screen readers when using role="separator" |
| `aria-hidden="true"` | Optional on decorative dividers that add no semantic value |
| `aria-label` | Optional descriptive label for dividers that separate distinct regions |

### Keyboard and remote

Each of these works with a keyboard on web and with a D-pad on television.

| Key | What happens |
| --- | --- |
| `N/A` | Divider is non-interactive; it does not receive focus |
| `Tab` | Focus passes through; divider is not in tab order |
| `Shift + Tab` | Focus passes through when navigating backwards |
| `Screen reader` | Announces as separator or thematic break when using semantic markup |

## Placing it

Padding, margin, width, alignment and order all come from `box`, which every component accepts.
A parent decides where this component sits and how much room it takes; the component decides how
its own children are arranged. See [the box](/nm-components/box) for the full vocabulary.
