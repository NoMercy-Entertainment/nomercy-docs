`NMTextarea` is the component your server names when it wants a textarea.
Like every NM component it accepts children and takes its box from the payload, so you can place
one inside a dashboard without it needing to know where it was placed.

## Sending one

A component arrives inside the standard envelope. The `component` field names it and `props` is
everything below.

```json
{
  "id": "textarea-1",
  "component": "NMTextarea",
  "props": {
    "id": "textarea-1",
    "resize": "both",
    "size": "lg",
    "box": { "margin": { "y": "4" }, "padding": { "all": "3" } }
  }
}
```

## What it does

These are the behaviours the design system specifies for it, so you can rely on all of them
being present on web, on mobile and on television.

- Three sizes: sm, md, lg
- Multiple states: default, hover, focus, typing, filled, disabled
- Character counter with max limit
- Resize options: vertical, none, both
- Label with required/optional markers
- Helper text with error state support
- Fully accessible with ARIA attributes
- Live character count announcements for screen readers

## Options

Every option is optional. Leave one out and the component uses the default in the last column,
which is the same default on every platform.

| Option | Accepts | Default | What it does |
| --- | --- | --- | --- |
| `disabled` | `true` , `false` | `false` | Whether the textarea is disabled |
| `error` | `true` , `false` | `false` | Whether the textarea has a validation error |
| `maxChars` | number | `200` | Maximum character limit |
| `placeholder` | text | `` | Placeholder text shown when empty |
| `resize` | `vertical` , `none` , `both` | `vertical` | Resize behavior |
| `showCounter` | `true` , `false` | `false` | Show character counter |
| `size` | `sm` , `md` , `lg` | `md` | The size of the textarea |

## Children

Anything you nest under `items` renders inside. The design system also names these places to put content:

| Slot | What goes there |
| --- | --- |
| `label` | Label component with required/optional markers |
| `helper` | Helper text component with error state support |

## What it reports

These are the moments the component tells the client about. In a payload you respond to them
with an `action`, which names an intent rather than carrying code.

| Event | Carries | When |
| --- | --- | --- |
| `input` | `{ value: string, length: number }` | Fired on text input |

## Accessibility

You do not have to do anything to get this. It is built in, and the list is here so you know what
you can count on and what you would be breaking if you overrode it.

| Attribute | Why |
| --- | --- |
| `aria-describedby` | Links helper text and character counter to the textarea |
| `aria-required` | Set to "true" for required fields |
| `aria-invalid` | Set to "true" when textarea has validation errors |
| `role="status"` | Applied to character counter for live updates |
| `aria-live` | Set to "polite" on counter to announce changes to screen readers |
| `disabled` | Native HTML attribute for disabled state |

### Keyboard and remote

Each of these works with a keyboard on web and with a D-pad on television.

| Key | What happens |
| --- | --- |
| `Tab` | Moves focus to the next focusable element |
| `Shift + Tab` | Moves focus to the previous focusable element |
| `Enter` | Inserts a new line |

## Placing it

Padding, margin, width, alignment and order all come from `box`, which every component accepts.
A parent decides where this component sits and how much room it takes; the component decides how
its own children are arranged. See [the box](/nm-components/box) for the full vocabulary.
