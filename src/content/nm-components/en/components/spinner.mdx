`NMSpinner` is the component your server names when it wants a spinner.
Like every NM component it accepts children and takes its box from the payload, so you can place
one inside a dashboard without it needing to know where it was placed.

## Sending one

A component arrives inside the standard envelope. The `component` field names it and `props` is
everything below.

```json
{
  "id": "spinner-1",
  "component": "NMSpinner",
  "props": {
    "id": "spinner-1",
    "color": "gray",
    "size": "xl",
    "box": { "margin": { "y": "4" }, "padding": { "all": "3" } }
  }
}
```

## What it does

These are the behaviours the design system specifies for it, so you can rely on all of them
being present on web, on mobile and on television.

- Four sizes: sm, md, lg, and xl for flexible layout scaling
- Two color variants: accent (brand) and gray for subtle contexts
- Smooth spinning animation for clear loading feedback
- role="status" for assistive technology announcement
- aria-live="polite" announces loading state to screen readers
- aria-label="Loading" provides accessible name
- .sr-only text ("Loading...") for additional screen reader context
- Customizable aria-label via opts for contextual messages

## Options

Every option is optional. Leave one out and the component uses the default in the last column,
which is the same default on every platform.

| Option | Accepts | Default | What it does |
| --- | --- | --- | --- |
| `ariaLabel` | text | `Loading` | Accessible label |
| `color` | `accent` , `gray` | `accent` | Spinner color |
| `size` | `sm` , `md` , `lg` , `xl` | `md` | Spinner size |

## Children

Anything you nest under `items` renders inside it.

## Accessibility

You do not have to do anything to get this. It is built in, and the list is here so you know what
you can count on and what you would be breaking if you overrode it.

| Attribute | Why |
| --- | --- |
| `role="status"` | Identifies the element as a live region for status updates |
| `aria-live="polite"` | Announces loading state to screen readers without interrupting |
| `aria-label="Loading"` | Provides accessible name; customizable via opts.ariaLabel |
| `.sr-only` | Visually hidden "Loading..." text for additional context |

### Keyboard and remote

Each of these works with a keyboard on web and with a D-pad on television.

| Key | What happens |
| --- | --- |
| `N/A` | Spinner is non-interactive; it does not receive focus |
| `Tab` | Focus passes through; spinner is not in tab order |
| `Shift + Tab` | Focus passes through when navigating backwards |
| `Screen reader` | Announces "Loading" via aria-live when visible |

## Placing it

Padding, margin, width, alignment and order all come from `box`, which every component accepts.
A parent decides where this component sits and how much room it takes; the component decides how
its own children are arranged. See [the box](/nm-components/box) for the full vocabulary.
