`NMColorPicker` is the component your server names when it wants a color picker.
Like every NM component it accepts children and takes its box from the payload, so you can place
one inside a dashboard without it needing to know where it was placed.

## Sending one

A component arrives inside the standard envelope. The `component` field names it and `props` is
everything below.

```json
{
  "id": "color-picker-1",
  "component": "NMColorPicker",
  "props": {
    "id": "color-picker-1",
    "size": "lg",
    "box": { "margin": { "y": "4" }, "padding": { "all": "3" } }
  }
}
```

The same thing from a server, or from a plugin, using the generated builder:

```csharp
NMColorPickerProps props = new()
{
    Id = "color-picker-1",
    Size = "lg",
    Box = new() { Margin = new() { Y = NmSpace.X4 }, Padding = new() { All = NmSpace.X3 } },
};

// In a plugin, the record becomes a node the client draws:
PluginComponent node = PluginDesign.Node("color-picker-1", props);
```

## Options

Every option is optional. Leave one out and the component uses the default in the last column,
which is the same default on every platform.

| Option | Accepts | Default | What it does |
| --- | --- | --- | --- |
| `disabled` | `true` , `false` | `false` | Disable the swatch trigger |
| `label` | text | `` | Optional label text above the swatch |
| `selected` | text | x | Current hex colour value |
| `showInput` | `true` , `false` | `true` | Show hex input row in panel |
| `showPanel` | `true` , `false` | `true` | Show the colour picker panel |
| `size` | `sm` , `md` , `lg` | `md` | Trigger and palette option size |

## Children

Anything you nest under `items` renders inside it.

## What it reports

These are the moments the component tells the client about. In a payload you respond to them
with an `action`, which names an intent rather than carrying code.

| Event | Carries | When |
| --- | --- | --- |
| `change` | `{ color: string }` | Fired when a colour is selected |
| `open` | void | Fired when panel opens |
| `close` | void | Fired when panel closes |

## Accessibility

You do not have to do anything to get this. It is built in, and the list is here so you know what
you can count on and what you would be breaking if you overrode it.

| Attribute | Why |
| --- | --- |
| `aria-haspopup="dialog"` | On the swatch trigger to indicate it opens a panel |
| `aria-expanded` | On the trigger to communicate open/closed state |
| `aria-label="Pick colour, current: …"` | On the trigger with the current colour value |
| `role="dialog"` | On the panel to identify it as a dialog |
| `role="listbox"` | On the palette grid |
| `role="option"` | On each colour swatch |
| `aria-selected` | Marks the currently selected colour |
| `aria-label (colour hex)` | On each option to announce the colour value |

### Keyboard and remote

Each of these works with a keyboard on web and with a D-pad on television.

| Key | What happens |
| --- | --- |
| `Enter / Space` | Opens the panel when trigger is focused, or selects a focused colour option |
| `Arrow Keys` | Navigate between colour options in the palette grid |
| `Escape` | Closes the panel and returns focus to the swatch trigger |
| `Tab` | Moves focus between trigger, palette options, and hex input |

## Placing it

Padding, margin, width, alignment and order all come from `box`, which every component accepts.
A parent decides where this component sits and how much room it takes; the component decides how
its own children are arranged. See [the box](/nm-components/box) for the full vocabulary.
