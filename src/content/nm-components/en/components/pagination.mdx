`NMPagination` is the component your server names when it wants a pagination.
Like every NM component it accepts children and takes its box from the payload, so you can place
one inside a dashboard without it needing to know where it was placed.

## Sending one

A component arrives inside the standard envelope. The `component` field names it and `props` is
everything below.

```json
{
  "id": "pagination-1",
  "component": "NMPagination",
  "props": {
    "id": "pagination-1",
    "size": "lg",
    "box": { "margin": { "y": "4" }, "padding": { "all": "3" } }
  }
}
```

## What it does

These are the behaviours the design system specifies for it, so you can rely on all of them
being present on web, on mobile and on television.

- Three sizes: sm, md, and lg for different layout densities
- Previous and next buttons for sequential navigation
- Page number buttons with active state for current page
- Ellipsis for large page ranges (e.g. 1 … 5 … 15)
- role="navigation" on the nav element for screen readers
- aria-label on all buttons for accessible context
- aria-current="page" on the current page button
- aria-disabled on disabled prev/next buttons at boundaries

## Options

Every option is optional. Leave one out and the component uses the default in the last column,
which is the same default on every platform.

| Option | Accepts | Default | What it does |
| --- | --- | --- | --- |
| `currentPage` | number | `1` | Current page number |
| `size` | `sm` , `md` , `lg` | `md` | Pagination size |
| `totalPages` | number | `1` | Total number of pages |

## Children

Anything you nest under `items` renders inside it.

## What it reports

These are the moments the component tells the client about. In a payload you respond to them
with an `action`, which names an intent rather than carrying code.

| Event | Carries | When |
| --- | --- | --- |
| `change` | `{ page: number }` | Fired when page changes |

## Accessibility

You do not have to do anything to get this. It is built in, and the list is here so you know what
you can count on and what you would be breaking if you overrode it.

| Attribute | Why |
| --- | --- |
| `role="navigation"` | On the nav element to identify the pagination landmark |
| `aria-label` | On the nav element ("Pagination") and on each button for context |
| `aria-current="page"` | On the current page button so screen readers announce it as the active page |
| `aria-disabled` | On disabled prev/next buttons at first/last page to indicate unavailable state |
| `aria-hidden="true"` | On ellipsis spans so screen readers skip decorative content |

### Keyboard and remote

Each of these works with a keyboard on web and with a D-pad on television.

| Key | What happens |
| --- | --- |
| `Tab` | Moves focus to the next focusable button |
| `Shift + Tab` | Moves focus to the previous focusable button |
| `Enter` | Activates the focused button (e.g. go to page or prev/next) |
| `Space` | Activates the focused button |

## Placing it

Padding, margin, width, alignment and order all come from `box`, which every component accepts.
A parent decides where this component sits and how much room it takes; the component decides how
its own children are arranged. See [the box](/nm-components/box) for the full vocabulary.
