`NMButton` is the component your server names when it wants a button.
Like every NM component it accepts children and takes its box from the payload, so you can place
one inside a dashboard without it needing to know where it was placed.

## Sending one

A component arrives inside the standard envelope. The `component` field names it and `props` is
everything below.

```json
{
  "id": "button-1",
  "component": "NMButton",
  "props": {
    "id": "button-1",
    "layout": "full",
    "size": "2xl",
    "box": { "margin": { "y": "4" }, "padding": { "all": "3" } }
  }
}
```

The same thing from a server, or from a plugin, using the generated builder:

```csharp
NMButtonProps props = new()
{
    Id = "button-1",
    Layout = "full",
    Size = "2xl",
    Box = new() { Margin = new() { Y = NmSpace.X4 }, Padding = new() { All = NmSpace.X3 } },
};

// In a plugin, the record becomes a node the client draws:
PluginComponent node = PluginDesign.Node("button-1", props);
```

## Options

Every option is optional. Leave one out and the component uses the default in the last column,
which is the same default on every platform.

| Option | Accepts | Default | What it does |
| --- | --- | --- | --- |
| `ariaLabel` | text | x | Accessible label for icon-only buttons |
| `disabled` | `true` , `false` | `false` | Whether the button is disabled |
| `full` | `true` , `false` | `false` | Whether the button fills its container; content stays centred and the icon edge padding is not applied |
| `iconOnly` | `true` , `false` | `false` | Whether to render as icon-only (hides label) |
| `layout` | `hug` , `full` | `hug` | Layout |
| `loading` | `true` , `false` | `false` | Whether the button is in a loading state |
| `size` | `sm` , `md` , `lg` , `xl` , `2xl` | `md` | The size of the button |
| `variant` | `primary` , `secondary` , `secondary-color` , `tertiary` , `tertiary-color` , `link` , `link-color` , `destructive` , `ghost-destructive` | `primary` | The visual style variant of the button |

## Children

Anything you nest under `items` renders inside. The design system also names these places to put content:

| Slot | What goes there |
| --- | --- |
| `default` | Button content (text and/or icons) |
| `iconLeft` | Leading icon slot |
| `iconRight` | Trailing icon slot |

## What it reports

These are the moments the component tells the client about. In a payload you respond to them
with an `action`, which names an intent rather than carrying code.

| Event | Carries | When |
| --- | --- | --- |
| `click` | MouseEvent | Fired when button is clicked (unless disabled or loading) |

## Accessibility

You do not have to do anything to get this. It is built in, and the list is here so you know what
you can count on and what you would be breaking if you overrode it.

| Attribute | Why |
| --- | --- |
| `aria-label` | Required for icon-only buttons to provide accessible name |
| `aria-busy` | Set to "true" during loading state to announce to screen readers |
| `disabled` | Native HTML attribute prevents interaction and announces disabled state |

### Keyboard and remote

Each of these works with a keyboard on web and with a D-pad on television.

| Key | What happens |
| --- | --- |
| `Enter` | Activates the button |
| `Space` | Activates the button |
| `Tab` | Moves focus to the next focusable element |
| `Shift + Tab` | Moves focus to the previous focusable element |

## Placing it

Padding, margin, width, alignment and order all come from `box`, which every component accepts.
A parent decides where this component sits and how much room it takes; the component decides how
its own children are arranged. See [the box](/nm-components/box) for the full vocabulary.
