`NMToggles` is the component your server names when it wants a toggles.
Like every NM component it accepts children and takes its box from the payload, so you can place
one inside a dashboard without it needing to know where it was placed.

## Sending one

A component arrives inside the standard envelope. The `component` field names it and `props` is
everything below.

```json
{
  "id": "toggles-1",
  "component": "NMToggles",
  "props": {
    "id": "toggles-1",
    "size": "lg",
    "state": "indeterminate",
    "box": { "margin": { "y": "4" }, "padding": { "all": "3" } }
  }
}
```

## What it does

These are the behaviours the design system specifies for it, so you can rely on all of them
being present on web, on mobile and on television.

- Checkbox, Radio, and Switch with shared layout structure
- Label and optional helper text composition
- Three sizes: sm, md, lg (checkbox supports lg)
- Checked, unchecked, and indeterminate states (checkbox)
- Disabled state for all types
- Uses Checkbox, Radio, and Toggle primitives internally
- Consistent visual treatment across toggle types

## Options

Every option is optional. Leave one out and the component uses the default in the last column,
which is the same default on every platform.

| Option | Accepts | Default | What it does |
| --- | --- | --- | --- |
| `disabled` | `true` , `false` | `false` | Disabled state |
| `size` | `sm` , `md` , `lg` | `md` | Toggle size |
| `state` | `unchecked` , `checked` , `indeterminate` | `unchecked` | Toggle state |
| `type` | `checkbox` , `radio` , `switch` | `checkbox` | Toggle type |

## Children

Anything you nest under `items` renders inside it.

## Accessibility

You do not have to do anything to get this. It is built in, and the list is here so you know what
you can count on and what you would be breaking if you overrode it.

| Attribute | Why |
| --- | --- |
| `aria-checked` | For custom controls: "true", "false", or "mixed" (indeterminate) |
| `aria-describedby` | Reference helper text id for additional context |
| `aria-disabled` | Set when toggle is disabled |
| `aria-invalid` | Set when validation fails |

### Keyboard and remote

Each of these works with a keyboard on web and with a D-pad on television.

| Key | What happens |
| --- | --- |
| `Space` | Toggles checkbox and switch; selects radio option |
| `Enter` | Activates the control when focused |
| `Tab` | Moves focus to next focusable element |
| `Shift + Tab` | Moves focus to previous focusable element |
| `Arrow keys` | For radio groups: move selection between options |

## Placing it

Padding, margin, width, alignment and order all come from `box`, which every component accepts.
A parent decides where this component sits and how much room it takes; the component decides how
its own children are arranged. See [the box](/nm-components/box) for the full vocabulary.
