`NMButtonGroup` is the component your server names when it wants a button group.
Like every NM component it accepts children and takes its box from the payload, so you can place
one inside a dashboard without it needing to know where it was placed.

## Sending one

A component arrives inside the standard envelope. The `component` field names it and `props` is
everything below.

```json
{
  "id": "button-group-1",
  "component": "NMButtonGroup",
  "props": {
    "id": "button-group-1",
    "box": { "margin": { "y": "4" }, "padding": { "all": "3" } }
  }
}
```

## What it does

These are the behaviours the design system specifies for it, so you can rely on all of them
being present on web, on mobile and on television.

- Horizontally grouped buttons with shared borders
- Supports text-only, icon-only, or icon+text modes
- Active state for current selection
- Disabled state for individual items
- Position-aware styling (first, middle, last, single)
- Clipped corners with inner shadow overlays
- Keyboard navigation support
- Accessible with proper button semantics

## Children

Anything you nest under `items` renders inside it.

## Accessibility

You do not have to do anything to get this. It is built in, and the list is here so you know what
you can count on and what you would be breaking if you overrode it.

| Attribute | Why |
| --- | --- |
| `type="button"` | Prevents form submission when used inside forms |
| `aria-label` | Required for icon-only buttons to provide accessible name |
| `aria-hidden` | Applied to decorative icons |
| `disabled` | Native HTML attribute prevents interaction for disabled items |

### Keyboard and remote

Each of these works with a keyboard on web and with a D-pad on television.

| Key | What happens |
| --- | --- |
| `Tab` | Moves focus to the next button in the group |
| `Shift + Tab` | Moves focus to the previous button |
| `Enter / Space` | Activates the focused button |
| `Arrow Left / Right` | Navigate between buttons (optional enhancement) |

## Placing it

Padding, margin, width, alignment and order all come from `box`, which every component accepts.
A parent decides where this component sits and how much room it takes; the component decides how
its own children are arranged. See [the box](/nm-components/box) for the full vocabulary.
