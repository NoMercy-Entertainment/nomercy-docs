# Plugins overview

A plugin adds capability to your server without changing the server itself. Only the server owner can install one.

## What a plugin can extend

| Extension point | Lets a plugin |
|-----------------|---------------|
| Media source | Find media somewhere the server does not look on its own |
| Metadata | Supply titles, artwork and details from another source |
| Encoder | Decide the encoding profile for a title |
| Scheduled task | Run work on a schedule |
| Authentication | Take part in signing users in |
| User interface | Add screens and navigation to the dashboard |

A single plugin can do several of these.

The user interface point is worth understanding: the plugin describes the screen and each client renders it in its own style. One plugin therefore looks native on the web, on a phone and on a TV without shipping three interfaces.

## Where plugins come from

Repositories. Your server starts with the official NoMercy repository configured, and you can add others.

You can also install a plugin from a file, as a `.zip` carrying its manifest or as a bare `.dll`.

See [Repositories and trust](/nomercy-media-server/plugins/trusted-publishers) for how a repository is trusted and what that changes.

## Consent

This is the part worth reading before you install anything.

A plugin declares what it needs. A plugin that only reads media, supplies metadata or adds a screen is treated as ordinary and is enabled when you install it.

A plugin that wants more, such as reaching the network, adding its own endpoints, or opening a socket, **installs but stays switched off until you allow it**. It cannot switch itself on. You see it listed as waiting for consent, you read what it asked for, and you decide.

Consent is recorded against the exact set the plugin asked for. An update whose manifest asks for more, a hook it did not carry before, its own endpoints or socket, or another network host, loads disabled and waits for you again, with the addition named. Your earlier yes covered the smaller request, so it answers for that one and no other.

Where a plugin came from never answers for you. A repository you marked trusted says the plugin's origin is one you accept, and the plugin still asks you before it runs. See [Repositories and trust](/nomercy-media-server/plugins/trusted-publishers).

Consent can be withdrawn later. Withdrawing it disables the plugin and clears what you granted.

## Grants

Beyond that first decision, a plugin can ask for something specific while it runs: one network host, the ability to write into one named library, permission to play a source outside your library.

Each request arrives separately with the reason the plugin gave, and you approve them one at a time. A plugin cannot widen its own reach by asking once and taking everything.

## What this protects you from

Plugins run inside the server, so this is a permission model rather than a wall. The protections that exist are real, and knowing their shape is better than assuming more:

- A plugin only reaches the network hosts it declared or you granted.
- A plugin needing anything beyond the ordinary set cannot run until you say so, and one that later asks for more waits for you again.
- The endpoints a plugin adds ask the caller for a token, on the server's own terms rather than the plugin author's. A plugin that wants one open to anybody declares it in its manifest, where you read it before you consent.
- Its version compatibility is checked before it loads, so a plugin built against a different server version is rejected rather than half-loaded.
- Downloads from a repository are checked against the checksum the repository published.

Install plugins you have reason to trust, the same way you would with any software that runs on your machine.

## What the server asks before a plugin runs

Four questions, always in this order, and the first no is the one you are told.

1. Was this exact build withdrawn? A build NoMercy pulled back does not start, and installing the publisher's next release fixes it.
2. Is it paid for? Only paid plugins are asked. One you bought keeps running for a week if your server cannot reach NoMercy, then goes quiet until it can. Nothing is deleted.
3. Is everything it leans on here and running? A plugin whose dependency was turned off pauses with it.
4. Did you say yes to what it asks for? A plugin waiting on you is installed and off, and its page says so.

The order is what makes the message useful. A withdrawn build that also happens to be unpaid tells you it was withdrawn: told to buy it instead, you would buy it and watch nothing change.

Two other checks happen when a package arrives rather than when it starts: its signature, and whether sideloading is allowed on this server. Those are decisions about an install you already made, so they are not asked again.
