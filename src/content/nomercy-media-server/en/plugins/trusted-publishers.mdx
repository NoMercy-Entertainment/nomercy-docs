# Repositories and trust

A repository is a catalog of plugins your server can install from. Trust is decided per repository, by you.

## The default repository

Your server starts with the official NoMercy repository configured and marked trusted.

## Adding a repository

Add one from the Plugins section of the dashboard by giving its catalog address. Refreshing it pulls the current list, and the available plugins then show alongside what you already have, with updates flagged.

Only the server owner can add or remove a repository.

## What trusted means

Marking a repository trusted says where a plugin came from. It is provenance, and it is a plugin's route to the marketplace without a review hold before its release is published.

It is not your consent. A plugin from a trusted repository installs the same way as any other. One asking for more than the ordinary set still installs switched off and waits for you to read what it asked for.

Consent is about your own machine, and nothing outside it answers that for you. The model is described in [Plugins overview](/nomercy-media-server/plugins/overview).

The trusted flag is yours to set and to see: the repositories list shows it. You can turn it on or off per repository from the Plugins section of the dashboard.

Trust attaches to the repository, never to a name inside a plugin's own manifest. A plugin cannot describe itself as trustworthy; trust only comes from you having marked the place it came from.

## Whether to trust one

Trusting a repository is saying you accept where its plugins come from, for every plugin they publish and every update they push later.

Trust the official repository. Trust others when you know who runs them and you would take a release from them without a review hold in between.

Either way you read each plugin's declaration and approve it yourself, so trust never costs you the decision.

## What is checked regardless

Trusted or not, every install is checked for two things.

**Version compatibility.** A plugin built against a different server version is rejected rather than loaded.

**Checksum.** A plugin downloaded from a repository is checked against the checksum that repository published, so a file altered in transit does not install. The checksum covers the `.zip` package the plugin is released as, and a repository that published one against anything else has its install refused with the reason.

## A note on the name

Elsewhere in the dashboard you may meet **trusted publishers** under encoding. That is a different feature: it verifies signatures on imported encoding profiles. It has nothing to do with plugins.
