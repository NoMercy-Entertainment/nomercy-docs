# Encoding history

The server keeps a record of every title it has encoded. You reach it from the dashboard, under encoding.

It exists for two reasons: it answers "what did that actually cost me", and it is what the server uses to estimate how long queued work will take.

## What each entry records

| Recorded | Tells you |
|----------|-----------|
| Preset used | Which settings produced this result |
| GPU used | Whether it ran on a graphics card, and which one |
| Duration | How long the job took |
| Input size and output size | What went in and what came out |
| Compression ratio | How much smaller the result is |
| Average speed | How many times faster than real time it ran |
| Average frames per second | Throughput, useful when comparing presets |
| Date | When it ran |

## Using it to choose a preset

This is the honest answer to "which preset should I use", because it is measured on your hardware and your content rather than argued from a table.

Encode a few titles with one preset, then a few with another, and compare the compression ratio and duration columns. A preset that halves your storage at an acceptable speed is the right preset for you, whatever anyone else recommends.

## Estimating the queue

The dashboard's estimate of remaining work comes from this history: recent speeds against the size of what is still queued.

A new server has nothing to average, so early estimates are rough and settle as history accumulates.
