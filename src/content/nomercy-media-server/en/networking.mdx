# Networking

Your server needs to be reachable by your own devices. On your home network that works straight away. From outside, something has to let traffic in, and the server tries to arrange that by itself.

## The port

The server listens on port **7626**, and uses the same number on the outside by default. You can change either with the `--internal-port` and `--external-port` options.

It also opens **7627** for its own health checks. That one is loopback only, so nothing outside the machine can reach it, and it never needs a rule.

## How the server gets itself reachable

Setup does this without asking you anything. In order, it tries to:

1. **Use the tunnel assigned to your server.** A NoMercy subscription assigns a named tunnel to each of your servers on its own. When your server has one, that tunnel is its address from outside your network. It works even when your router allows nothing inbound, and a server that is running on a quick tunnel moves to it within a minute.
2. **Open a port on your router.** Without a named tunnel, or when the tunnel cannot connect, the server asks the router directly, using UPnP, and then asks the NoMercy API to connect to that address from the internet. A router that accepts the request but does not actually forward anything is common, which is why the check runs from outside instead of trusting the reply.
3. **Open a quick tunnel.** When there is no named tunnel and no verified port, the server opens a free Cloudflare quick tunnel on its own. It needs no account, no token and no router change. Cloudflare hands out a random `trycloudflare.com` address for this run, and your apps get that address from NoMercy the moment it is live. The address changes every time the server starts; your apps follow it without you doing anything.

A named tunnel wins over a port forward that works: with a subscription, your server's address from outside is its tunnel. Inside your own network, your apps keep using the local address. Every server ends up reachable from outside on one of the three, whatever the router allows.

When even the quick tunnel cannot connect out, the server stays reachable on your own network only, and keeps retrying in the background with growing gaps between attempts.

::Troubleshooting

**It works at home, not away from home.**
The server could not open any outside route, not even a quick tunnel. That happens when the network blocks the server from connecting out, for example a strict firewall or a VPN. The server keeps retrying, and becomes reachable from outside by itself once it can connect out.

**Nothing reaches the server at all, even at home.**
Check the machine's firewall. On Windows the prompt appears the first time the server runs and has to be allowed.

::
