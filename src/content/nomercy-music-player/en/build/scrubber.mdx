# Build a Player: The Scrubber

[Step 1](/nomercy-music-player/build/shell) mounted the native bar. The config below is identical. There is nothing to add, because the native scrubber already covers seeking. This page names the methods you will use the day you build your own.

## What the native scrubber actually does

`controls: true` sets `controls` on the audio element and stops there. The scrubber you see is the browser's, and it seeks that element directly rather than calling `time(seconds)`.

The player still follows along, because it tracks the element's `timeupdate`. So a native seek moves `time()` and keeps `'time'` and `'duration'` firing, both covered on [Time & Seeking](/nomercy-music-player/tour/time). Those two events and `time(seconds)` are what a custom scrubber is built from:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-music-player';

const player = nmplayer('player');
const scrubber = document.querySelector<HTMLInputElement>('#scrubber')!;
let dragging = false;
scrubber.addEventListener('pointerdown', () => { dragging = true; });
scrubber.addEventListener('change', () => {
  dragging = false;
  void player.time(Number(scrubber.value));
});

player.on('duration', ({ duration }) => {
  scrubber.max = String(duration);
});
player.on('time', ({ time }) => {
  if (!dragging) scrubber.value = String(time);
});
```

The `dragging` guard matters the moment you build this yourself. Without it, an incoming `'time'` update mid-drag snaps the thumb back to the actual playback position every frame, fighting the user's own gesture. Seek only on `change` (release), never on `input` (continuous). This is the same rule [Time & Seeking](/nomercy-music-player/tour/time) documents for `time()`.
