# Build a Player: The Track List

The last two steps had nothing to add — the native bar already covers transport. This step is different: `controls: true` has no concept of a playlist at all, so a track-list toggle is the first thing in this tutorial actually worth hand-building.

## One button, not a bar

Earlier versions of this tutorial rebuilt play/pause, seeking, and volume as a competing custom bar sitting next to the native one. That's gone — the config below is still just `controls: true`. What's new is a single small button, positioned clear of the native bar, that opens a panel built fresh from `queue()`/`index()` on every open, exactly the pattern [The Queue](/nomercy-music-player/tour/queue) documents:

```ts
function renderList() {
  list.replaceChildren();
  const items = player.queue();
  const activeIndex = player.index();

  items.forEach((item, index) => {
    addOption(item.name, index === activeIndex, () => {
      player.item(index, { autoplay: true });
    });
  });
}
```

Each option button is built with `createButton`, `nomercy-player-core`'s accessible DOM helper, so every entry gets a real `aria-label` for free.

## Keeping the highlight in sync

A track can change without a click on this menu at all — `next()`, `previous()`, or a manual [`crossfadeTo()`](/nomercy-music-player/tour/crossfade) all move the cursor. Re-render whenever the queue's `item` event fires and the list happens to be open, instead of only updating on a click inside the menu itself:

```ts
player.on('item', () => {
  if (menuIsOpen) renderList();
});
```
