# Build a Player: The Shell

Five steps. Mount a real music player, then add the two things it genuinely lacks: a track list and a now-playing panel.

Music ships no UI plugin. There is no chrome overlay for audio the way there is for video.

So steps 1 to 3 cover what the native bar gives you for free, and steps 4 and 5 build what it cannot.

The custom-UI steps lean on the Plugin base helpers: `mount`, `createElement`, `addClasses`, `listen`, and their siblings. Each is used in context here; the [Plugin Handbook](/nomercy-player-core/handbook/building-dom) teaches every one in full when you want the complete picture.

## The real chrome is native

`controls: true` renders the browser's own `<audio controls>` bar. It is the same bar the [Quickstart](/nomercy-music-player/quickstart) mounts. There's no options surface to configure it with; the browser owns its layout and rendering entirely:

```ts
const config: MusicPlayerConfig = {
  baseUrl,
  playlist: songs,
  controls: true,
};
```

`item(0)` loads the first track once `setup()`'s pipeline settles, so the bar has something to play. Music has no `autoPlay` config field the way video does. Browsers block audio autoplay outside a user gesture anyway.

## What the native bar already covers

Play/pause, seeking, volume, and mute are all in the bar the moment `controls: true` is set. The next two steps ([Scrubber](/nomercy-music-player/build/scrubber), [Volume](/nomercy-music-player/build/volume)) point at the exact kit methods driving it under the hood. These are useful the day you swap the native bar for a fully custom one, not because anything is missing here.
