# Build a Player: Volume

[Step 2](/nomercy-music-player/build/scrubber) covered seeking. Same pattern here — the native bar already has a volume slider and a mute toggle, so the config is unchanged again. This is the last of the three "nothing to build" steps before [The Track List](/nomercy-music-player/build/track-list) adds something real.

## What's already wired

The native slider applies live on every drag through `volume(level)` — 0-100, clamped, no cost to spamming it the way seeking has. The mute button reflects `volumeState()` (see [Volume](/nomercy-music-player/tour/volume)) and resyncs on the `'mute'` event rather than tracking a local boolean, so it can't drift when something else changes mute state — a keyboard shortcut, a Connect sync, another tab:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-music-player';
import { VolumeState } from '@nomercy-entertainment/nomercy-music-player';

const player = nmplayer('player');

player.on('mute', () => {
  const muted = player.volumeState() === VolumeState.MUTED;
  // update a custom mute icon here
});
```

A click only ever *requests* a change — `toggleMute()` — the `'mute'` event is what confirms it and is the only thing a custom UI should render from.
