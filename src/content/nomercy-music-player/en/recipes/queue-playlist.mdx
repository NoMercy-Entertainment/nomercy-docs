# Recipe: Queue & Playlist Panel

[The Queue](/nomercy-music-player/tour/queue) covers the full mutation surface, `queueAppend`, `queueMove`, `queueShuffle`, and the rest. This recipe is the task most apps actually reach for first: a panel that shows the queue, highlights what's playing, and lets the user jump to any track in it.

## Rendering the list

Rebuild the panel from `queue()` fresh on every render rather than mutating DOM nodes in place. It stays correct after a shuffle or a removal without tracking index deltas by hand:

```ts
function renderQueue(player: IMusicPlayer, panel: HTMLElement): void {
  panel.replaceChildren();
  const activeId = player.item()?.id;

  player.queue().forEach((item, index) => {
    const row = document.createElement('button');
    row.type = 'button';
    row.textContent = `${index + 1}. ${item.name}${item.artist ? ` — ${item.artist}` : ''}`;
    row.setAttribute('aria-current', item.id === activeId ? 'true' : 'false');
    row.addEventListener('click', () => player.playItem(item.id));
    panel.appendChild(row);
  });
}
```

## Re-rendering on the right events

Two events cover every way the panel's content can go stale:

| Event | Fires when |
|---|---|
| `'item'` | The cursor moved; a different row is now active. |
| `'queue'` | Items were added, removed, reordered, or replaced. |

```ts
import nmplayer from '@nomercy-entertainment/nomercy-music-player';

const player = nmplayer('player');
const panel = document.querySelector<HTMLElement>('#queue-panel')!;

player.on('item', () => renderQueue(player, panel));
player.on('queue', () => renderQueue(player, panel));
renderQueue(player, panel); // initial paint
```

Subscribing to both instead of polling means the panel updates immediately on a shuffle, a crossfade-driven advance, or another client's Connect-synced queue change, not just a local click.

## playItem() closes the item()/play() race

A naive click handler races. `player.item(item.id); player.play();` fires a fire-and-forget `load()`. The `play()` call right after can reach the backend before the new source is set.

`playItem(target)` closes that race, and `playNow(items, start?)` does the same when replacing the whole queue.

Both route through `item(target, { autoplay: true })`, which calls `play()` inside the resolved `load()`'s own continuation:

```ts
player.playItem(item.id);            // jump to a track already in the queue and play it
player.playNow(album, 'track-2');    // replace the queue and start playing this track
```

Use `playItem`/`playNow` for anything the user clicks. Reserve a plain `item(target)` for cases where you deliberately don't want autoplay, such as restoring a paused session at the last position.
