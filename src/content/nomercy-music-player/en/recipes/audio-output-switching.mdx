# Recipe: Audio Output Switching

[Audio Output Devices](/nomercy-music-player/tour/audio-output) covers `audioOutputs()`, `selectAudioOutput()`, and `audioOutput()` individually. This recipe assembles them into the UI most apps actually ship: a persistent device switcher rather than a picker that only opens on demand.

## A select pre-selected to the active device

`audioOutputs()` enumerates devices without a permission prompt. `audioOutput()`, called with no argument, reads the currently-selected device id, or `null` for the system default. Read both together, and the dropdown opens already showing the right selection instead of defaulting to the first entry:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-music-player';
import type { IMusicPlayer } from '@nomercy-entertainment/nomercy-music-player';

async function renderDeviceSelect(player: IMusicPlayer, select: HTMLSelectElement): Promise<void> {
  const [devices, current] = await Promise.all([player.audioOutputs(), player.audioOutput()]);
  select.replaceChildren();

  devices.forEach((device, index) => {
    const option = document.createElement('option');
    option.value = device.deviceId;
    option.textContent = device.label || `Output ${index + 1}`;
    if (device.deviceId === current) option.selected = true;
    select.appendChild(option);
  });
}

const player = nmplayer('player');
const select = document.querySelector<HTMLSelectElement>('#audio-output')!;
void renderDeviceSelect(player, select);

select.addEventListener('change', () => {
  void player.audioOutput(select.value);
});
```

## Labels need a permission grant first

Browsers gate device *labels*, not the device list. Before a permission grant, `audioOutputs()` still resolves with the right number of entries, some or all with an empty `label`.

For readable names on first render, trigger a microphone permission prompt through `getUserMedia` before calling `renderDeviceSelect`, or reuse a grant the app already holds.

Then call it again once the permission resolves:

```ts
async function ensureDeviceLabels(): Promise<void> {
  try {
    const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
    stream.getTracks().forEach((track) => track.stop()); // release immediately, only needed for the permission grant
  }
  catch {
    // Permission denied — fall back to unlabeled entries, the switcher still works.
  }
}
```

Don't request this permission just to populate a device list. Only ask for it if your app already needs microphone access for another reason, such as voice search or a companion recording feature. Otherwise, the unlabeled `audioOutputs()` result plus the native picker below covers device switching without an extra prompt.

## The native picker as a fallback entry point

`selectAudioOutput()` opens the browser's own device picker. It works as an always-available "choose a device" button regardless of whether labels are populated, because the native picker doesn't carry the label-gating restriction the enumeration API does:

```ts
const pickerButton = document.querySelector<HTMLElement>('#choose-output')!;

pickerButton.addEventListener('click', () => {
  void player.selectAudioOutput().then(async (device) => {
    if (device) {
      await player.audioOutput(device.deviceId);
      await renderDeviceSelect(player, select); // resync the <select> to the new choice
    }
  });
});
```

`selectAudioOutput()` works only in Chrome 105 and later. Every other browser throws a structured `BrowserPolicyError`. Wrap the click handler's call in a check or a try/catch, and hide the button on unsupported browsers rather than surfacing a raw rejection.
