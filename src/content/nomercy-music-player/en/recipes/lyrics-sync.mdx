# Recipe: Synced Lyrics UI

[Lyrics](/nomercy-music-player/tour/lyrics) covers registering `LyricsPlugin` and reading the single active line. This recipe builds the fuller UI most listening apps actually want: every line visible at once, in a scrollable panel, with the active one highlighted and scrolled into view as playback moves through it.

## Rendering the whole cue list up front

`all()` returns every parsed cue for the current track, not just the active one. Render it once, on the plugin's `loaded` event, rather than building rows incrementally as lines become active:

```ts
import { LyricsPlugin } from '@nomercy-entertainment/nomercy-music-player/plugins/lyrics';

player.addPlugin(LyricsPlugin);
player.setup({ baseUrl, playlist });

const rows = new Map<{ text: string }, HTMLElement>();

player.on('plugin:lyrics:loaded', () => {
  const lyrics = player.getPlugin(LyricsPlugin);
  panel.replaceChildren();
  rows.clear();

  for (const cue of lyrics?.all() ?? []) {
    const row = document.createElement('div');
    row.textContent = cue.payload.text;
    panel.appendChild(row);
    rows.set(cue.payload, row);
  }
});
```

## Matching the active line by identity, not text

`lineEnter` and `lineExit` hand back the cue's `payload` object directly, the exact same reference `all()` already put in the `rows` map. Using that reference as the map key means the active-line lookup works correctly even when a song repeats a line (a chorus), where matching by text content would highlight every occurrence instead of only the current one:

```ts
player.on('plugin:lyrics:lineEnter', (payload) => {
  const row = rows.get(payload);
  if (row) {
    row.classList.add('active');
    row.scrollIntoView({ block: 'center', behavior: 'smooth' });
  }
});

player.on('plugin:lyrics:lineExit', (payload) => {
  rows.get(payload)?.classList.remove('active');
});
```

## Handling the no-lyrics case

Not every track carries a `lyricsUrl`, [Lyrics](/nomercy-music-player/tour/lyrics#no-lyrics-file-no-error) covers why that's silent rather than an error. A panel built this way should show something explicit rather than sitting empty:

```ts
player.on('plugin:lyrics:loaded', () => {
  const lyrics = player.getPlugin(LyricsPlugin);
  const cues = lyrics?.all() ?? [];
  if (cues.length === 0) {
    panel.textContent = 'No synced lines in this file.';
    return;
  }
  // ...render rows as above
});
```

`loaded` only fires once a lyrics file was actually found, parsed, and attached, when `item.lyricsUrl` is missing entirely the plugin clears state without emitting anything, clear the panel on the `current` event's item change so a previous track's lyrics don't linger on screen.
