# Recipe: Synced Lyrics UI

[Lyrics](/nomercy-music-player/tour/lyrics) covers registering `LyricsPlugin` and reading the single active line. This recipe builds the fuller UI most listening apps actually want: every line visible at once, in a scrollable panel. The active line highlights and scrolls into view as playback moves through it.

## Rendering the whole cue list up front

`all()` returns every parsed cue for the current track, not just the active one. Render it once, on the plugin's `loaded` event, rather than building rows incrementally as lines become active:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-music-player';
import { LyricsPlugin } from '@nomercy-entertainment/nomercy-music-player/plugins/lyrics';

const player = nmplayer('player');
player.addPlugin(LyricsPlugin);
player.setup({
  baseUrl: 'https://raw.githubusercontent.com/NoMercy-Entertainment/nomercy-media/master/Music',
  playlist: [
    {
      id: 'ketsa-01-where-dreams-drift',
      name: 'Where Dreams Drift',
      artist: 'Ketsa',
      url: '/K/Ketsa/CC.BY.FREE.TO.USE.FOR.ANYTHING.(2025)/01.Where.Dreams.Drift.mp3',
      lyricsUrl:
        'https://raw.githubusercontent.com/NoMercy-Entertainment/nomercy-media/master/Music/K/Ketsa/CC.BY.FREE.TO.USE.FOR.ANYTHING.(2025)/01.Where.Dreams.Drift.lrc',
    },
  ],
});

const panel = document.querySelector<HTMLElement>('#lyrics-panel')!;
const rows = new Map<{ text: string }, HTMLElement>();

player.on('plugin:lyrics:loaded', () => {
  const lyrics = player.getPlugin(LyricsPlugin);
  panel.replaceChildren();
  rows.clear();

  for (const cue of lyrics?.all() ?? []) {
    const row = document.createElement('div');
    row.textContent = cue.payload.text;
    panel.appendChild(row);
    rows.set(cue.payload, row);
  }
});
```

## Matching the active line by identity, not text

`lineEnter` and `lineExit` hand back the cue's `payload` object directly. It is the exact same reference `all()` already put in the `rows` map.

Use that reference as the map key, not the text. A chorus repeats the same words, and a text match would light up every occurrence instead of the one playing now:

```ts
player.on('plugin:lyrics:lineEnter', (payload) => {
  const row = rows.get(payload);
  if (row) {
    row.classList.add('active');
    row.scrollIntoView({ block: 'center', behavior: 'smooth' });
  }
});

player.on('plugin:lyrics:lineExit', (payload) => {
  rows.get(payload)?.classList.remove('active');
});
```

## Handling the no-lyrics case

Not every track carries a `lyricsUrl`. [Lyrics](/nomercy-music-player/tour/lyrics#no-lyrics-file-no-error) covers why that case is silent instead of an error. A panel built this way should show something explicit rather than sitting empty:

```ts
player.on('plugin:lyrics:loaded', () => {
  const lyrics = player.getPlugin(LyricsPlugin);
  const cues = lyrics?.all() ?? [];
  if (cues.length === 0) {
    panel.textContent = 'No synced lines in this file.';
    return;
  }
  // ...render rows as above
});
```

`loaded` only fires once a lyrics file is found, parsed, and attached. When `item.lyricsUrl` is missing entirely, the plugin clears state without emitting anything. Clear the panel on the `item` event's cursor change too, so a previous track's lyrics don't linger on screen.
