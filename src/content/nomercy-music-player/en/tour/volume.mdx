# Volume

Volume here is one number with two meanings, and keeping them apart is most of the work.

`player.volume()` gives you a slider position on a 0 to 100 scale.
What reaches the audio is a gain, and it is a different number.

Everything below is safe to call once `ready()` has resolved.

## Reading and setting the level

`volume()` with no argument returns the current position.
`volume(level)` sets it, clamps it to 0 to 100, and hands back a promise you can await.

```ts
const level = player.volume(); // 0 to 100
await player.volume(50);
```

A fresh player sits at 100.

`volumeUp()` and `volumeDown()` move the level by five points.
Pass your own step to either one.

```ts
player.volumeDown(); // five points down
player.volumeUp(10); // ten points up
```

Both route through `volume()`, so both clamp the same way.
Neither returns anything to await, which is what makes them the pair a key binding reaches for.

## What the level does to the sound

The position is squared before it becomes gain.

| Position | Gain |
| --- | --- |
| 100 | 1 |
| 50 | 0.25 |
| 30 | 0.09 |
| 0 | 0 |

Loudness is heard logarithmically.
Mapping the slider straight onto gain packs most of the audible range into the bottom of the travel, so the top half of the slider does almost nothing.
The square-law taper spreads the change out instead.

The squaring happens where the level meets the audio, not in `volume()`.
`player.volume()` always reports the position you set.

## Where the level lands

Two audio backends ship, and the same `volume(50)` call reaches the sound differently in each.

The default is `str audio-element`.
It writes the gain straight onto the `<audio>` element, in one step: `element.volume` becomes `0.25`.

Ask for the other one at setup:

```ts
player.setup({
  backend: 'webaudio',
  // baseUrl, playlist, and the rest
});
```

Now the gain goes onto the `cls GainNode` at the head of the Web Audio chain instead, ahead of the `cls AnalyserNode` a spectrum plugin taps.
It is eased in with a 10 ms time constant rather than set outright, which is the difference between a fade and a click under a fast drag.

The audio element's own `volume` stays at 1 on this path and the player never writes to it.
Reading it tells you nothing about where the slider is.

So read `player.volume()` and nothing else.
It is the only reader that answers with a position; each backend holds the squared gain instead.

## Mute

`mute()` and `unmute()` are absolute.
`toggleMute()` flips whichever way the player currently sits.

```ts
await player.mute();
await player.unmute();
player.toggleMute();
```

Calling for a state the player is already in does nothing at all.
No event, no change.

Mute is the audio element's own `key muted` flag, on both backends.
The gain is left where it was, so unmuting brings the level back without you storing it.

While muted, `volume()` reports `0` rather than the stored level.
A slider bound to it drops to zero on mute and returns on unmute, with nothing extra to write.

Set a level above 0 while muted and the player unmutes itself.
That is what someone dragging a muted slider means, and it saves you from a slider that moves while nothing plays.

## Keeping a control in step

`volumeState()` returns `cls VolumeState.MUTED` or `cls VolumeState.UNMUTED`.
Render a mute button from that, never from a boolean of your own.

The `str volume` and `str mute` events fire whatever caused the change: your slider, a key binding, or another part of your app.
A control that draws itself from those two cannot fall out of step.

```ts
import { VolumeState } from '@nomercy-entertainment/nomercy-music-player';

player.on('volume', ({ level }) => {
  slider.value = String(level);
});

player.on('mute', () => {
  const muted = player.volumeState() === VolumeState.MUTED;
  muteButton.setAttribute('aria-pressed', String(muted));
});
```

## See it running

Drag the slider and press mute.
The button reads `volumeState()` on every `mute` event, so it cannot drift.

## Remembering the level

Nothing here persists.
Every reload starts at 100 again, unmuted.

[Volume Memory](/nomercy-player-core/plugins-adapters/volume-memory) is the plugin that saves the level and the mute flag on every change, and puts them back when it starts.
