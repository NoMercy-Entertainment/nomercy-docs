# The Queue

Behind `queue()` is one cursor-aware `MediaList<T>` instance, the same structure [Core: The Queue](/nomercy-player-core/tour/queue) documents. `nomercy-music-player` adds the item shape (`MusicPlaylistItem`). Everything else, the queue mechanics included, is unchanged kit code.

## The track shape

`MusicPlaylistItem` carries these fields:

- `name`
- `artist`
- `album`
- `cover`
- `url`
- `lyricsUrl`
- `duration`

`name` is the canonical display field. `title` also works, since it is inherited from the base shape. But `name` is what the rest of this library reads:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-music-player';

const player = nmplayer('player');
player.setup({
  baseUrl: 'https://raw.githubusercontent.com/NoMercy-Entertainment/nomercy-media/master/Music',
  playlist: [
    {
      id: 'ketsa-01-where-dreams-drift',
      name: 'Where Dreams Drift',
      artist: 'Ketsa',
      url: '/K/Ketsa/CC.BY.FREE.TO.USE.FOR.ANYTHING.(2025)/01.Where.Dreams.Drift.mp3',
    },
    {
      id: 'ketsa-02-saviour-above',
      name: 'Saviour Above',
      artist: 'Ketsa',
      url: '/K/Ketsa/CC.BY.FREE.TO.USE.FOR.ANYTHING.(2025)/02.Saviour.Above.mp3',
    },
  ],
});
```

`url` stays relative and `baseUrl` supplies the origin. That is the pattern [Quick Start](/nomercy-music-player/quickstart#the-baseurl-pattern) introduces. There is no `file` → `url` normalization step here. A track is already in its canonical shape the moment it enters the queue.

`cover` resolves differently. See [Now Playing & Lyrics](/nomercy-music-player/build/now-playing) for why cover art usually needs a fully-qualified URL instead.

## Reading, moving, and mutating the queue

Reading the cursor, moving it, and mutating the queue (append, prepend, insert, remove, move, clear, shuffle, sort) are all unchanged kit methods. `playItem(target)` and `playNow(items, start?)` are the race-free way to jump to a track and play it in one call, closing a gap where `queue(items); item(start); play()` can reach the backend before the source is even set.

Every mutation fires a typed event (`queue:append`, `queue:move`, ...) that a reactive track-list UI subscribes to instead of re-reading `queue()` after every call. The full method list, signatures, and event names are on [Reference: Domain Types](/nomercy-player-core/reference/types#queue-methods).

```ts
const items = player.queue(); // ReadonlyArray<MusicPlaylistItem>
const current = player.item();
player.item('track-2'); // by id
player.item(1); // by index

player.playNow(album, 'track-2'); // replace the queue and start playing this track
player.playItem('track-1'); // jump to a track already in the queue and play it
```

`peekNext()` / `peekPrevious()` read what `next()` / `previous()` (see [Transport](/nomercy-music-player/tour/transport)) would load. They do not move the cursor or trigger a load. Use them for a "coming up next" label, or to pick the target of a manual [crossfade](/nomercy-music-player/tour/crossfade).
