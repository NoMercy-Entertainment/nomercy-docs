# Audio Output Devices

Sound leaves the machine through whichever device the system already chose.
A listener who wants a different one, headphones now and a Bluetooth speaker in ten minutes, has to be able to say so.

Three calls cover it, and the player you created in the [Quick Start](/nomercy-music-player/quickstart) carries all three.
They come from the kit rather than from music, so a video player answers to the same names.

| Call | Answers with |
| --- | --- |
| `audioOutputs()` | Every device the browser reports as an audio output. |
| `selectAudioOutput()` | The device chosen in the browser's own picker, or `null`. |
| `audioOutput(deviceId)` | Nothing. Playback moves to that device. |

## List what the browser reports

`audioOutputs()` calls `navigator.mediaDevices.enumerateDevices()` and keeps the entries whose `kind` is `audiooutput`.

Nothing on that path asks for permission, so the list is safe to build while the page loads.

Each entry is a `MediaDeviceInfo`, and the two fields you want are `deviceId` and `label`.
The example below names each device by its `label`, and falls back to a numbered name when that label is empty.

## Let the listener choose

`selectAudioOutput()` opens the browser's own output picker and resolves with the device chosen in it.

Dismissing the picker is not a failure.
The call inspects the rejection's `name`, and returns `null` for both `AbortError` and `NotAllowedError`.
Any other rejection is rethrown as it arrived.

## Route playback there

`audioOutput(deviceId)` calls `setSinkId(deviceId)` on the backend's media element, then stores the id.

An empty string is passed straight through to `setSinkId`, and the stored id is cleared to `null` rather than kept as `''`.

Called with no argument, `audioOutput()` reads instead of writes.
It returns the element's live `sinkId`, or the id last stored when the element has none, and `null` when either is the empty string.

```ts
const device = await player.selectAudioOutput();

if (device) await player.audioOutput(device.deviceId);
```

## Where a browser stops you

Not every browser exposes both halves of this, and the player says so in three different shapes.

`audioOutputs()` resolves with an empty array where there is no `navigator.mediaDevices.enumerateDevices` to call.
It throws nothing, so an empty list is the whole signal.

`selectAudioOutput()` throws a `BrowserPolicyError` with code `core:policy/audioOutputPickerUnsupported` when the browser exposes no picker.
The list above is still the working path there, which is why the example offers both.

`audioOutput(deviceId)` throws a `BrowserPolicyError` with code `core:policy/setSinkIdUnsupported` when the media element has no `setSinkId`.
The same error covers the case where no element is bound yet, so make the call once `ready()` has resolved.

Both are thrown out of the call rather than emitted on the bus, so they land in your `catch` and not in an `error` listener.
