# Audio Output Devices

Picking which speaker plays audio matters constantly for a listening session, headphones now, a Bluetooth speaker in ten minutes, a desk speaker after that. The device-routing surface lives in the kit, `nomercy-music-player` is simply the library most consumers reach for it from.

## Listing devices

`audioOutputs()` enumerates available output devices without prompting for permission:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-music-player';

const player = nmplayer('player');

const devices = await player.audioOutputs(); // MediaDeviceInfo[]
```

Browsers gate device *labels* behind a permission grant, without one, `enumerateDevices()` still returns entries, just with an empty `label` on some devices. Render what you get, a picker button covers the rest.

## Picking one

`selectAudioOutput()` opens the browser's own output picker (Chrome ≥105 only, everything else throws a structured `BrowserPolicyError`) and resolves with the chosen device, or `null` if the user cancels:

```ts
const device = await player.selectAudioOutput();
if (device) {
  await player.audioOutput(device.deviceId);
}
```

`audioOutput()` reads the currently-selected device id (`null` for the system default); `audioOutput(deviceId)` routes playback there by calling `setSinkId()` on the backend's media element, and throws `BrowserPolicyError` when the browser doesn't support it.
