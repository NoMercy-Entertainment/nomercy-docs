# Audio Output Devices

A listening session moves between speakers all the time: headphones now, a Bluetooth speaker in ten minutes, a desk speaker after that. The device-routing surface lives in the kit. `nomercy-music-player` is simply the library most consumers reach for it from.

## Listing devices

`audioOutputs()` enumerates available output devices without prompting for permission:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-music-player';

const player = nmplayer('player');

const devices = await player.audioOutputs(); // MediaDeviceInfo[]
```

Browsers gate device *labels* behind a permission grant. Without a grant, `enumerateDevices()` still returns entries, but some carry an empty `label`. Render what you get. A picker button covers the rest.

## Picking one

`selectAudioOutput()` opens the browser's own output picker. It resolves with the chosen device, or `null` when the user cancels. The picker exists in Chrome 105 and later only. Every other browser throws a structured `BrowserPolicyError`:

```ts
const device = await player.selectAudioOutput();
if (device) {
  await player.audioOutput(device.deviceId);
}
```

Two calls read and set the device:

| Call | What it does |
| --- | --- |
| `audioOutput()` | Reads the currently-selected device id (`null` for the system default). |
| `audioOutput(deviceId)` | Routes playback to that device by calling `setSinkId()` on the backend's media element. |

When the browser does not support `setSinkId()`, the call throws `BrowserPolicyError`.
