# Transport

A music player makes no sound on its own.

The player you built in [Quick Start](/nomercy-music-player/quickstart) has a track cued and is silent, and it stays that way until you call `play()`.
Every method below comes from [Core: Transport](/nomercy-player-core/tour/transport), which owns the cancellable cycle each one runs.
Music adds no transport method of its own.

## Nothing starts until you ask

`setup()` arms the queue and returns.
Once the player is ready it loads the first track with autoplay off, so a control bar has something to act on and the room stays quiet.

There is no autoplay option on the music config.
The first `play()` is the first sound, and that is what a browser wants: a gesture before the audio.

## Play, pause, stop

```ts
await player.play();
await player.pause();
await player.togglePlayback();
await player.stop();
```

`togglePlayback()` pauses while the player is playing and plays otherwise.

`stop()` moves the player to its stopped phase, pauses the element and winds it back to 0.
Reach for it when the now-playing view goes away, and for `pause()` when the position has to survive.

**Only `play()` waits for the audio backend.**
It awaits the backend's own `play()` and rejects when that rejects.
`pause()` and `stop()` set the state, emit their event, and hand the call to the backend without waiting on it.

## When the browser refuses

A browser blocks audio nobody asked for, and the refusal arrives inside `play()`.

The player sets the state to playing before the backend has answered, because that is what keeps a control bar responsive.
When the answer is a refusal it undoes all of it: the play state goes back to paused, the phase change is reversed, `str playPrevented` is emitted with reason `str backend-refused`, and the error is rethrown.

**The rethrow is the part that bites.**
A `play()` nobody awaits becomes an unhandled rejection in the console.

```ts
player.on('playPrevented', ({ reason }) => {
  if (reason === 'backend-refused') showTapToPlay();
});

try {
  await player.play();
} catch {
  // Already reported through playPrevented.
}
```

The event also carries `key cause`, which is the error the backend threw.

**A listener can refuse too.**
`str beforePlay` is cancellable, and a listener calling `preventDefault()` emits that same `str playPrevented` with reason `str listener-prevented`.
Nothing changes state on that path and `play()` returns normally, so `key reason` is what tells the two apart.

`pause()` and `stop()` have the matching `str pausePrevented` and `str stopPrevented`.
Neither can be refused by the backend, because neither waits for it.

## Seeking

Seeking is `time()` with a number, in seconds.

```ts
await player.time(90);
```

It returns a promise, so awaiting it is how you know the seek finished rather than started.

| Call | Where it lands |
| --- | --- |
| `time(90)` | Ninety seconds in. A negative number lands at 0. |
| `rewind()` / `forward()` | Five seconds either way, or the seconds you pass. |
| `seekByPercentage(50)` | Halfway. It does nothing while the duration is still 0. |
| `restart()` | The start, and then it plays. |

`rewind()` stops at 0.
`forward()` has no limit of its own, so a backend that will not seek past the end snaps there instead.
`time()` carries the number you asked for until the next tick reads the element back.

`seekByPercentage()` is the one that hands back nothing to await.
It is built for a scrubber, where the next drag is more interesting than the last one landing.

Every seek runs the cancellable `str beforeSeek` cycle, and a listener that stops one gets `str seekPrevented` instead.
A prevented `restart()` skips its `play()` as well, because restart is one intent rather than a seek followed by a play.

## Before setup and after dispose

Each call here checks the player first.
Before `setup()` it throws `str core:player/not-ready`, and after `dispose()` it throws `str core:player/disposed`.

Reading `time()` with no argument skips that check.
A progress bar still polling after teardown gets the last position back rather than a throw.
