# Crossfade

Moving between tracks without a gap, or with a real overlap instead of a hard cut, is the one job that is genuinely specific to listening. `crossfadeTo(item, opts)` is `nomercy-music-player`'s own method. The kit does not provide it.

## crossfadeTo()

Call it with any queue item to fade the current track out while the target fades in, over a configurable duration:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-music-player';

const player = nmplayer('player');

const upNext = player.peekNext();
if (upNext) {
  await player.crossfadeTo(upNext, { duration: 4, curve: 'equal-power' });
}
```

Internally, `crossfadeTo()` runs a sequence of steps:

- Loads the target into a second audio element (on `WebAudioBackend`, a second Web Audio node graph).
- Primes the target.
- Ramps both gains over the window.
- Swaps the target in as primary and advances the queue cursor.

That advance fires the same `item` event a normal `next()` does.

`isTransitioning()` reports `true` while a fade is in flight. A second `crossfadeTo()` during that window is ignored rather than stacked.

`opts.duration` falls back to `crossfadeDefaults.duration` on the config, then to 5 seconds.

`opts.curve` picks between two values:

| Curve | Behavior |
| --- | --- |
| `'linear'` | The default for a manual `crossfadeTo()`. |
| `'equal-power'` | Perceptually smoother, with no volume dip at the midpoint. |

It resolves per call first, then from `crossfadeDefaults.curve`.

The automatic track-boundary fade, run by `CrossfadeTransitionStrategy`, uses equal-power on its own.

`opts.startAt` seeks the incoming track to a start position in milliseconds before the fade begins.

## The event sequence

```ts
player.on('beforeCrossfade', (e) => {
  // e.data: { from, to, duration } — call e.preventDefault() to cancel
});
player.on('crossfadeStart', ({ from, to, duration }) => { /* ... */ });
player.on('crossfadeComplete', ({ item }) => { /* ... */ });
player.on('crossfadePrevented', ({ reason }) => { /* ... */ });
```

`beforeCrossfade` is cancellable the same way every other `before*` event is. When a listener calls `preventDefault()`, no buffers are touched and `from` keeps playing. `crossfadePrevented` fires instead of `crossfadeStart`.

## Automatic crossfade between queue items

Manually calling `crossfadeTo()` is one use of crossfade. The other is automatic. `setup()` defaults `crossfadeEnabled: true` for music, so the queue's own track-boundary transition already overlaps instead of cutting. `crossfadeLeadSeconds` and `crossfadeTailSeconds` (both default `3`) control that window:

```ts
player.setup({
  baseUrl,
  playlist: tracks,
  crossfadeLeadSeconds: 5,
  crossfadeTailSeconds: 5,
  crossfadeDefaults: { duration: 5, curve: 'equal-power' },
});
```

That automatic behavior is `CrossfadeTransitionStrategy`, a medium-neutral kit primitive. This page does not reimplement it. See [Adapter: Transition Strategy](/nomercy-player-core/plugins-adapters/adapter-transition-strategy) for the full mechanism. `crossfadeTo()` above is the explicit, on-demand version of the same idea.

## Backend precision

The two backends drive the fade differently:

| Backend | How it drives the fade |
| --- | --- |
| `AudioElementBackend` (default) | Uses a `requestAnimationFrame` loop. Not sample-accurate, so expect sub-frame-length seams at track boundaries. |
| `WebAudioBackend` | Routes through a real `AudioContext` graph for a sample-accurate ramp. |

Switch to it with:

```ts
await player.backend('webaudio');
```
