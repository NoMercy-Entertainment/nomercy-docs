# Crossfade

`crossfadeTo` moves the player to another track by fading between the two rather than cutting.

You call it at a moment only your application knows about: a listener pressing next, or your own logic deciding what follows.

:::snippet{file="music-tour-crossfade"}
:::

Press play, then press the crossfade button.

**You should hear the playing track fade down as the next one comes up**, over the four seconds this config sets.

When the fade finishes the player's current item is the new track, so nothing else has to move the cursor.

## How long it lasts

Three places set the length, and the first one present wins.

| Where | Unit |
| --- | --- |
| The `duration` you pass to `crossfadeTo` | Seconds |
| `crossfadeDefaults.duration` in your config | Seconds |
| The built-in fallback of `5` | Seconds |

**Pass the whole options object or none of it.**
`duration` is required inside it, so `crossfadeTo(next)` compiles and `crossfadeTo(next, { curve: 'linear' })` does not.

Setting `crossfadeDefaults` once is what lets every call site stay bare.

## The shape of the fade

`linear` is what you get when you name no curve at all.
Both tracks move at a constant rate, so the combined loudness dips through the middle of the join.

`equal-power` is the one to ask for.
It holds the combined loudness steady, which is what removes that dip.

Name it on the call or once in `crossfadeDefaults`, as the example above does.

## Starting the incoming track partway in

`startAt` skips into the track you are fading to.

**It is in milliseconds, and so is the `duration` on the `crossfadeStart` event.**
The crossfade fields in the table above are in seconds, so this is the boundary to watch.

## What can go wrong

Three failures throw rather than fading.

An item with no `url` throws `core:media/missing-url`, because there is nothing to fade into.

A backend reporting no crossfade support throws `core:player/crossfade-unsupported`.
Both shipped backends support it, so this only happens behind a backend of your own.

A source that will not load rejects too, and it does so after `crossfadeStart` has already fired.
A listener watching that event will see a fade announced that never happens.

A call made while a fade is already running returns without doing anything, so a listener leaning on the button cannot stack them.
