# Music Player: Quick Start

This gets a real song playing in the preview below: "Where Dreams Drift" by Ketsa, streamed from the `nomercy-media` fixture catalogue. It uses the baseUrl pattern every NoMercy player and app is built around.

## Install

```bash
npm install @nomercy-entertainment/nomercy-music-player
```

That's the only package you need. `nomercy-player-core` is a regular dependency of `nomercy-music-player`. npm installs it for you, so there is no peer dependency to add by hand.

## Play your first song

Here it is loaded for real: an MP3 streamed from `baseUrl`, through the native `<audio>` controls that `controls: true` mounts. Press play in the bar to start it. Below the player is the exact code that produced it, ready to copy:

:::snippet{file="music-quickstart" runnable preview="first"}
:::

The player is headless. It mounts a plain `<audio>` element into your container, and `controls: true` gives it the browser's own control bar. `item(0)` loads the first track so those controls have something to play.

Add the container and style it however your app needs. Here it sits as a full-width bar along the bottom:

```html
<div id="player"></div>
```

```css
#player audio {
  position: fixed;
  inset: auto 0 0 0;
  width: 100%;
}
```

## The baseUrl pattern

`baseUrl` is the one config field every playlist should set. Item paths (`url` above) stay relative, exactly the shape a real media server sends. The player prepends `baseUrl` as a plain string prefix and keeps the whole base path:

- The server sends the base with no trailing slash (`.../master/Music`) and each item path with a leading slash (`/K/Ketsa/...`).
- Move to a different server, a different environment, or a signed-URL CDN, and you change one config value; nothing in your catalogue is hardcoded to today's origin.
- Never pre-join an absolute URL into an item yourself. That is the player's job, and doing it twice breaks the moment the base changes.
