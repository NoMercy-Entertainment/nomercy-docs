# Adapter: Similarity Engine

`cls ISimilarityEngine` is the port for "find items similar to this seed".

It is there for a future radio mode or "more like this", and for [`cls SmartShuffleGenerator`](/nomercy-music-player/plugins-adapters/auto-advance) when its local genre and decade scoring is not enough.

The contract ships and is importable. What does not ship is an implementation behind it, or a caller for one.

## What ships, and what does not

The type is published on two paths, and both resolve against the installed package:

```ts
import type { ISimilarityEngine, SimilarityQueryOptions } from '@nomercy-entertainment/nomercy-music-player/adapters/similarity-engine';
```

`@nomercy-entertainment/nomercy-music-player/adapters` re-exports the same two names beside the audio-backend types, so either path gives you the shape to implement against.

Nothing else is there yet:

- No default adapter ships. [Audio Backend](/nomercy-music-player/plugins-adapters/adapter-audio-backend) always has `cls AudioElementBackend` behind it; this port has no `cls NoopSimilarityEngine` counterpart.
- No plugin in this package calls `fn findSimilar`. `cls AutoAdvancePlugin`'s `cls SmartShuffleGenerator` scores genre and decade locally and never touches this interface. See [Plugin: Auto-Advance](/nomercy-music-player/plugins-adapters/auto-advance).
- There is no config field or `fn addPlugin` option that accepts one. An implementation you write today is yours to call from your own code.

## The interface, for reference

```ts
interface ISimilarityEngine<T extends BasePlaylistItem = BasePlaylistItem> {
  readonly id: string;
  findSimilar(seed: T, opts?: SimilarityQueryOptions): Promise<T[]>;
}

interface SimilarityQueryOptions {
  limit?: number;                          // max results, implementation-defined default
  excludeIds?: ReadonlyArray<string | number>; // exclude items already in the queue
  minScore?: number;                       // minimum similarity score, implementation-defined scale [0, 1]
}
```

`fn findSimilar` returns results ordered by descending similarity, most similar first.

The scale behind `key minScore` is deliberately implementation-defined. A tag-based engine and an ML-embedding engine don't score similarity on comparable numbers. Treat the score as relative within one engine, not as a portable threshold across implementations.

## Where the data would come from

An implementation of this shape is normally backed by one of:

- **Server-driven**, the NoMercy media server's own recommendation endpoint.
- **Audio-feature-based**, BPM / key / energy similarity computed from the audio itself.
- **Tag-based**, genre / decade / mood overlap, a generalized version of what `cls SmartShuffleGenerator` already does locally.
- **ML embedding**, vector proximity over a precomputed embedding space.
- **External service**, Last.fm similar-tracks, or an equivalent third-party API.
