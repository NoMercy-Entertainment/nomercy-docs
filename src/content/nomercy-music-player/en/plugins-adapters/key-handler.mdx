# Plugin: Key Handler

`KeyHandlerPlugin` (id `'key-handler'`) is `nomercy-music-player`'s keyboard-binding set, a thin subclass of the kit's [`KeyHandlerPlugin`](/nomercy-player-core/plugins-adapters/key-handler) (scope resolution, cooldown, input-field awareness, `bind`/`unbind`/`replace`). It inherits every kit default unchanged and overrides only `addMediaKeys()` to add four listening-specific bindings.

## Options

Same `KeyHandlerOptions` the kit plugin accepts, `scope`, `bindings`, `extend`, `when`, `cooldownMs`, `disableMediaControls`, see [Plugin: Key Handler (core)](/nomercy-player-core/plugins-adapters/key-handler) for the full table. This subclass adds no new option fields.

## Bindings

Inherited from the kit unchanged: `Space` (toggle playback), arrow keys (seek / volume), `m` (toggle mute), and the hardware `MediaX` keys. Added by this subclass:

| Keys | Action |
|---|---|
| `n` | Next item. |
| `p` | Previous item. |
| `r` | Cycle repeat state: off → all → one → off. |
| `s` | Toggle shuffle on/off. |

## Rules & restrictions

- `addMediaKeys()` calls `super.addMediaKeys()` first, then adds the four bindings above, overriding it in a further subclass without calling `super` drops the kit's own media-key bindings too, not just these four.
- `r` and `s` call `repeatState()` / `shuffleState()` directly, they reflect and mutate the same state a UI-driven repeat/shuffle button would, there's no separate "key handler state" to keep in sync.

## How to extend it

```ts
import nmplayer from '@nomercy-entertainment/nomercy-music-player';
import { KeyHandlerPlugin } from '@nomercy-entertainment/nomercy-music-player/plugins/key-handler';

const player = nmplayer('player');

class MyKeyHandler extends KeyHandlerPlugin {
  protected override addMediaKeys(): void {
    super.addMediaKeys(); // keep n/p/r/s and the kit defaults
    this.bind('l', () => { void this.player.forward(15); }); // custom 15s skip
  }
}

player.addPlugin(MyKeyHandler);
```
