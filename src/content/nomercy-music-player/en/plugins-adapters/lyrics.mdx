# Plugin: Lyrics

`cls LyricsPlugin` (id `str lyrics`) wires a track's synced lyrics to the kit's generic cue machinery.

On every `item` change, the plugin runs its pipeline:

1. Resolves a lyrics URL.
2. Fetches it through the auth-aware fetch.
3. Parses it with the parser `fn resolveCueParser` hands back for that URL.
4. Attaches a `cls CueTracker` that fires as playback crosses each line's window.

[Lyrics](/nomercy-music-player/tour/lyrics) is the walkthrough. [Recipe: Synced Lyrics UI](/nomercy-music-player/recipes/lyrics-sync) builds a scrolling panel.

## Options

| Option | Type | Default | Purpose |
|---|---|---|---|
| `key getLyricsUrl` | `ts (item: MusicPlaylistItem) => string | undefined` | reads `key lyricsUrl` off the item | Custom resolver, for a catalog that derives the lyrics URL rather than storing it on the item. |
| `key autoFetch` | `ts boolean` | `ts true` | Fetch on the `str item` event. `ts false` still clears the previous track's lines and leaves the fetching to `fn fetchLyrics`. |

## Events

The plugin's own events reach the player bus under a `str plugin:lyrics:` prefix, which is the name a listener has to spell out:

```ts
player.on('plugin:lyrics:lineEnter', (line: { text: string }) => {
  console.log(line.text);
});
```

Every line payload carries `key text` and whatever else the parser put on that cue, which for enhanced LRC is a `key words` array of per-word timings.

| Event | Payload | Fires when |
|---|---|---|
| `str plugin:lyrics:loaded` | `key count`, the number of lines | The cue list is fetched, parsed, and the tracker is attached. |
| `str plugin:lyrics:line` | the line payload | A line's window starts. Same payload and instant as `str plugin:lyrics:lineEnter`, for a listener that does not need the enter and exit split. |
| `str plugin:lyrics:lineEnter` | the line payload | A line's window starts. |
| `str plugin:lyrics:lineExit` | the line payload | A line's window ends. |

## Methods

| Method | Answers | Purpose |
|---|---|---|
| `fn current` | the active line's payload, or `ts undefined` | What to show right now. It is `ts undefined` in the gap between two lines. |
| `fn all` | every parsed cue for the current track | The whole sheet, for a panel that scrolls. Empty when nothing is loaded. |
| `fn clear` | nothing | Tear down the active tracker without disposing the plugin. |
| `fn fetchLyrics` | the parsed cue list, or `ts undefined` | Load a URL yourself. It resolves once the tracker is attached, and answers `ts undefined` when the fetch or the parser lookup failed. |

## Rules & restrictions

- `key lyricsUrl` is fetched exactly as given. It is not resolved against `key baseUrl` the way `key url` is. Store a fully-qualified URL, or build one in a `key getLyricsUrl` resolver. See [Lyrics: lyricsUrl isn't resolved against baseUrl](/nomercy-music-player/tour/lyrics#lyricsurl-isnt-resolved-against-baseurl).
- A track with no `key lyricsUrl`, and no resolver answering for it, clears the previous track's lines and stops there. No fetch, no error.

- A failed fetch, and a URL no registered parser claims, both go to the plugin's error channel as `str plugin:lyrics/fetch-failed` and `str plugin:lyrics/no-parser`. Neither throws, and playback carries on.
- A parser that throws on the file it claimed is a different case: `fn parse` runs outside that guard, so the rejection reaches whoever called `fn fetchLyrics`, and an auto-fetch surfaces it as an unhandled rejection. A parser you register yourself answers `ts false` from `fn canParse` for a file it cannot read.
- Parsing needs a cue parser registered for that URL's format. A `.lrc` file reaches the built-in parser. A format of your own needs its own `cls ICueParser` registered first, through `fn registerCueParser`. See [Core: Cue Parsers](/nomercy-player-core/tour/cue-parsers).
- Add it before `fn setup`, like any plugin, so its `str item` listener is wired before the first track primes.

- Added after `fn ready`, the listener attaches too late for the track already mounted, so lyrics start at the next `str item` change or at an explicit `fn fetchLyrics` call.

## How to extend it

`cls LyricsPlugin` is configured rather than subclassed. `key getLyricsUrl` routes to a different sidecar location or format, and a format the kit does not read joins it as a cue parser of your own:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-music-player';
import { LyricsPlugin } from '@nomercy-entertainment/nomercy-music-player/plugins/lyrics';

const MUSIC_BASE = 'https://raw.githubusercontent.com/NoMercy-Entertainment/nomercy-media/master/Music';

const player = nmplayer('player');
player.addPlugin(LyricsPlugin, {
  // The lyrics URL is never resolved against baseUrl, so build the whole thing here.
  getLyricsUrl: item =>
    item.lyricsUrl ?? (item.url ? `${MUSIC_BASE}${item.url.replace(/\.mp3$/u, '.lrc')}` : undefined),
});
player.setup({
  baseUrl: MUSIC_BASE,
  playlist: [
    {
      id: 'ketsa-01-where-dreams-drift',
      name: 'Where Dreams Drift',
      artist: 'Ketsa',
      url: '/K/Ketsa/CC.BY.FREE.TO.USE.FOR.ANYTHING.(2025)/01.Where.Dreams.Drift.mp3',
      lyricsUrl:
        'https://raw.githubusercontent.com/NoMercy-Entertainment/nomercy-media/master/Music/K/Ketsa/CC.BY.FREE.TO.USE.FOR.ANYTHING.(2025)/01.Where.Dreams.Drift.lrc',
    },
  ],
});
```
