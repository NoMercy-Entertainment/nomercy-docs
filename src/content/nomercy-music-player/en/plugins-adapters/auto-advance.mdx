# Auto Advance

Reach for `AutoAdvancePlugin` when you want a queue that keeps playing. It listens for a track ending and moves to the next one. Without it the player stops at the end of every track and waits for your own code to call `player.next()`.

It also does the two things that have to happen slightly before a track ends: loading the next track early, and crossfading.

Crossfading overlaps the end of one track with the start of the next instead of cutting between them. Both are off by default, because both cost bandwidth a listener may not want spent.

```ts
import { AutoAdvancePlugin } from '@nomercy-entertainment/nomercy-music-player/plugins/auto-advance';

player.addPlugin(AutoAdvancePlugin);
```

Register it before `setup()`, like any plugin.

**You should now hear the queue run on its own:** let a track reach its end and the next one starts, with no call from you.

If a track skips two forward instead of one, something else is advancing the queue as well. An app driving playback from a websocket or a Cast sync layer already has an authority deciding what plays next, and this plugin is a second one. Pick whichever suits, and register this plugin only when it is the one in charge.

## Options

Every option is optional, and the defaults give you plain sequential playback.

| Option | Type | Default | What it does |
| --- | --- | --- | --- |
| `enabled` | `boolean` | `true` | Master switch. `false` leaves the plugin registered and inert. |
| `preloadNextOnEnding` | `boolean` | `false` | Fetches the next track early, so it is already buffered when the current one ends. |
| `crossfade` | `boolean` | `false` | Overlaps the two tracks instead of cutting between them. |
| `crossfadeDuration` | `number` | `0` | Seconds of overlap. At `0` the change is a hard cut rather than a fade. |
| `generator` | `IPlaylistGenerator` | the queue's own order | An object that decides which track is next. Covered below. |

**Turning `crossfade` on without also setting a duration cuts every track short.** The handoff runs when the player emits `itemEndingSoon`, and at a duration of `0` there is no fade to fill the gap, so the tail of every track is dropped.

Set the two together, with the duration matching how early that event fires:

```ts
player.addPlugin(AutoAdvancePlugin, {
  crossfade: true,
  crossfadeDuration: 10,
});
```

Ten seconds is the default lead. It is `itemEndingSoonThreshold` on the player config, in seconds, and moving it there means moving the duration here to match.

## Choosing what plays next

Without a generator, the plugin walks the queue in the order you supplied it. That is the default, and it is what most applications want.

A generator replaces that decision. Two ship with the plugin, and both come from the same import subpath.

### SmartShuffleGenerator

Shuffles, but avoids putting two similar tracks back to back.

```ts
import { SmartShuffleGenerator } from '@nomercy-entertainment/nomercy-music-player/plugins/auto-advance';

player.addPlugin(AutoAdvancePlugin, {
  generator: new SmartShuffleGenerator(),
});
```

**You should now hear the queue play out of order**, with the same artist's tracks spread apart rather than clustered.

It reads two optional fields on each item, `genre` and `decade`.

A candidate earns one penalty point for sharing a genre with the track just played, and another for sharing a decade. The score is the negated penalty plus a random value up to `0.5`.

The next track is then drawn at random from everything within `0.1` of the best score.

That random component is what stops it being deterministic. With no tags anywhere in the queue every candidate scores the same way, and the result is an ordinary uniform shuffle.

**Items carrying no `genre` and no `decade` cannot be told apart.** Neither field is part of the music playlist item type, so both arrive as extra fields of your own, and a queue without them shuffles plainly rather than smartly.

### LinearPlaylistGenerator

Plays the queue in order, for code that picks a strategy at runtime and wants the slot filled explicitly.

**It is not the same as passing no generator.** With no generator the plugin calls the player's own `next()`, which honours the repeat setting and announces the move as a `next` event, or as `queue:exhausted` when there was nothing left to play.

Any generator, this one included, is routed through `player.item()` instead. That emits `current` and neither of the other two, and it does not consult the repeat setting.

The symptom is repeat-one quietly advancing to the following track once a generator is set, and a queue that ends without your `queue:exhausted` handler ever firing.

### Writing your own

A generator is an object with an id and two methods. Each receives the queue and the current position, and returns an index.

```ts
import type { MusicPlaylistItem } from '@nomercy-entertainment/nomercy-music-player';
import type { IPlaylistGenerator } from '@nomercy-entertainment/nomercy-music-player/plugins/auto-advance';

// A radio mode: never play the same artist twice in a row.
const neverRepeatArtist: IPlaylistGenerator<MusicPlaylistItem> = {
  id: 'never-repeat-artist',

  next(items, currentIndex) {
    const current = items[currentIndex];
    const index = items.findIndex((item, i) => i > currentIndex && item.artist !== current?.artist);

    return index === -1 ? undefined : index;
  },

  previous(items, currentIndex) {
    return currentIndex > 0 ? currentIndex - 1 : undefined;
  },
};

player.addPlugin(AutoAdvancePlugin, {
  generator: neverRepeatArtist,
});
```

**You should now hear the queue skip any track whose artist just played**, and stop when it runs out of anything else to play.

`currentIndex` is `-1` only while the queue is empty. A queue that is loaded but not yet started reports `0`, so treat `-1` as "nothing to choose from" rather than "not started".

**Returning `undefined` means the end of the queue, and the player stops there.** A generator that runs out of candidates and returns `-1` instead would send playback to the last track, so return `undefined` rather than an out-of-range index.
