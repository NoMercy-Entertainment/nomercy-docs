# Plugin: Auto-Advance

`AutoAdvancePlugin` (id `'auto-advance'`) listens to the player's `ended` event to move to the next item, and `itemEndingSoon` to optionally preload it ahead of time or crossfade into it. Don't register this plugin if an external orchestrator, a Cast sync layer, a WebSocket-driven listening session, already drives `next()` itself, the two would double-advance.

## Options

| Option | Type | Default | Purpose |
|---|---|---|---|
| `enabled` | `boolean` | `true` | Master toggle, both `ended` and `itemEndingSoon` handling. |
| `preloadNextOnEnding` | `boolean` | `false` | On `itemEndingSoon`, peek the queue and `load()` the next item into the next slot. |
| `crossfade` | `boolean` | `false` | On `itemEndingSoon`, hand off to `player.crossfadeTo()`. |
| `crossfadeDuration` | `number` | `0` | Duration passed to `crossfadeTo()` when `crossfade` is enabled. `0` is a hard cut. |
| `generator` | `IPlaylistGenerator<MusicPlaylistItem>` | — | Custom "what's next?" ordering. Omitted, the plugin falls back to the player's own linear `next()` / `peekNext()`, so adding the plugin without a generator doesn't change observable ordering. |

## The IPlaylistGenerator port

```ts
interface IPlaylistGenerator<T extends BasePlaylistItem = BasePlaylistItem> {
  readonly id: string;
  next(items: ReadonlyArray<T>, currentIndex: number): number | undefined;
  previous(items: ReadonlyArray<T>, currentIndex: number): number | undefined;
}
```

Two built-in implementations ship:

| Generator | Behavior |
|---|---|
| `LinearPlaylistGenerator` | Sequential order, `currentIndex + 1` / `currentIndex - 1`. This is the implicit default, `AutoAdvancePlugin` without `opts.generator` behaves identically via the player's own `next()`. |
| `SmartShuffleGenerator` | Tag-aware shuffle. Scores candidates by penalizing items sharing the current item's `genre` or `decade` field, picks randomly from the top-scored pool, falls back to uniform random when items carry no tag fields. `previous()` pops from its own played-index history when available. |

Both read a minimal item shape (`genre?: string | string[]`, `decade?: number | string` for the shuffle variant), your own `MusicPlaylistItem` extension satisfies it automatically if it already carries those fields.

## Methods

| Method | Signature | Behavior |
|---|---|---|
| `advance()` | `() => Promise<void>` | Force-advance immediately, regardless of `ended` state. Uses `opts.generator` when configured, otherwise `player.next()`. |
| `preloadNext()` | `() => Promise<void>` | Peek the queue head (or the generator's pick) and `load()` it into the next slot. No-op with nothing next. |
| `addEndedHandler(fn)` | `(fn: () => void \| Promise<void>) => void` | Register an additional handler that runs after the built-in advance on `ended`. |
| `addPreloadHandler(fn)` | `(fn: (next) => void \| Promise<void>) => void` | Register an additional handler for the preload path on `itemEndingSoon`. |
| `addCrossfadeHandler(fn)` | `(fn: (next, duration) => void \| Promise<void>) => void` | Register an additional handler for the crossfade path on `itemEndingSoon`. |

## Rules & restrictions

- With a custom `generator`, advancing calls `player.item(next, { source: 'auto-advance' })` directly rather than `player.next()`, since the generator's ordering may not match the queue's own linear order. Without one, it's a plain `player.next({ source: 'auto-advance' })`.
- `crossfade: true` with no `next` item resolved (end of a non-repeating queue) simply does nothing, no error, no empty crossfade attempt.
- Errors from `advance()`, `preloadNext()`, or a registered handler are caught and logged through the plugin's logger, one bad handler doesn't stop the others from running or break the natural `ended` → advance flow.

## How to extend it

Provide a generator for radio-style or recommendation-driven ordering instead of writing queue-management code against `ended` yourself:

```ts
import { AutoAdvancePlugin, SmartShuffleGenerator } from '@nomercy-entertainment/nomercy-music-player/plugins/auto-advance';

player.addPlugin(AutoAdvancePlugin, {
  generator: new SmartShuffleGenerator(),
  preloadNextOnEnding: true,
  crossfade: true,
  crossfadeDuration: 4,
});
player.setup({ baseUrl, playlist });
```

A server-driven "radio" feature implements `IPlaylistGenerator` against a recommendation endpoint instead of scoring local tag fields, the interface doesn't require the candidates to already be in the queue, `next()` can return an index the generator itself decided to reorder toward.
