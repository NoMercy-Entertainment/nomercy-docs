# Adapter: Audio Backend

`cls IAudioBackend` is the one port every music-specific player method reads and writes through: `fn play`, `fn time`, `fn crossfadeTo`, `fn audioOutput`, and the rest. `cls NMMusicPlayer` itself never touches an `<audio>` element or the Web Audio API directly.

Two implementations ship: `cls AudioElementBackend` (the default) and `cls WebAudioBackend`. This is the swap point for a custom backend: WebCodecs, a native-shell `<audio>` bridge, or a test double.

## The interface

```ts
interface IAudioBackend {
	readonly kind: AudioBackendKind; // 'audio-element' | 'webaudio'

	load(url: string, opts?: { preload: 'auto' | 'metadata' | 'none' }): Promise<void>;
	unload(): void;
	dispose(): void;
	setAuthHeaderProvider?(provider: () => string | undefined | Promise<string | undefined>): void;

	play(): Promise<void>;
	pause(): void;
	stop(): void;

	currentTime(): number;
	currentTime(seconds: number): void;
	duration(): number;
	buffered(): number;
	bufferedRanges(): TimeRanges;
	seekable(): TimeRanges;
	playbackRate(): number;
	playbackRate(rate: number): void;

	volume(): number;
	volume(level: number): void;
	mute(): void;
	unmute(): void;

	state(): BackendState;
	outputNode(ctx: AudioContext): AudioNode;
	analyserSource(ctx: AudioContext): AudioNode;
	analysisNode?(ctx: AudioContext): AudioNode;
	audioContext?(): AudioContext;

	mediaElement(): HTMLMediaElement;
	captureStream(): MediaStream;

	setSinkId(deviceId: string): Promise<void>;
	getSinkId(): string;

	mediaKeys(): MediaKeys | undefined;
	setMediaKeys(keys: MediaKeys): Promise<void>;
	outputProtectionState(): 'unrestricted' | 'restricted' | 'unsupported';

	pauseLoader(): void;
	resumeLoader(): void;
	loaderState(): BackendLoaderState;

	on<E extends BackendEvent>(event: E, fn: (data?: BackendEventPayload[E]) => void): void;
	off<E extends BackendEvent>(event: E, fn: (data?: BackendEventPayload[E]) => void): void;

	// Crossfade
	supportsCrossfade(): boolean;
	loadSecondary(url: string): Promise<void>;
	disposeSecondary(): void;
	primeSecondary(seekMs?: number): Promise<void>;
	crossfade(durationMs: number, curve?: CrossfadeCurve): Promise<void>;
	secondaryGain(): number;
	secondaryGain(value: number): void;
}
```

Method conventions mirror the player class itself:

- Stateful values are overloaded functions: `fn volume` reads, `fn volume` with a level writes.
- Actions are bare verbs (`fn play`, `fn pause`, `fn mute`).
- Seeking goes through `fn currentTime`. There is no separate `fn seek` method at this layer either.

## The two shipped implementations

| Backend | `key kind` | Signal path | Use for |
|---|---|---|---|
| `cls AudioElementBackend` | `str audio-element` | Plain `cls HTMLAudioElement`. Lazily creates a `cls MediaElementAudioSourceNode` only the first time a plugin requests the analyser graph, so a consumer without an equalizer or spectrum plugin pays zero Web Audio cost. | The default, the safe fallback for environments where Web Audio is restricted or undesired. |
| `cls WebAudioBackend` | `str webaudio` | `<audio>` → `cls MediaElementAudioSourceNode` → `cls AnalyserNode` → destination, routed through a real `cls AudioContext`. When `cls AudioContext` is unavailable, it throws `cls BrowserPolicyError` immediately at construction. It never silently degrades to a no-op graph. | Sample-accurate crossfades, or when a plugin needs full Web Audio graph access. |

Pick one at `fn setup` with `key backend`, or swap at runtime:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-music-player';

const player = nmplayer('player');

player.setup({ backend: 'webaudio', playlist: [] });
await player.ready();

// Later, on the same player:
await player.backend('audio-element');
```

**`player.backend().kind` now reads back the one you asked for.** The swap is asynchronous, so await it before reading.

Both back the identical `cls IAudioBackend` surface, so every player-level method, `fn crossfadeTo` included, reads the same either way.

## Crossfade: the dual-buffer contract

`fn crossfadeTo` on the player delegates the dual-buffer work to whichever backend is active. Three calls do it:

- `fn loadSecondary` allocates and loads a second playback handle, without touching primary playback.
- `fn primeSecondary` pre-rolls it to a start position and waits for it to be ready.
- `fn crossfade` ramps both gains over the window, then swaps the secondary in as primary and disposes the old one. The curve is linear by default, constant-power with `str equal-power`.

`fn secondaryGain` reads and writes the incoming handle's gain, for a test or a caller inspecting the middle of a fade.

Precision differs by backend.

`cls AudioElementBackend` drives the fade with a `requestAnimationFrame` loop. That is not sample-accurate, so expect a sub-frame seam at track boundaries.

`cls WebAudioBackend` ramps through real `cls AudioParam` automation, which is sample-accurate. It allocates a fresh `<audio>` element and `cls MediaElementAudioSourceNode` pair per crossfade, because `fn createMediaElementSource` binds an element to a context permanently and the same element cannot be reattached.

`fn supportsCrossfade` reports whether a backend can allocate a second playback handle at all. Both built-in backends return `ts true`. When a custom backend returns `ts false`, `fn crossfadeTo` throws a `cls StateError` (a `cls PlayerError` subclass) with code `str core:player/crossfade-unsupported`. The throw happens before any crossfade event fires or any buffer is touched. The player never attempts the transition.

## Auth on manifest and segment requests

On an HLS audio stream, hls.js makes its own manifest and segment requests. `fn setAuthHeaderProvider` is how `Authorization: Bearer <token>` reaches those requests, not just the kit's `fn fetch` calls.

The player wires the provider onto every backend it builds, reading the `key auth` block of your setup config. It resolves the bearer value on each request rather than capturing it once, so a getter backed by a store stays live.

## Rules & restrictions

- `fn backend` builds the instance on the first call and keeps it. Make that first call after `fn ready` has resolved, so it is built from the config your `fn setup` passed. A backend built earlier is never rebuilt, and the `key backend`, `key backendFactory` and `key controls` fields of that config reach nothing.
- One backend is active per player at a time. Swapping mid-session disposes the previous one and emits `str backend:changed`.

- A swap is not a crossfade. Whatever was playing stops, and the new backend comes up with no source, so reload the current item to resume.
- `fn mediaKeys`, `fn setMediaKeys` and `fn outputProtectionState` exist for EME and DRM coordination on protected audio. A backend that never touches encrypted content implements them as no-ops.
- `fn outputNode` and `fn analysisNode` are the tap points the kit's `cls AudioGraphPlugin` chain needs for the equalizer, spectrum and visualizers. See [Equalizer](/nomercy-music-player/tour/equalizer). `fn analysisNode` is optional: a backend with no separate pre-volume source node omits it, and the plugin falls back to `fn outputNode`.

## How to extend it

Pass a `key backendFactory` to `fn setup`. It receives the resolved kind and the whole config, and answers any `cls IAudioBackend`:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-music-player';
import type { AudioBackendFactory } from '@nomercy-entertainment/nomercy-music-player';
import {
  AudioElementBackend,
  WebAudioBackend,
} from '@nomercy-entertainment/nomercy-music-player/adapters/audio-backend';

const player = nmplayer('player');

// Route every kind through a real backend, and log which one was built.
const backendFactory: AudioBackendFactory = kind => {
  console.log(`building the ${kind} backend`);

  if (kind === 'webaudio') return new WebAudioBackend(player.container);

  return new AudioElementBackend(player.container);
};

player.setup({
  baseUrl: 'https://raw.githubusercontent.com/NoMercy-Entertainment/nomercy-media/master/Music',
  playlist: [],
  backendFactory,
});
```

A backend implementing the whole contract, crossfade calls included, works with every player-level method unchanged. `fn crossfadeTo` never branches on which one is active.
