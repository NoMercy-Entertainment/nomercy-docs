# Plugin: Cast Sender

## Purpose

`cls CastSenderPlugin` (id `str cast-sender`) sends a track to a Chromecast receiver: session lifecycle, remote-state mirroring, and resume-on-disconnect. It is a two-method specialization of the kit's [`cls CastSenderPlugin`](/nomercy-player-core/plugins-adapters/cast-sender). This subclass supplies only the two things that differ per medium: the default MIME type, and how a `cls MusicPlaylistItem` becomes Cast metadata.

## Using it

```ts
import nmplayer from '@nomercy-entertainment/nomercy-music-player';
import { CastSenderPlugin } from '@nomercy-entertainment/nomercy-music-player/plugins/cast-sender';

const player = nmplayer('player');

player.addPlugin(CastSenderPlugin);
player.setup({
  baseUrl: 'https://raw.githubusercontent.com/NoMercy-Entertainment/nomercy-media/master/Music',
  playlist: [
    {
      id: 'ketsa-01-where-dreams-drift',
      name: 'Where Dreams Drift',
      artist: 'Ketsa',
      url: '/K/Ketsa/CC.BY.FREE.TO.USE.FOR.ANYTHING.(2025)/01.Where.Dreams.Drift.mp3',
    },
  ],
});
await player.ready();

await player.getPlugin(CastSenderPlugin)?.connect();
```

Register before `fn setup` and await `fn ready` before `fn connect`. `fn ready` never settles on a player that was never set up.

The receiver app id is not a plugin option. Set it on the Cast SDK's own `cls CastContext` before calling `fn connect`, which is where the core page's [rules](/nomercy-player-core/plugins-adapters/cast-sender) put it.

Subclass and override `fn buildMetadata` when your items carry fields beyond the canonical `cls MusicPlaylistItem`, such as a composer or a linked artist entity rather than a plain string. `fn buildMetadata` is declared as returning `ts unknown`, because the metadata class comes from whichever Cast SDK build the page loaded, so narrow it before you write to it:

```ts
import type { ChromeCastMediaCtors } from '@nomercy-entertainment/nomercy-player-core';
import type { MusicPlaylistItem } from '@nomercy-entertainment/nomercy-music-player';

interface StudioTrack extends MusicPlaylistItem {
  composer?: string;
}

class StudioCastSender extends CastSenderPlugin<StudioTrack> {
  protected override async buildMetadata(item: StudioTrack, ctors: ChromeCastMediaCtors) {
    const meta = (await super.buildMetadata(item, ctors)) as Record<string, unknown>;
    meta['composer'] = item.composer ?? '';
    return meta;
  }
}
```

## Reference

`fn defaultContentType` answers `str audio/mpeg` here.

`fn buildMetadata` reads a fixed list of fields off the item, and builds a `cls MusicTrackMediaMetadata`. When the loaded SDK build carries no music-track constructor it builds a `cls GenericMediaMetadata` instead, and fills the same fields.

| Item field | Metadata field |
|---|---|
| `key name` | `key title`, empty string when the field is absent |
| `key artist` | `key artist`, left off when the field is absent |
| `key album` | `key albumName`, left off when the field is absent |
| `key image`, falling back to `key cover` | `key images`, a single entry whose URL went through `fn resolveUrl` under the `str poster` category |

An item carrying fields outside that list needs your own override. Nothing else is read.

Options, events, browser restrictions, the volume conversion, and the `fn transferTo` boundary are unchanged from the kit. See [Plugin: Cast Sender (core)](/nomercy-player-core/plugins-adapters/cast-sender) for the full surface.

This subclass carries its own string bundle for every locale the package ships, loaded lazily through `fn translationsFromGlob`. The kit base carries English and Dutch eagerly. Both bundles end up in the table, because plugin registration walks the prototype chain, and a key this subclass defines wins.
