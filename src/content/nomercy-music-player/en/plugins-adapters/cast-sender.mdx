# Plugin: Cast Sender

`CastSenderPlugin` (id `'cast-sender'`) is a thin, two-method specialization of the kit's [`CastSenderPlugin`](/nomercy-player-core/plugins-adapters/cast-sender), which owns everything medium-agnostic: SDK probing, session lifecycle, `RemotePlayer` event mirroring, resume-on-disconnect. This subclass only supplies the two things that differ between video and music: the default MIME type, and how a `MusicPlaylistItem` becomes Cast metadata.

## Options

Same `CastSenderOptions` the kit plugin defines, `chromecastAppId`, `enableAirPlay`, `customReceiverNamespace`, `resumeLocalOnDisconnect`, `defaultContentType`, `live`, see [Plugin: Cast Sender (core)](/nomercy-player-core/plugins-adapters/cast-sender) for the full table. `defaultContentType` defaults to `'audio/mpeg'` here unless you override it explicitly.

## Events

Same `CastSenderEvents` as the base: `cast:connected`, `cast:disconnected`, `cast:error`, `cast:remote-state`, `cast:media-changed`, `unsupported`.

## What the music subclass builds

`buildMetadata(item, ctors)` reads only fields already on the canonical `MusicPlaylistItem`, building a `MusicTrackMediaMetadata` (falling back to `GenericMediaMetadata` if the SDK build lacks the music-track constructor):

| Item field | Metadata field |
|---|---|
| `item.name` | `title` |
| `item.artist` (if set) | `artist` |
| `item.album` (if set) | `albumName` |
| `item.cover` (if set) | Resolved through `resolveUrl(item.cover, 'poster')` (auth-aware, respects `baseImageUrl`) and set as `images`. |

## Translations

Cast Sender's UI strings (connect/disconnect prompts, error copy) are auto-discovered from this plugin's own `./i18n/*.ts` folder via `translationsFromGlob`, on top of the kit base's own translation bundle. Each plugin in the chain ships only its own keys, the kit's plugin registration walks the prototype chain so both bundles end up in the translation table, see [Core: i18n](/nomercy-player-core/tour/i18n).

## Rules & restrictions

- All the base plugin's restrictions apply unchanged: Chrome/Chromium Web Sender SDK only, requires `cast.framework` / `chrome.cast.media` already loaded on the page, volume forwarded on the SDK's native 0-100 scale.
- Consumers carrying application-specific fields beyond the canonical `MusicPlaylistItem` (linked artist/album entities instead of plain strings, for instance) should subclass this plugin and override `buildMetadata()` themselves rather than expecting it to read fields it was never typed against.

## How to extend it

```ts
import { CastSenderPlugin } from '@nomercy-entertainment/nomercy-music-player';

class MyCastSenderPlugin extends CastSenderPlugin {
  protected override async buildMetadata(item, ctors) {
    const meta = await super.buildMetadata(item, ctors);
    // add app-specific fields on top of the canonical set super() already built
    return meta;
  }
}

player.addPlugin(MyCastSenderPlugin, { chromecastAppId: 'ABCD1234' });
await player.ready();
await player.getPlugin(MyCastSenderPlugin)?.connect();
```
