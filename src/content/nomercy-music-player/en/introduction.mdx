# What is nomercy-music-player

`nomercy-music-player` is a headless audio engine. It ships no chrome.

You get the audio transport and a typed surface to drive it. Everything on screen is code you write, or a plugin you add.

What it handles for you:

- Gapless queue playback
- Crossfade between tracks
- A swappable audio backend: a plain `<audio>` element, or a full Web Audio graph
- Synced lyrics
- A plugin system

It is built on [`nomercy-player-core`](/nomercy-player-core), which carries lifecycle, queue, plugin runtime, i18n and auth.

This library adds the one piece the kit cannot: an audio backend, plus the methods that only mean something when listening. Crossfade between queue items, and lyrics.

## Who it's for

Anything where someone listens: a streaming app, a podcast or radio client, a music dashboard inside a bigger product.

Reach for it when you want the UI to be yours, rather than someone else's chrome under CSS overrides.

Composing a third kind of player, neither video nor music? Start one level down at [`nomercy-player-core`](/nomercy-player-core).

## Why it exists

Listening has one genuinely hard job: getting from one track to the next without a gap or a click, and with a real overlap when the app wants a crossfade rather than a cut.

A swappable audio backend owns that job.

`AudioElementBackend`, the default, drives a plain `HTMLAudioElement`. `WebAudioBackend` routes through an `AudioContext` graph, which buys sample-accurate crossfades and a tap point for an equalizer or a visualizer.

Both sit behind the same typed surface, so `crossfadeTo(nextItem)` reads the same either way.

Queueing, transport, volume, auth and plugins are not listening-specific, so they come from the core. A fix there reaches every player built on it.

## The setup, then freedom, model

Create an instance bound to a container, call `setup(config)` once, wait for it, then do whatever you want.

`nmplayer(id)` is the factory. It returns the existing instance for an id already in use, or mounts a fresh one into the `<div>` at that id, creating its own audio element inside it.

```ts
import nmplayer from '@nomercy-entertainment/nomercy-music-player';

const player = nmplayer('player-container')
  .setup({ /* ... */ });
await player.ready();
```

`setup()` is the only strict part. It walks the pipeline every kit-composed player runs, before `ready()` resolves: config snapshot, plugin registration, stream, auth, playlist, media readiness.

Call it twice and it throws, so a half-configured instance is not a state you can reach.

Once `ready()` resolves, no UI is prescribed. Build controls against the typed methods, or add plugins for lyrics, cast or media session.

Every path calls the same `play()`, `pause()` and `crossfadeTo()` underneath.

## What you get

- **`NMMusicPlayer<T>`**, created through the `nmplayer(id)` factory, generic over your own playlist item type.
- **A swappable audio backend**: `AudioElementBackend` by default, `WebAudioBackend` for sample-accurate crossfades and a Web Audio graph tap, selectable at setup or at runtime through `backend(kind)`.
- **Crossfade between queue items** (`crossfadeTo(item, opts)`) with a configurable duration and curve. Music defaults `crossfadeEnabled: true`, unlike a hard-cut transition.
- **Audio output device selection** (`audioOutputs()`, `selectAudioOutput()`, `audioOutput()`) for routing playback to a specific speaker or Bluetooth device.
- **A Web Audio equalizer and audio graph**, from the kit's `AudioGraphPlugin` chain, available on either backend, `AudioElementBackend` lazily creates the Web Audio source node the first time a plugin requests it.
- **Synced lyrics** through the opt-in `LyricsPlugin`: fetches `item.lyricsUrl`, parses it through the kit's cue parser registry, and fires line-enter/line-exit events for a karaoke-style UI.
- **A plugin system**: media-session, cast, key-handler, scrobbling, and auto-advance ship as opt-in plugins instead of bundle weight everyone pays for.
- **Everything from `nomercy-player-core`** underneath: lifecycle, queue, transport, volume, i18n, and auth-aware fetch, so it never gets reimplemented per medium.
