# Hardware

Two things live here: what the server found in the machine, and what it measured that hardware doing.

## Detected hardware

Every accelerator the server can use, with what each one can encode and decode. A machine with nothing usable says so, and encoding then runs on the processor.

## The benchmark

Running the benchmark encodes real work with each combination and records what happened. That is what the server then uses when choosing how to encode.

Each device shows how many profiles it has been benchmarked with, so a partial picture is visible as a partial picture.

The result is kept, so the page is cheap to open. Running it again is worth doing after changing hardware or drivers.

Running the benchmark puts the machine under load for as long as it takes, so it is the owner's call and not something to start while people are watching.

::Troubleshooting

**No hardware detected on a machine that has some.** The server needs the driver and access to the device. In a container, the device also has to be passed in.

**The benchmark finishes with less than you expected.** A combination that cannot run is left out rather than reported as slow. The detected-hardware list above says what was available to try.

::
