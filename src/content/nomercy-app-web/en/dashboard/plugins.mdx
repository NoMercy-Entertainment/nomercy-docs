# Plugins

Plugins add capability to your server. Only the owner can install one, because installing one is letting code run inside your server.

## Getting one

The catalog lists what your configured repositories offer, with what is already installed marked. Install from there, or install a file you have.

## Consent

A plugin that asks for more than the ordinary set installs and waits, and the screen says it is waiting on you. Read what it asked for, then allow or deny.

A plugin that only reads media, supplies details or adds a screen is enabled when you install it.

You can review what you granted later, and withdraw it. Withdrawing disables the plugin and clears the grants.

## Grants

Beyond that first decision, a plugin can ask for something specific while it runs, such as one network host. Those appear at the top of the screen and are answered one at a time.

## Managing an installed plugin

Open it to see what it is and what it can do. Each can be disabled without uninstalling, which is the right move when you are working out whether it causes something.

Some changes need the server restarted before they take effect, and the screen says so where that is the case.

::Troubleshooting

**A plugin shows as failed.** It could not load. Version compatibility is checked before loading, so a plugin built against a different server version is rejected rather than half-loaded.

**A plugin is installed and does nothing.** It may be waiting for your consent. The screen marks that.

::

## What your server tells NoMercy about plugins

Once an hour your server sends a short report. Here is all of it.

Always, for every plugin you installed from the marketplace:

- Which refusals that plugin hit, by code, and how many times.
- Nothing else about the plugin, and nothing at all about you.

Only after you turn it on, in plugin settings:

- How many times each plugin crashed.
- How many times each plugin went past a resource ceiling.

Never, under any setting:

- Anyone's name, account or address.
- Any title, file, folder or library.
- Anything about a sideloaded plugin. A plugin you loaded yourself is your own
  code on your own machine, and your server does not report that it exists, or
  that you installed, updated or removed it.

Refusal counts go without asking because a plugin refusing the same thing on a
thousand servers is one plugin with a bug, not a thousand people with a
problem. Fixing it needs the count and nothing more.

A report that cannot be delivered is dropped rather than kept. A server that
was offline for a week comes back reporting this hour, not that week.

## When a plugin uses too much

The server watches what each plugin uses and acts when one goes past what you allowed it.

A plugin using too much processor is reported and left running, because it is still
answering and stopping it would lose whatever it was doing. A plugin holding too much memory
is restarted, because memory is not given back by asking and waiting costs the whole server.

A plugin restarted three times in an hour is turned off instead of restarted again. One that
breaches every time it comes back is in a loop, and a server that never settles helps
nobody. Its page says how many restarts it took and how to turn it on again.

On this release the server measures no processor or memory per plugin: a plugin runs inside
the server's own process, so the runtime knows what the process used, not which plugin used
it. The ceilings are there and the actions work; what feeds them arrives when plugins run
somewhere the operating system can count them separately.

## What a plugin is allowed

Every plugin starts with a share of your machine rather than a fixed number, so the same
plugin suits a laptop and a rack server.

- Processor: a quarter of your processors.
- Memory: a tenth of your memory, and never less than 256 MB.
- Disk: 5 GB, the same on every machine. A share of the disk would let a plugin grow into a
  drive you bought for films.
- Sending: a quarter of your upload speed. Until your upload speed has been measured, this
  is unlimited, because a limit worked out from a number the server made up would slow a
  plugin for no reason.
- Fetching: unlimited. A plugin fetching spends your line on something you installed on
  purpose.

Disk and sending are counted where the server hands the bytes over, so both numbers are
what happened rather than an estimate.

A write that would go past the disk allowance is refused before the bytes land, and the
plugin is told how much it was allowed. A plugin sending faster than it may is slowed
rather than stopped: whoever is watching keeps watching, a little behind.

Each plugin's page shows its four allowances and how much disk it is holding. You can raise
any of them, and clearing a field turns that limit off entirely. The page says plainly what
you gave up when you do: nothing then stops that plugin taking as much as the server has.

## What a plugin keeps about each person

Anything a plugin stores about somebody goes in that person's own folder,
separate from the plugin's own files. There is one folder per person per
plugin, and nothing is shared between them.

That means two things always work. Anyone can ask for everything a plugin
holds about them and get it as a file. And when someone leaves your server,
every plugin's copy goes with them, not just the plugins they installed.

The server does the removing, never the plugin. An author who forgot to write
that code cannot leave somebody's history behind.
