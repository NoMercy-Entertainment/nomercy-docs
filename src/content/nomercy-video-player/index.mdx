# nomercy-video-player — Documentation Home

Headless HLS video player built on `nomercy-player-core`. Ships HDR-aware adaptive bitrate, multi-track subtitles, ASS/SSA rendering, chapter markers, intro/credits skip, Chromecast handoff, and a full-featured built-in UI plugin.

---

## What this package provides

- `NMVideoPlayer<T>` — the core class. Generic over your playlist item type.
- `nmplayer(id)` — factory that creates or retrieves a named player instance.
- Four video-specific adapter ports (backend, chapter source, thumbnail source, subtitle style store).
- Fifteen built-in plugins (desktop UI, subtitle overlay, octopus ASS/SSA, skipper, cast sender, key handler, auto-advance, and more).
- Full TypeScript types for all public methods, events, and configuration.

## Architecture in one diagram

```
Your playlist item type (T extends VideoPlaylistItem)
       |
NMVideoPlayer<T>        ← per-library layer (video concerns only)
       |
nomercy-player-core     ← kit (generic: queue, auth, plugins, i18n, storage)
       |
IVideoBackend           ← backend layer (Html5VideoBackend / custom)
       |
<video> + hls.js + MSE
```

Everything below `NMVideoPlayer<T>` is generic — zero knowledge of your server API, your item shape beyond the typed fields, or any NoMercy infrastructure. App-specific glue lives in layer-5 consumer plugins.

## Container class system

The `<video>` element and state CSS classes on `.nomercyplayer` are kit-level concerns — the player manages them directly via the container-class mixin. The UI overlay (controls, seek bar, menus) is the responsibility of the optional `DesktopUiPlugin`.

State classes like `nm-playing`, `nm-paused`, `nm-fullscreen` are applied to the `.nomercyplayer` container by the kit's container-class-emit mixin when state changes. `DesktopUiPlugin` reads those classes to show/hide UI elements.

Do not add `nm-` or `nmplayer-` prefixed classes to elements from outside the plugin — those namespaces belong to the kit and the UI plugin respectively.

See [Desktop UI](/player/video/desktop-ui) for the full class table. The exact boundary between kit-owned vs plugin-owned classes is tracked in the architecture spec — Spine owns that boundary definition.
