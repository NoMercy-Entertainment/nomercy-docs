# Playlist Items

An item is one thing in the queue. Only `id` is required, but an item without `url` has nothing to play.

The fields divide into two groups, and the division is worth knowing before you build one.

Most fields change what the player does. A handful exist only so your own objects pass through without a cast.

## Identity and source

These four are the item.

| Field | Type | What it does |
| --- | --- | --- |
| `id` | `string \| number` | Required. Identifies the item in the queue and in every event that names one. |
| `url` | `string` | The media source. Resolved against `baseUrl` when relative, and through your auth rules before it reaches the backend. |
| `title` | `string` | The display name. Used by the interface, the operating system's now-playing panel, and Cast metadata. |
| `duration` | `number` | Seconds. Lets the interface show a length before the media loads. |

## Artwork

**Three field names are accepted for the same picture, and they are read in one order:** `image`, then `poster`, then `thumbnail`. The first one present as a string wins.

That exists so an item from a backend that calls it `poster` needs no rewriting on the way in. Set one of them, not several.

The value is resolved against `baseImageUrl` when relative and passed through untouched when it is already a full URL. It becomes the `<video>` element's poster, and it is the artwork the now-playing panel and a Cast receiver fetch.

## What the interface draws from

Set these and the shipped interface has more to show. Leave them out and it shows less, without failing.

| Field | Type | What it adds |
| --- | --- | --- |
| `description` | `string` | Synopsis text on the playlist card. |
| `show` | `string` | Series title in the top bar, shown when `season` and `episode` are present. |
| `season` | `number` | 1-based. Combines with `episode` into an `S01E03` label. |
| `episode` | `number` | 1-based. |
| `progress` | `WatchProgress` | Continue-watching state, drawn as the progress bar on the playlist card. |

**The player never writes `progress`.** It reads it to draw the bar; persisting it is yours to do. [Resume playback](/nomercy-video-player/recipes/resume-playback) shows the round trip.

## Sidecars

Each of these points at a file the player fetches alongside the media.

| Field | Type | What it carries |
| --- | --- | --- |
| `subtitles` | `SubtitleTrackRef[]` | Subtitle tracks, one entry per language and format. |
| `chapters` | `ChapterRef[]` | Chapter marks, drawn on the scrubber and reachable from the skip controls. |
| `previewSpriteUrl` | `string` | The sprite sheet behind the thumbnail a viewer sees while scrubbing. |
| `fonts` | `FontTrackRef[]` | Font manifests or font files, used when rendering ASS and SSA subtitles. |

Their shapes are in [Types](/nomercy-video-player/reference/types).

## Two fields the playlist menu branches on

`playlist_type` and `video_type` change what the playlist menu renders. A value of `'movie'` in either one keeps an item out of the episode list, and `playlist_type: 'tv'` puts it in.

They sit in the source under a comment saying the consumer-supplied fields are not used by the player. That is true of the others below it and not of these two, which the desktop interface reads when it decides between an episode card and a movie card.

## Fields carried, not read

These exist so an item straight from your own API type-checks without a cast. The player stores them and does nothing with them.

`uuid`, `logo`, `rating`, `audio`, `tmdb_id`, `video_id`, `year`

Setting one changes nothing on screen. They are listed here so you can tell them apart from the fields above, which is the question the type alone does not answer.

`seasonName` belongs with them for a player built today. The only code that reads it is the v1 compatibility plugin, when it rebuilds a v1-shaped season list.
