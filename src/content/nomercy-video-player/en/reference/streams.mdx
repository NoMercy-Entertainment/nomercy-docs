# Streams

The player asks one question about a URL: is it HLS.

Everything else is handed to the video element, so what plays is what the browser can decode.

## The rule the player applies

A URL is treated as HLS when it contains `.m3u8` followed by a `?`, a `#`, or the end of the string.

The test is case insensitive.
It is not anchored to the end of the path, so `movie.mp4?fallback=alt.m3u8` plays as HLS because the `.m3u8` is the last thing in the URL.

Nothing else about the URL is read, and no content type is consulted.

## How HLS plays

**The player prefers the browser's own HLS support and falls back to `hls.js`.**

The choice is a capability probe rather than a browser name.
A browser answering `probably` to an HLS content type plays it natively, and so does one answering `maybe` without Media Source Extensions.
Everything else gets `hls.js`, imported at the moment it is needed rather than at page load.

`hls.js` is a dependency of the core package underneath, so it installs with the player.
Installing from npm needs no peer dependency and no import of your own.

## Everything else

Any other URL becomes the `src` of the video element.
That is how `.mp4` and `.webm` play.

A URL with no extension at all is handed over the same way.

The decision is the browser's rather than the player's.
The list of playable formats is therefore the browser's list, and it differs between browsers.
