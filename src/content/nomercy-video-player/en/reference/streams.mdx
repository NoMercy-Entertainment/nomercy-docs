# Streams

A stream factory turns a URL into something the player can play. Two ship with the player, and between them they cover HLS and progressive files, so most catalogues need nothing added.

## What plays without a factory of your own

The player matches on the URL first and the content type second. Either one is enough.

The HLS factory claims a URL whose path ends in `.m3u8`, before any `?` or `#`. It also claims these content types:

- `application/vnd.apple.mpegurl`
- `application/x-mpegurl`
- `application/mpegurl`
- `audio/vnd.apple.mpegurl`
- `audio/x-mpegurl`
- `audio/mpegurl`

The native factory claims a URL ending in one of these extensions, again before any `?` or `#`:

| Kind | Extensions |
| --- | --- |
| Audio | `mp3`, `flac`, `aac`, `m4a`, `wav`, `ogg`, `opus`, `weba` |
| Video | `mp4`, `webm`, `mov`, `m4v`, `ogv` |

It also claims any content type beginning `audio/` or `video/`, with the HLS types above excluded so the HLS factory keeps them.

Nothing else is matched. A URL with no extension and no content type reaches no factory, and the player throws `core:stream/no-factory-match` naming the URL it could not place.

## How HLS actually plays

**The player prefers the browser's own HLS support and falls back to `hls.js`.** Safari plays HLS natively, so nothing is downloaded there; every other browser gets `hls.js`, imported at the moment it is needed rather than at page load.

`hls.js` is a dependency of the core package underneath, so it installs with the player. There is no peer dependency to add and no import to write.

## Registering a factory of your own

A factory answers two questions: whether it can play a URL, and what to create for it.

```ts
import type { IStreamFactory } from '@nomercy-entertainment/nomercy-player-core';

const dashFactory: IStreamFactory = {
  id: 'dash',

  canPlay(url, contentType) {
    return /\.mpd(?:[?#]|$)/i.test(url) || contentType === 'application/dash+xml';
  },

  create(opts) {
    return new DashStreamSource(opts);
  },
};

player.registerStream(dashFactory);
```

`id` is what makes a factory replaceable: registering a second factory with the same `id` replaces the first in place rather than adding to the list.

**The most recently registered factory that claims a URL wins.** The registry walks its list newest first, so your factory takes precedence over the built-ins without any priority number.

That makes the second argument read backwards, and it is worth knowing before you reach for it:

```ts
player.registerStream(myFactory, true);
```

Passing `true` prepends, which puts your factory at the **front** of the list and therefore last in the walk. A factory registered that way is consulted only when nothing else claims the URL, which is what you want for a catch-all and never what you want for an override.

## When a URL reaches no factory

The player throws `core:stream/no-factory-match`. The message names the URL and the content type it was given, and the error's `context` carries both as fields.

Two causes account for most of it.

The extension is one the shipped factories do not claim. A factory of your own is the fix.

Or the URL carries no extension, because it is a signed or rewritten link. Passing the content type alongside it is enough for the built-ins to claim it.
