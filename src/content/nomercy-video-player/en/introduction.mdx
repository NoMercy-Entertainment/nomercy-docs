# What is nomercy-music-player

`nomercy-music-player` is an audio engine that handles the hard parts for you. It supports gapless playback, crossfade between tracks, a swappable audio backend, synced lyrics, and a plugin system. It does not include any built-in UI. There is no play button, no timeline, no volume slider. You get the audio transport and a typed API, and you build the interface you want.

It is built on `nomercy-player-core`, the shared foundation under the whole player trio. The core provides lifecycle, queueing, plugins, translations, and auth. `nomercy-music-player` adds the audio backend and the features that only make sense for listening such as crossfade, audio output device selection, and lyrics.

## Who it's for

Use `nomercy-music-player` when you are building a listening experience. This includes streaming apps, podcast or radio clients, or a music dashboard inside a larger product. It is for situations where you want full control over the UI instead of trying to restyle someone else’s player. If you are building a player that is not music or video, start with [`nomercy-player-core`](/nomercy-player-core/introduction).

## Why it exists

Listening has one challenge that is genuinely hard. You need to move from one track to the next without a gap or a click, and you need real overlap when the app wants a crossfade. `nomercy-music-player` solves this with a swappable audio backend. `AudioElementBackend` uses a normal `HTMLAudioElement`. `WebAudioBackend` uses a full `AudioContext` graph for sample accurate crossfades and a tap point for an equalizer or visualizer. Both backends use the same typed API, so `player.crossfadeTo(nextItem)` works the same way. Everything that is not specific to listening such as queueing, transport, volume, auth, and plugins comes from `nomercy-player-core`.

## The setup, then freedom, model

You create a player instance, call `setup(config)` once, wait for it to finish, and then you can build any UI you want. `nmplayer(id)` is the factory. It returns the existing instance for an id already in use, or mounts a new one into the `<div>` with that id and creates its own audio element inside it.

```ts
import nmplayer from '@nomercy-entertainment/nomercy-music-player';

const player = nmplayer('player-container')
  .setup({ /* ... */ });
await player.ready();
```

`setup()` is the only strict step. It runs a fixed sequence such as config snapshot, plugin registration, stream, auth, playlist, and media readiness. Calling it twice throws an error so you never end up with a half configured player. After `ready()` resolves, there is no required UI. Build your own controls using the typed methods, or add plugins for lyrics, cast, or media session integration. Every path uses the same `play()`, `pause()`, and `crossfadeTo()` methods.

## What you get

- **`NMMusicPlayer<T>`** created through the `nmplayer(id)` factory, generic over your playlist item type.
- **Swappable audio backend** `AudioElementBackend` by default, `WebAudioBackend` for sample accurate crossfades and a Web Audio graph tap. Selectable at setup or at runtime through `backend(kind)`.
- **Crossfade between queue items** `crossfadeTo(item, opts)` with a configurable duration and curve. Music defaults to `crossfadeEnabled: true`.
- **Audio output device selection** `audioOutputs()`, `selectAudioOutput()`, `audioOutput()` for routing playback to a specific speaker or Bluetooth device.
- **Web Audio equalizer and audio graph** from the core’s `AudioGraphPlugin` chain. Available on both backends. `AudioElementBackend` creates the Web Audio source node the first time a plugin requests it.
- **Synced lyrics** through the optional `LyricsPlugin`. It fetches `item.lyricsUrl`, parses it through the core’s cue parser registry, and fires line enter and line exit events for a karaoke style UI.
- **Plugin system** media session, cast, key handler, scrobbling, and auto advance are available as opt-in plugins.
- **Everything from `nomercy-player-core`** lifecycle, queue, transport, volume, translations, and auth aware fetch.
