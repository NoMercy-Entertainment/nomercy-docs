# Quick Start

Five steps to a film playing in your own page. Each one says what you should see, so you can tell it worked before moving on.

## 1. Install it

```bash
npm install @nomercy-entertainment/nomercy-video-player
```

That is the whole install. `hls.js` arrives with it, as a dependency of the core package underneath, and the player imports it only when the browser cannot play HLS on its own.

Two kinds of source play with nothing further: HLS, and progressive files such as `.mp4` and `.webm`. The player picks between them from the URL, so an `.m3u8` needs no flag.

Anything else needs a stream factory of your own. [Streams](/nomercy-video-player/reference/streams) lists every extension and content type that is matched, and the call that registers one.

## 2. Give it a container

The player fills an element you provide.

```html
<div id="player"></div>
```

That div becomes the player root. The player marks it `nomercyplayer` and keeps state classes on it as playback changes, so `paused`, `playing` and `active` are available to your own CSS without a line of JavaScript.

The video element is created inside it, on the first frame rather than at setup.

**It must be a `<div>`.** Any other tag throws `core:player/element-not-div`, and an id matching no element throws `core:player/element-missing`.

Give it a width. A bare player needs nothing else, because the video element sizes itself and takes the container along with it.

```css
#player {
  width: 100%;
  background: #000;
}
```

**Pinning the box to a ratio at this stage overflows it.** The video keeps its own dimensions until something styles it, so `aspect-ratio: 16 / 9` on the container leaves the picture hanging out of the side. Add the ratio once you add the interface, which is what makes the video fill its container.

There is no stylesheet to import at any point. The interface plugin injects its own.

**You should now see Sintel sitting on its first frame, with the browser's own controls under it.** Press play and it runs.

If the picture is there and stays black, the source could not load. If nothing appears at all, the id in your CSS and the id you passed do not match, and the player threw `core:player/element-missing` rather than mounting.

Calling `nmplayer('player')` again with the same id gives back the same player rather than a second one.

The registry is checked before the element is, so a repeat call holds up even after the div has gone. That is what makes it safe inside a component that re-renders.

A real second player therefore needs a second container with a different id.

## 4. Wait for it before calling anything

`setup` returns straight away, and the player is not usable yet. That is what the last line of the block above is for.

`await player.ready()` resolves once setup has finished and every plugin has come up.

**Past that line every method is safe to call.** Restoring a saved position or selecting a track belongs after it, and a method called before it may quietly do nothing.

Calling `ready()` again on a player that is already ready resolves immediately, so it is safe in a path that may run twice.

## 5. Keep item paths relative

`baseUrl` is the one config field every playlist should set. It prefixes media and sidecar paths, and `baseImageUrl` does the same for artwork.

Both are string prefixes joined by plain concatenation, so give the base no trailing slash and the path a leading one.

**Artwork gets its own base because it has to end up absolute.** The operating system's now-playing panel and a Cast receiver both fetch it with no page to resolve against.

Setting the base once is what lets one config value move a whole catalogue between environments. An item that carries a full URL of its own is passed through untouched, so the two mix freely and each item is judged on its own.

## What you have, and what is next

That is a working player with the browser's controls. Controls of the player's own are a plugin, and everything past this point adds one.

- [The desktop interface](/nomercy-video-player/plugins-adapters/desktop-ui) puts real controls over the picture: a title bar, a scrubber with chapter markers and preview thumbnails, volume, and menus.
