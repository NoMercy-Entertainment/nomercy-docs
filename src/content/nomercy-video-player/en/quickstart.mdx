# Quick Start

Five steps to a film playing in your own page. Each one says what you should see, so you can tell it worked before moving on.

## 1. Install it

```bash
npm install @nomercy-entertainment/nomercy-video-player
```

That is the whole install. `str hls.js` arrives with it, as a dependency of the core package underneath, and the player imports it only when the browser cannot play HLS on its own.

The player makes one decision about a URL: whether it ends in `str .m3u8`.
An `str .m3u8` plays as HLS and needs no flag.

Everything else is handed to the video element, so `str .mp4`, `str .webm` and anything else your browser decodes play with nothing further.
[Streams](/nomercy-video-player/reference/streams) has the rule in full, including the one case where a query string makes an `str .mp4` play as HLS.

## 2. Give it a container

The player fills an element you provide.

```html
<div id="player"></div>
```

That div becomes the player root.
The player marks it `css .nomercyplayer` and keeps state classes on it as playback changes, so `css .playing`, `css .paused` and `css .active` are available to your own CSS without a line of JavaScript.

The video element is created inside it when the stream is attached, which is after `setup()` has returned and after `ready()` has resolved.

**It must be a `html <div>`.**
Any other tag throws `str core:player/element-not-div`, and an id matching no element throws `str core:player/element-missing`.

Size it yourself.

```css
#player {
  width: 100%;
  background: #000;
}
```

The container takes its height from the video inside it, so a width is all it needs at this stage.

**A bare player is as wide as the artwork you gave it.**
While the poster is showing, the video element takes that image's own size, and a replaced element does not shrink to fit the column around it.
An item whose image is 780 pixels wide therefore hangs out of any container narrower than that.

An item with no `image` skips that and takes the video's own dimensions from the start.

`aspect-ratio` on the container changes neither case, because the video is not taking its size from the container in the first place.
Add/content/no the ratio once you add a controls plugin, which is what stretches the video to fill its container.

There is no stylesheet to import at any point.
A controls plugin injects its own.

**You should now see Sintel's artwork, with the browser's own controls across the bottom of it.**
Those controls are drawn inside the video element, over the picture rather than under it.
Press play and the film starts.

The artwork is the item's `image`, which the player sets as the element's poster and leaves up until playback begins.

If the picture is there but nothing you wrote in CSS applies, the id in your stylesheet and the id on the div do not match.
The player reads only the div's own id, so a selector that misses is invisible to it.

An id passed to `nmplayer()` that matches no element is the other case, and it throws `str core:player/element-missing` before anything mounts.

Calling `nmplayer('player')` again with the same id gives back the same player rather than a second one.
The registry is checked before the element is, so a repeat call holds up even after the div has gone.
That is what makes it safe inside a component that re-renders.

A real second player therefore needs a second container with a different id.

## 4. Wait for it before calling anything

`fn setup` returns straight away, and the player is not usable yet. That is what the last line of the block above is for.

`await player.ready()` resolves once setup has finished and every plugin has come up.

**Past that line every method is safe to call.** Restoring a saved position or selecting a track belongs after it, and a method called before it may quietly do nothing.

Calling `ready()` again on a player that is already ready resolves immediately, so it is safe in a path that may run twice.

## 5. Keep item paths relative

`key baseUrl` is the one config field every playlist should set. It prefixes media and sidecar paths, and `key baseImageUrl` does the same for artwork.

Both are string prefixes joined by plain concatenation, so give the base no trailing slash and the path a leading one.

**Artwork gets its own base because it has to end up absolute.** The operating system's now-playing panel and a Cast receiver both fetch it with no page to resolve against.

Setting the base once is what lets one config value move a whole catalogue between environments. An item that carries a full URL of its own is passed through untouched, so the two mix freely and each item is judged on its own.
