# Plugin: Cast Sender

`cls CastSenderPlugin` (id `str cast-sender`) sends the playing video item to a Chromecast receiver and mirrors the receiver's state back onto the player.

It is a two-method subclass of the kit's [`cls CastSenderPlugin`](/nomercy-player-core/plugins-adapters/cast-sender). Session lifecycle, the transport bridge, the volume conversion, the events and the resume-on-disconnect behavior all live in the base class and are unchanged here. This page covers only what the video subclass decides: the default MIME type, and how a `cls VideoPlaylistItem` becomes Cast metadata.

## Registering it

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player';
import { CastSenderPlugin } from '@nomercy-entertainment/nomercy-video-player/plugins/cast-sender';

const player = nmplayer('player');

player.addPlugin(CastSenderPlugin, { live: true });
player.setup({ playlist: [] });
await player.ready();

await player.getPlugin(CastSenderPlugin)?.connect();
```

`fn connect` needs `ts cast.framework` already on the page, and the receiver app id is set on the SDK's own `ts CastContext` before you call it. The receiver is not a plugin option. The core page covers both, along with the separate `fn transferTo` route.

## The default content type

`fn defaultContentType` answers `str video/mp4`. It is the type sent when the item carries neither `key mime` nor `key contentType`, and the `key defaultContentType` option overrides it per registration.

## What the metadata carries

`fn buildMetadata` reads five fields off the canonical `cls VideoPlaylistItem` and nothing else.

| Item field | What it becomes |
|---|---|
| `key title` | `key title`, or an empty string when the item has none |
| `key show`, set to a non-empty string | `ts TvShowMediaMetadata` if the SDK build carries that constructor, otherwise `ts GenericMediaMetadata`, with `key seriesTitle` taken from `key show` |
| `key season` | `key season`, coerced with `fn Number`, and only on the show path |
| `key episode` | `key episode`, coerced with `fn Number`, and only on the show path |
| `key poster` | resolved through `fn resolveUrl` under the `str poster` category, then written as a one-entry `key images` array |

An item with no `key show` gets a plain `ts GenericMediaMetadata` carrying the title and the poster. An item carrying your own fields needs your own override, because the list above is fixed.

## How to extend it

Subclass and call up to the base, which builds the canonical set for you:

```ts
import { CastSenderPlugin } from '@nomercy-entertainment/nomercy-video-player/plugins/cast-sender';
import type { ChromeCastMediaCtors } from '@nomercy-entertainment/nomercy-player-core';
import type { VideoPlaylistItem } from '@nomercy-entertainment/nomercy-video-player';

class MyCastSenderPlugin extends CastSenderPlugin {
  protected override async buildMetadata(item: VideoPlaylistItem, ctors: ChromeCastMediaCtors) {
    const meta = await super.buildMetadata(item, ctors);
    return meta;
  }
}
```

Keeping the `str cast-sender` id means the subclass replaces the built-in at registration rather than running beside it.

## Translations

The subclass ships its own bundle for 79 locales, discovered by `fn translationsFromGlob`. The kit's base class ships English and Dutch as an eager literal. Registration walks the prototype chain, so both bundles reach the table with the base's keys first.
