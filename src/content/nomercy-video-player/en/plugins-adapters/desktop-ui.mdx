# Plugin: Desktop UI

`cls DesktopUiPlugin` (id `str desktop-ui`) is the overlay this library ships with. A top bar, a center play button, a bottom bar carrying the scrubber and the transport, a settings menu of seven panes, and an auto-hide cycle it takes over from the player.

Nothing inside it is private machinery you cannot reproduce. It calls the same public methods your own code would, `fn play`, `fn subtitle`, `fn quality`, and it restyles with plain CSS.

[Build a Player](/nomercy-video-player/build/shell) walks through writing one yourself. This page is the shipped one: what it takes, what it draws, and how each group inside it works.

## Options

| Option | Type | Default | Purpose |
|---|---|---|---|
| `key hideTitle` | `cls boolean` | `false` | Hide the top bar's title column. The buttons beside it stay. |
| `key disableClickToPause` | `cls boolean` | `false` | Stop a click on the video element from toggling playback. |
| `key inactivityMs` | `cls number` | `4000` | Milliseconds of quiet before the chrome hides. |
| `key imageBaseUrl` | `cls string` | none | Prefix for relative thumbnail paths in the playlist pane, separate from the player's `key baseImageUrl`. |
| `key buttons` | `cls DesktopUiButtonOptions` | none | Per-button opt in and opt out. |
| `key buttonOrder` | `cls ReadonlyArray` | none | Re-anchors the named buttons to the end of the bar in that sequence. Unnamed ones keep their place. |
| `key settingsItems` | `cls SettingsToggleItem[]` | none | Toggle rows appended to the settings menu. |
| `key subtitleMenuActions` | `cls SubtitleMenuAction[]` | none | Action rows appended to the subtitles pane. |
| `key settingsMenuActions` | `cls SubtitleMenuAction[]` | none | Action rows appended to the main settings menu, below any toggles. |
| `key buttonPriority` | `cls ButtonPriorityList` | see below | Order the bar sheds buttons in as it narrows. |
| `key portraitHidden` | `cls Array` | see below | Buttons forced off in portrait, whatever the width. |
| `key breakpoints` | `cls Breakpoint[]` | see below | The tier names and widths the plugin reports as it resizes. |
| `key volumeSlider` | `str horizontal`, `str vertical` or `str auto` | `str auto` | Slider shape. |

Three events carry the plugin's own namespace, `str plugin:desktop-ui:`.

| Event | Payload | What it is for |
|---|---|---|
| `str shortcuts-toggle` | none | Raise it to open or close the keybinds dialog. |
| `str layout:breakpoint` | `key from`, `key to`, `key visibleButtons`, `key hiddenButtons` | Fires on a tier change, with the two button lists. |
| `str opts:changed` | the new options | Re-emit it with new options to re-apply them live. |

## Which buttons render

`cls DesktopUiButtonOptions` decides which control-bar buttons exist at all, before the width rules below get a say.

On by default: `key play`, `key mute`, `key volume`, `key fullscreen`, `key settings`, `key next`, `key previous`, `key chapterPrev`, `key chapterNext`.

Off by default: `key theater`, `key pip`, `key speed`, `key quality`, `key subtitles`, `key audio`, `key playlist`, `key seekBack`, `key seekForward`, `key aspectRatio`, `key cast`.

The two seek buttons are off because a jump is already two other places. `str ArrowLeft` and `str ArrowRight` on the keyboard move five seconds, and a double tap in the [touch zones](/nomercy-video-player/plugins-adapters/touch-zones) moves ten. Turn the buttons on for a build with neither. Their own click seeks ten seconds either way.

`key cast` is the odd one. It renders in the top bar next to `key back` and `key close` rather than in the control bar.

Clicking it emits the player's `str cast` event and does nothing else, which is the same no-opinion shape its two neighbors have. Wire a listener and open your own device picker from it. `cls CastSenderPlugin` drives a session once a target is chosen; picking the target is yours.

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player';
import { DesktopUiPlugin } from '@nomercy-entertainment/nomercy-video-player/plugins/desktop-ui';

const player = nmplayer('player');

player.addPlugin(DesktopUiPlugin, {
  buttons: { theater: true, subtitles: true, audio: true },
});
```

## Narrowing the bar

Every resize walks `key buttonPriority` from the front, adds up estimated widths, and hides the first button that no longer fits along with everything behind it. So the order is a ranking of what survives longest.

The default:

```text
play -> mute -> volume -> fullscreen -> settings
  -> next -> previous -> chapterPrev -> chapterNext
  -> seekForward -> quality -> subtitles -> audio
  -> seekBack -> theater -> pip -> speed
  -> aspectRatio -> playlist
```

Subtitles and audio sit above the framing and pacing controls deliberately. A narrow bar that keeps picture-in-picture and drops the subtitle menu has kept a convenience and lost the control some viewers cannot watch without.

The arithmetic is 40 px per button, plus 96 px for the volume slider's hover expansion on a device that has hover. That total is measured against the container width less 148 px, reserved for the time labels and padding.

A `cls ResizeObserver` on the container drives the pass. `matchMedia('(orientation: portrait)')` and `matchMedia('(hover: none) and (pointer: coarse)')` feed it too, and each stamps a `str data-orientation` or `str data-no-hover` attribute on the container for your CSS to key off.

Four rules compose, in this order:

1. A button turned off in `key buttons` never shows.
2. A button marked `str data-content-hidden` is skipped without counting its width. That is the capability gating below.
3. In portrait, the `key portraitHidden` set is forced off.
4. Whatever is left is fitted against the width.

`key breakpoints` names the tiers this pass reports. The default progression is `str xs` to 320 px, `str sm` to 480, `str md` to 720, `str lg` to 1024 and `str xl` above that.

The active name lands on the container as `str data-breakpoint`, and crossing a boundary emits `str layout:breakpoint` with both button lists. A consumer building its own overflow menu subscribes there rather than re-deriving visibility from the width.

```ts
player.addPlugin(DesktopUiPlugin, {
  breakpoints: [
    { name: 'compact', maxWidth: 480, hideAfterRank: 4 },
    { name: 'full', maxWidth: Infinity, hideAfterRank: Infinity },
  ],
});
```

## Portrait

Portrait fits five or six controls whatever the ranking says, so a set is forced off there regardless of width. The default set is `key chapterPrev`, `key chapterNext`, `key previous`, `key next`, `key subtitles`, `key audio`, `key quality` and `key playlist`.

`key portraitHidden` replaces that set rather than merging with it, so name every button you want gone. An episodic app usually keeps `key next` and `key chapterNext`, because skipping an intro one-handed is why a phone viewer reaches for the controls at all:

```ts
player.addPlugin(DesktopUiPlugin, {
  buttons: { chapterNext: true, next: true },
  portraitHidden: ['chapterPrev', 'previous', 'subtitles', 'audio', 'quality', 'playlist'],
});
```

Pass `ts []` to force nothing off and let width alone decide. The override buys a button a place in the ranking walk, not an exemption from it. A button still goes once the row runs out of room, so raise it in `key buttonPriority` too if it must outlive the squeeze.

## Mounting your own UI on it

`fn overlay` hands back the auto-hiding chrome root. An element appended there inherits the same show and hide cycle instead of floating over hidden chrome:

```ts
const badge = document.createElement('div');

const ui = player.getPlugin(DesktopUiPlugin);
const overlayRoot = ui?.overlay();

if (overlayRoot)
  overlayRoot.append(badge);
```

It answers `ts null` until `fn use` has built the DOM, so guard the call.

An overlay anchored to the top or bottom bar also has to stop those bars hiding underneath it. `fn holdChrome` pins them; `fn releaseChrome` lets the countdown resume. The hold is counted, so independent holders compose and the chrome stays until the last release. Call them in pairs:

```ts
const ui = player.getPlugin(DesktopUiPlugin);

ui?.holdChrome();
// … your panel is open …
ui?.releaseChrome();
```

An extra release floors at zero rather than going negative, so a double release cannot wedge the chrome hidden. The plugin's own menus need none of this: they pin through their own menu-open flag.

## How it is built

Everything below is internal machinery. The package exports the plugin class, its options types and the two consumer row types, `cls SettingsToggleItem` and `cls SubtitleMenuAction`, and nothing else from this folder.

Read it as patterns for your own UI plugin rather than an API to import. The shared toolkit each group leans on, `fn mount`, `fn listen`, `fn timeout`, `fn on`, `fn emit`, `fn fetch`, `fn t` and `key storage`, is the [Plugin Handbook](/nomercy-player-core/handbook/anatomy)'s subject.

The class body is thin: static metadata, field declarations, the lifecycle overrides, and the public `fn overlay`, `fn holdChrome` and `fn releaseChrome`.

Nine mixin objects carry the method bodies. `fn composeMixins` stamps them onto the prototype, which is the same primitive `cls NMVideoPlayer` is composed from.

A `cls DesktopUiInternals` interface is the typed `this` between the fields and the mixin bodies. Under the mixins sit free functions that take their state as parameters, so each concern tests without a plugin instance.

The DOM it builds:

```text
overlay                       one mount(), z-index 20, pointer-events none
  top-bar                     back / cast / close + title + show-info
  center                      spinner + center play button
  bottom-bar
    slider-bar                buffer, hover, progress, chapter markers, nipple, pop
    bottom-row                transport, volume, time labels, feature buttons
  menu-frame-dialog           a <dialog>, main menu + seven sub-panes
  keybinds dialog             the shortcuts sheet
```

The message line is the exception: it lives on the player container, not in the overlay, so a "Loading…" line survives the chrome hiding.

### Activity and auto-hide

The player has a built-in activity tracker and this plugin turns it off. The first thing `fn use` does is `player.activityTracking(false)`, taking over as the only emitter of `str activity`. A cleanup hands ownership back on dispose.

The reason is scope. The built-in tracker sees DOM input only. This chrome must also stay up while a menu is open, while the pointer rests on the bars, and while a scrub is in flight.

Three moves work a small state bag:

- `fn bumpActivity` shows the chrome and re-arms the countdown for `key inactivityMs`.
- `fn maybeHide` runs when that timer fires. It refuses while playback is not `str playing`, while a menu is open, while a hold is outstanding, or while a mouse pointer is over the bottom bar or the menu frame.
- `fn dismissOverlay` is the deliberate paused-state dismiss, used when the viewer clicks the empty overlay background. It skips the playing-only guard and still refuses on a menu, a hold, or a scrub.

What counts as activity:

- a `str mousemove` that moved at least 2 px on either axis
- a `str mousedown` or a `str pointerdown`
- a `str touchstart`, but only while the chrome is down
- a `str keydown`
- every control interaction

A `str mouseleave` on the container goes straight to `fn maybeHide`.

Pausing cancels the timer and pins the chrome. Hover pinning reads `key pointerType` and counts only `str mouse`, so a finger resting after a tap pins nothing.

`str activity` fires only when the state flips, with one guard. A show is forced through if the container has lost its `str active` class while the flag still says active. So a direct `player.emit('activity', …)` from outside cannot wedge the chrome hidden.

`fn disable` hides the overlay outright rather than just its handlers, cancels the timer, and emits one last `str activity` with `key active` false. That is how a peer that owns the screen takes over without doubled chrome. `fn enable` restores the overlay and re-arms the cycle.

### The top bar

Two columns. The left holds three buttons that each emit one player event and do nothing else: `str back`, `str cast`, `str close`. The right holds the primary title and a secondary line.

Visibility differs per button.

`key back` and `key close` appear only while the player has a listener for their event. The `str listeners-changed` event keeps that live, so calling `player.on('back', …)` after mount makes the button appear.

`key cast` is gated on the option instead, never on listener presence, because an app may want it rendered before its Cast SDK finishes probing.

All three hide in picture-in-picture, where floating chrome would act on the wrong window.

The title composition mirrors the Android app's top bar:

| Content | Primary line | Secondary line |
|---|---|---|
| TV episode | Show name | `S{n}E{n} • {episode title}` |
| Season 0 special | Show name | `Extras E{n} • {episode title}` |
| Movie | Item title | Blank, and hidden |

Season and episode labels come from the plugin's own translation table, so the tokens localize. `key hideTitle` hides the right column only.

### Menus

Two files split the job: one renders, the other orchestrates. The frame is a real `str dialog` element carrying `str popover="manual"`. It holds a main menu of category buttons plus consumer rows, and seven panes: `str language`, `str subtitles`, `str quality`, `str speed`, `str playlist`, `str subtitleSettings` and `str aspectRatio`.

Menu state lives in one bag: which pane is open, the cached active subtitle, audio and quality indexes, and whether the viewer pinned a quality by hand. Buttons and panes both read from that bag, so the bottom bar's subtitle icon and the checkmark in the subtitles pane cannot disagree.

The pointer path opens a pane from its trigger button. Pressing the same trigger again closes it, because triggers stop propagation and never reach the outside-click closer, so without the toggle the only way out would be clicking elsewhere. A document-level click outside the frame closes everything, and `str aria-expanded` is managed on every trigger at each transition.

The keyboard path cycles focus with `str ArrowUp` and `str ArrowDown` through the open pane's visible, enabled buttons, wrapping at the ends. Those keys stop propagation, so the player's own seek and volume handlers cannot fire while a menu is open. `str Escape` closes the menus first and the shortcuts sheet second.

Panes repaint from live player data rather than being built once. Each has a guard that fires from the matching player event, so a selection made anywhere, a keyboard shortcut or another plugin, repaints an open pane too.

Picking a row closes the whole menu for a one-shot choice: quality, subtitles, audio, playlist and the subtitle style pane. It keeps the pane open for a compare-and-adjust one: speed and aspect ratio.

The cached indexes reconcile with the player's own state at `str mediaReady`. That read asks `fn subtitle`, `fn audioTrack` and `fn quality` first, because those cover plugin-rendered tracks that never reach a backend's native lists.

A default-track heuristic is the fallback when the player has no selection yet. Repaints never re-run the reconciliation, or a viewer's manual pick would be overwritten.

Opening a menu also sets the menu-open flag, which is what pins the chrome.

### Tooltips

One primitive covers every control-bar button, and its label function runs on each hover so a dynamic label stays current. The next button's tooltip names the next queue item; the chapter buttons name the chapter in their direction, on the same one-second tolerance the navigation uses.

The tooltip appears after 500 ms through a single debounce token shared across all buttons, and dismisses on click or `str mouseleave`. It is clamped horizontally against the slider bar's bounding rectangle, the same fence the scrub preview uses, and the clamp shifts the arrow so it keeps pointing at its button.

One structural detail worth copying: an icon renders into a `str .btn-icon` child span rather than the button itself. Swapping the icon's markup then never destroys the tooltip span beside it.

### The progress bar

The slider bar is a buffer fill, a hover fill, a progress fill, a chapter layer, the nipple, and the pop. The pop is the preview bubble holding a thumbnail, a chapter title and a timestamp. The bar carries `str role="slider"` with `str aria-valuenow` kept in sync as a percentage.

Scrubbing is three phases:

1. Arm. `str mousedown` or `str touchstart` sets the scrub flag, so the chrome cannot hide mid-drag.
2. Paint. `str mousemove` or `str touchmove` paints the pop and moves the hover fill, and while armed drags the nipple without seeking yet.
3. Seek once, at release. A `str mouseup` on `str document`, a `str touchend`, or a click computes the time and calls `player.time(seconds)`. The `str mouseup` lives on the document, not the bar, so a drag that ends outside still finalizes.

While scrubbing, the `str time` handler skips its progress writes so the clock cannot yank the nipple back.

The buffered fill is `player.buffered()` over the duration, repainted on every `str time` event inside a try/catch, because a detaching source buffer can throw mid-read.

Chapters change the rendering. With chapters present the bar gains `str has-chapters`, the single buffer fill hides, and each chapter gets a marker holding four layers: background, buffer, hover and progress. A marker spans `calc(width% - 2px)`, and that 2 px gap is what draws the dividers.

Fills are painted with `fn scaleX`, by the fill's position against the chapter's range:

| Position | Value |
|---|---|
| Before the range | `scaleX(0)` |
| Inside it | The fraction of the span |
| Past it | `scaleX(1)` |

Progress, buffered and hover reuse the same function on different layers. Clicking a marker calls `player.seekToChapter(index)`. Markers rebuild on the `str chapters` event, on `str duration`, and on an item change, and whichever arrives last wins.

### Sprite seek thumbnails

The sprite URL resolves from the playlist item: the typed `key previewSpriteUrl` field first, then a `key tracks` entry whose `key kind` is `str thumbnails`. The manifest is a VTT whose cue bodies read `image.webp#xywh=x,y,w,h`, and parsing hands off to core's `fn parseVttSprite`.

Both requests go through the plugin's authenticated `fn fetch`: the VTT as text, the image as an `cls ArrayBuffer` turned into a `str blob:` object URL. The detour exists because a bare `str img` source cannot carry an `str Authorization` header. The image is preloaded, so the first hover paints at once.

Loads are guarded with an incrementing token. A playlist jump mid-load discards the stale result and revokes its object URL rather than painting the previous film's thumbnails. Painting is a `str background-position` on a fixed-size div, and the object URL is revoked on the next item and on dispose.

### The volume slider

Three shapes, and `str auto` is the default.

- `str horizontal` expands on hover, in CSS alone.
- `str vertical` is a click-toggled popup above the mute button, carrying its own mute row.
- `str auto` picks vertical whenever the device reports no hover or the container is 520 px or narrower, re-evaluated on every resize.

While the vertical popup is the active shape, a click on the mute button opens the popup instead of muting. The mute row inside it is the mute control.

### Icon and button state

A set of pure functions each take only the DOM refs and scalars they need, and a mixin binds them to the plugin's refs.

One convention runs through all of them: a non-default state gets the `str is-active` class, which the stylesheet uses to force the filled icon variant. It lights for:

- a playback rate away from 1
- a manually pinned quality
- an active subtitle track
- a non-default audio track
- picture-in-picture engaged
- an aspect ratio other than `str uniform`

Aria labels carry the dynamic part. The speed button appends the rate when it is not 1, and the quality button appends the playing level's label.

The volume icon reads mute state and level together:

| State | Icon |
|---|---|
| Muted, or level 0 | Muted |
| Below 30 | Low |
| 30 through 60 | Medium |
| Above 60 | High |

Quality has one extra wrinkle: the icon and the pane distinguish the requested level from the playing one, because the requested value is often `str auto`.

The playing index is cached from `str level-switched`, with a peek at `backend().currentLevel()` before the first switch lands. Levels are matched on their `key index` field rather than array position, because `fn qualityLevels` filters unsupported codecs out.

### Transport state

Capability gating hides a button whose feature the current item cannot use, by marking it `str data-content-hidden` so the width pass skips it:

- subtitles with zero tracks, unless `key subtitleMenuActions` rows exist, which keep the button reachable on their own
- audio with one track or fewer
- quality with fewer than two levels
- chapter buttons with no chapters
- playlist with fewer than two queue items

The settings button itself hides only when all five of these hold at once:

- the speed list holds one entry or none
- audio holds one track or none
- there are no subtitle tracks
- there are no `key subtitleMenuActions`
- there are no `key settingsItems`

The matching main-menu category rows hide with their buttons. All of it re-runs on `str mediaReady`, `str chapters`, `str levels`, `str audioTracks`, `str subtitles` and an item change.

Enablement is finer than visibility. `key previous` and `key next` disable at the queue edges and whenever the queue holds one item. Rewind disables at time zero, forward within a quarter second of the end, and each chapter button when no chapter lies in its direction, on a one-second tolerance. A disabled button carries both `str disabled` and `str aria-disabled`.

Display state composes on top: theater hides in fullscreen or picture-in-picture, where it means nothing, and the top-bar buttons hide in picture-in-picture. A config opt-out always outranks state-driven showing.

The remaining-time label toggles between a countdown and the total duration on click. The choice persists in the plugin's scoped storage under `key showRemaining`, which reaches `str localStorage` as `str nmplayer-desktop-ui-showRemaining`.

### Feedback and toasts

The spinner and the message line are event-driven:

| Event | State |
|---|---|
| `str waiting`, `str stalled` | Buffering |
| A new `str item` | Loading |
| `str canplay`, `str playing`, `str time` | Cleared |
| `str error` | The error line |

The opening "Loading…" shows only when the player has something queued, because a player can legitimately mount idle. The busy class goes on the plugin's own center wrapper and never the container, whose playback-state classes belong to core.

The same line is the consumer toast surface, reachable through plain player events with no plugin reference:

```ts
player.emit('display-message', { text: 'Up next: Episode 2', ms: 4000 });
player.emit('remove-message', undefined);
```

A toast with `key ms` dismisses itself. Playback feedback carries no duration and clears when playback recovers instead.

### The shortcuts sheet

`str ?` toggles a dialog listing the key bindings, from this plugin's own `str keydown` handler on the container. No key handler is needed for it. `str Escape` closes it, and closes an open menu first if there is one.

Other plugins toggle it by raising `str plugin:desktop-ui:shortcuts-toggle`. [Plugin: Key Handler](/nomercy-video-player/plugins-adapters/key-handler)'s `str shift+?` calls `fn toggleShortcuts` directly instead.

A one-time hint toast shows on the first `str play` of each browser session, tracked in `str sessionStorage`.

### Live option changes

Re-emitting `str plugin:desktop-ui:opts:changed` with new options re-applies `key hideTitle`, re-runs capability gating so a live `key subtitleMenuActions` change lands, and re-renders the `key settingsMenuActions` rows.

Those rows are the one main-menu row kind built for repaint. A consumer can add a "Cast to device…" entry once its Cast SDK finishes an async probe and see the row appear without a rebuild.

## Rules & restrictions

- `key controls` on the player config sets the `str controls` attribute on the media element and nothing else. The browser's own bar then drives the element directly, so its buttons never enter `fn play` or `fn pause` and no `str beforePlay` listener sees them. Loading this plugin beside it draws two sets of controls. Pick one.
- `cls TvKeyHandlerPlugin` binds the same keys this overlay's own handlers use. One control surface per platform.
- Menu-driven and cycle-driven is a deliberate split. Quality, subtitles, audio, speed and aspect ratio open a pane on click, because each is a list. Theater, picture-in-picture and fullscreen are binary toggles. `fn cycleAspectRatio` and its siblings are for a remote or a key binding, where there is no list to pick from.
- The stylesheet is injected once per page under a fixed element id, however many players are mounted. Override its selectors from your own sheet rather than forking the plugin.

## How to extend it

Options cover most of it. Beyond them, subclass and override the lifecycle hooks, or write a plugin of your own that reads `fn overlay`:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player';
import { DesktopUiPlugin } from '@nomercy-entertainment/nomercy-video-player/plugins/desktop-ui';

const player = nmplayer('player');

let autoSkip = false;

player.addPlugin(DesktopUiPlugin, {
  buttons: { theater: true, quality: true },
  volumeSlider: 'auto',
  settingsItems: [
    {
      id: 'auto-skip',
      label: () => 'Auto-skip intros',
      get: () => autoSkip,
      set: (value) => {
        autoSkip = value;
      },
    },
  ],
});
```
