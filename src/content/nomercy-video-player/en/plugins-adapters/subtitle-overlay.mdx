# Plugin: Subtitle Overlay

`SubtitleOverlayPlugin` (id `'subtitle-overlay'`) is the VTT rendering half of subtitle support.

It turns the player's `'subtitleCue'` stream into a styled, positioned DOM tree above the video. Those cues arrive either as sidecar VTT parsed by the kit, or as native `TextTrack` cuechange forwarded by the backend.

It is a pure consumer. Where cues come from is decided upstream, in the kit and the video backend. This plugin paints what it is handed.

## Options

`SubtitleOverlayOptions` currently has no configurable fields, add the plugin as-is:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player';

const player = nmplayer('player');

player.addPlugin(SubtitleOverlayPlugin);
```

Visual customization goes through `player.subtitleStyle()` (see [Subtitles & Text Tracks](/nomercy-video-player/tour/subtitles)), not plugin options, the plugin repaints every active cue immediately on the `'subtitleStyle'` event.

## DOM tree and cue pooling

```
subtitle-overlay > subtitle-safezone > subtitle-area.<aligned> > subtitle-text
```

`.subtitle-area` and `.subtitle-text` pairs are pooled, one per active cue.

Two cues active at different `line` positions render as two independently positioned boxes, the way a browser's native VTT renderer handles simultaneous cues.

Where cues would collide, the later one is nudged along the line axis. That mirrors the WebVTT collision-avoidance step, rather than letting two lines paint over each other.

The overlay itself is sized and positioned to the actual video display rectangle (`player.videoRect()`, letterbox-fit under `object-fit: contain`), not the container, so subtitles never sit inside letterbox padding on a wide container playing a narrower-aspect video.

## Cue geometry

Cue `line`, `align`, `size` and `position` map to CSS following the WebVTT 1.0 layout algorithm.

Horizontally, `left` and `width` derive from `position`, `size` and an alignment anchor of 0, 0.5 or 1 for start, center and end.

Vertically, the anchor picks `top` or `bottom` from which half of the safezone `line` falls in. That approximates the native renderer's overflow fallback.

The safezone insets 5% top and bottom, 3% left and right. It is calibrated for widescreen delivery rather than the CRT-era SMPTE convention, matching what streamers ship today.

## Rules & restrictions

- Renders only. Subtitle *selection* is kit surface, `subtitle()` and `subtitles()`. Selecting a track without this plugin loaded changes state correctly and paints nothing. See [Subtitles & Text Tracks](/nomercy-video-player/tour/subtitles).
- ASS/SSA is not this plugin's job. [`OctopusPlugin`](/nomercy-video-player/plugins-adapters/octopus) renders those. The two coexist safely because they react to different signals: native cue events here, the `'subtitle'` selection event there. Each tears its own rendering down for formats it does not own.
- Colors resolve through a canvas-normalised hex conversion, with an alpha byte folded in from `textOpacity`, `backgroundOpacity` and `windowOpacity`. So any CSS color string works in `subtitleStyle`, not only hex literals.

## How to extend it

There's no subclass hook, the plugin is a leaf consumer of `subtitleCue` and `subtitleStyle`. A genuinely different rendering strategy (canvas-based, WebGL, a different cue-collision algorithm) is a new plugin against the same two signals rather than a subclass of this one:

```ts
import { Plugin } from '@nomercy-entertainment/nomercy-player-core';

class MySubtitleRenderer extends Plugin {
  static override readonly id = 'my-subtitle-renderer';

  override use(): void {
    this.on('subtitleCue', (change) => {
      // paint change.cues your own way
    });
  }
}
```

Don't register both `SubtitleOverlayPlugin` and a custom renderer for the same format at once, both would paint the same cue stream independently and double up the DOM.
