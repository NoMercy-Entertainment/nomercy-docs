# Plugin: Subtitle Overlay

`cls SubtitleOverlayPlugin` (id `str subtitle-overlay`) is the WebVTT rendering half of subtitle support.

It turns the player's `str subtitleCue` stream into a styled, positioned DOM tree over the video. Those cues arrive either as sidecar VTT the kit parsed itself, or as native `ts TextTrack` cue changes the backend forwards, and both funnel into that one event.

The plugin is a pure consumer of it. Which track is playing and where its cues come from are settled upstream, in the kit and the backend. This one paints what it is handed.

## Registering it

`cls SubtitleOverlayOptions` declares no fields, so the plugin takes no options:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player';
import { SubtitleOverlayPlugin } from '@nomercy-entertainment/nomercy-video-player/plugins/subtitle-overlay';

const player = nmplayer('player');

player.addPlugin(SubtitleOverlayPlugin);
player.setup({ playlist: [] });
await player.ready();
```

Appearance is set through `fn player.subtitleStyle` rather than through the plugin. It caches the current style when it starts and repaints every live cue the moment a `str subtitleStyle` event arrives, so a settings menu that writes the style sees the change on screen without a reload. [Subtitles & Text Tracks](/nomercy-video-player/tour/subtitles) covers that surface.

## The DOM tree

```text
subtitle-overlay > subtitle-safezone > subtitle-area.aligned-center > subtitle-text[data-language]
```

The `.subtitle-area` and `.subtitle-text` pairs are pooled, one per active cue, growing on demand and shrinking back to nothing when no cue is active. Two cues at different `key line` positions therefore render as two independently positioned boxes, which is what a browser's own VTT renderer does with simultaneous cues.

Each `.subtitle-text` carries a `key data-language` attribute holding the active language tag, so a stylesheet can target one language, a script that needs a larger line height for instance.

## The stylesheet it injects

The plugin appends a `ts <style>` element with the id `str nm-subtitle-overlay-styles` on first use, once per document. That sheet is where the overlay geometry lives, and a rule of yours at equal or higher specificity overrides any of it.

Three parts of it decide what a reader sees.

The safezone insets 5% on the block axis and 3% on the inline axis. The vertical figure keeps a caption clear of a scrubber, a bezel or any other chrome that might clip it.

The horizontal figure is smaller than the SMPTE convention on purpose: that rule was calibrated for CRT overscan, which web delivery does not have, and equal percentages produce a lopsided pixel inset on a non-square picture.

Cue text is sized at `ts clamp(14px, calc(var(--subtitle-scale, 1) * 2.5cqi), 56px)`. The `ts cqi` unit resolves against the player container, so text scales with the picture, and the clamp holds it readable at the small end and sane at the large one. The `str --subtitle-scale` variable is written per box from the style's font size.

The overlay root is `ts pointer-events: none` at `ts z-index: 0`, so it never intercepts a click meant for the video or for the chrome above it.

## Where the overlay sits

The overlay is sized and positioned to the video's actual display rectangle, read from `fn player.videoRect` and kept current by the `str videoRect` event. That rectangle is the letterboxed picture under `ts object-fit: contain`, not the container.

So a wide container playing a narrower picture keeps its captions on the picture rather than down in the letterbox bar, and pillarboxed 4:3 content gets its 3% margin measured against the 4:3 picture.

## Cue geometry

A cue's `key line`, `key align`, `key size` and `key position` map to CSS by the WebVTT 1.0 cue layout rules.

Horizontally, the alignment picks an anchor of 0, 0.5 or 1 for start, center and end, and a default position of 0%, 50% or 100% to match. `key left` is then the position minus the anchor times the size, and `key width` is the size.

Both are clamped into the safezone, so a box the spec would send off the edge keeps its anchor and loses no trailing text.

Vertically, an automatic line anchors the box to the bottom of the safezone. A line in the lower half anchors by `key bottom`, so the box sits above the line rather than hanging past the safezone. A line in the upper half anchors by `key top`.

Where two boxes would collide, the cue listed first keeps its position and the later one is pushed along the line axis, which is the WebVTT displacement step. The push is downward where there is room below and upward where there is not, and the displaced box is re-anchored so it stays inside the safezone either way.

## Rules and restrictions

- The plugin renders and nothing else. Choosing a track is kit surface, `fn subtitle` and `fn subtitles`. Selecting a track with this plugin absent moves the player's state correctly and paints nothing.
- ASS and SSA belong to [`cls OctopusPlugin`](/nomercy-video-player/plugins-adapters/octopus). The two coexist because they react to different signals: cue events here, the selection event there. Each tears its own rendering down for a format it does not own.
- Colors accept any CSS color string, not only hex. Nine common names resolve from a table, and everything else is normalized through a 2D canvas. The result is `str #RRGGBBAA` with the alpha byte folded in from `key textOpacity`, `key backgroundOpacity` or `key windowOpacity`, so an opacity of zero stays exact rather than rounding to opaque.
- An item change clears every box, so nothing from the previous item survives into the next one.

## How to extend it

There is no subclass hook. The plugin is a leaf consumer of `str subtitleCue` and `str subtitleStyle`, so a genuinely different strategy, a canvas renderer or a different collision algorithm, is a new plugin against the same two signals:

```ts
import { Plugin } from '@nomercy-entertainment/nomercy-player-core';
import type { NMVideoPlayer } from '@nomercy-entertainment/nomercy-video-player';

class MySubtitleRenderer extends Plugin<NMVideoPlayer> {
  static override readonly id = 'my-subtitle-renderer';

  override use(): void {
    this.on('subtitleCue', (change) => {
      console.log(change.cues.length, change.language);
    });
  }
}
```

Register one renderer per format. Two plugins on the same cue stream both paint it and double the DOM.
