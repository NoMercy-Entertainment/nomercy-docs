# Adapter: Subtitle Style Store

`player.subtitleStyle()` (see [Subtitles & Text Tracks](/nomercy-video-player/tour/subtitles)) keeps the user's font, color, and edge-style choices in memory. It emits `'subtitleStyle'` on every change. It never persists anything on its own.

`ISubtitleStyleStore` is the contract for the other half. Load a saved preference after `ready()` and apply it. Save on every change so the choice survives the next session.

## The interface

```ts
interface ISubtitleStyleStore {
	/** Persisted style, or null when nothing was saved yet. */
	load(): Promise<Partial<SubtitleStyle> | null>;

	/** Persist style so it survives a reload. */
	save(style: SubtitleStyle): Promise<void>;

	/** Clear any persisted preference ("reset to defaults"). */
	clear(): Promise<void>;
}
```

## The shipped implementation

`StorageBackedSubtitleStyleStore` persists through the kit's [`IStorage`](/nomercy-player-core/plugins-adapters/adapter-storage) port, under the key `'subtitle-style'`. That is the same swappable storage interface the kit's plugins persist their preferences through via `this.storage`. The key is namespaced automatically when the storage backend itself is namespaced.

The constructor takes an `IStorage` instance directly, not the player. The player has no public accessor for its own active storage adapter; only plugin code reaches it, via `this.storage`. Construct the store with the same instance passed to `setup({ storage })`, or with a fresh `LocalStorageBackend` (the kit's own default) when `setup()` didn't override it:

```ts
import { StorageBackedSubtitleStyleStore } from '@nomercy-entertainment/nomercy-video-player';
import { LocalStorageBackend } from '@nomercy-entertainment/nomercy-player-core';

const store = new StorageBackedSubtitleStyleStore(new LocalStorageBackend());
```

## Wiring it end to end

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player';

const player = nmplayer('player');

await player.ready();

const saved = await store.load();
if (saved) player.subtitleStyle(saved);

player.on('subtitleStyle', (style) => {
  void store.save(style);
});
```

`load()` returns `Partial<SubtitleStyle>`, not the full shape, because a store might only have persisted a subset of fields across app versions. `player.subtitleStyle(patch)` already merges a partial onto the current style. Passing the loaded value straight through is correct even when it's incomplete.

## Rules & restrictions

- The player never calls any of these three methods itself. Wiring load-on-ready and save-on-change is the consumer's responsibility, the same pattern as [Recipe: Swap an Adapter](/nomercy-player-core/recipes/swap-an-adapter) for other kit-level ports.
- `clear()` only removes the persisted record. It does not reset the live `subtitleStyle()` value. For a "reset to defaults" action that also changes the rendered subtitles, call `player.subtitleStyle(defaultStyle)` alongside it.

## How to extend it

Implement the three methods against a remote store for cross-device sync, or any other backing store you already have:

```ts
class ApiSubtitleStyleStore implements ISubtitleStyleStore {
  async load(): Promise<Partial<SubtitleStyle> | null> {
    return fetchUserPreference('subtitleStyle');
  }

  async save(style: SubtitleStyle): Promise<void> {
    await saveUserPreference('subtitleStyle', style);
  }

  async clear(): Promise<void> {
    await deleteUserPreference('subtitleStyle');
  }
}
```
