# Adapter: Thumbnail Source

A scrub preview asks one question thousands of times: what image belongs at this second. `cls IThumbnailSource` is the port that answers it, loaded once per item and read synchronously from then on, because a pointer moving across the scrubber cannot wait on a fetch.

`cls VttSpriteThumbnailSource` is the implementation the package ships, and it reads the item's `key previewSpriteUrl`. Implement the port yourself when your frames come from somewhere else, and call it from your own scrubber.

## The interface

```ts
interface IThumbnailSource {
  /** Fetch and cache here. false means this item has no preview. */
  load(item: BasePlaylistItem): Promise<boolean>;

  /** The frame covering timeSeconds, or null. Synchronous. */
  lookup(timeSeconds: number): ThumbnailFrame | null;

  /** Drop the cache. */
  unload(): void;
}
```

A `cls ThumbnailFrame` names both an image and the rectangle to show from it, so one sprite sheet covers a whole film and a per-frame source fits the same shape.

```ts
interface ThumbnailFrame {
  spriteUrl: string; // the image to paint
  x: number; // left offset inside it, in pixels
  y: number; // top offset inside it, in pixels
  w: number; // width of the sub-region
  h: number; // height of the sub-region
  start: number; // cue start, in seconds
  end: number; // cue end, in seconds
}
```

## The shipped implementation

`cls VttSpriteThumbnailSource` fetches the WebVTT manifest at `key previewSpriteUrl`, parses it, preloads the sprite image, and then answers from memory.

Each cue body is an image reference with a media fragment, `sprite.webp#xywh=x,y,w,h`. That is what the NoMercy media server's sprite generator writes, and it is the same convention ffmpeg tiling output and other web players use.

Sintel's manifest in the docs catalog, `str Films/Sintel.(2010)/thumbs_256x109.vtt`, holds 89 cues, one every ten seconds, each a 256 by 109 tile. `fn lookup` at 45 seconds answers with x 1024 and y 0.

Every cue carries its own image URL, so a set that spills across several sheets works without anything extra.

Nothing calls a source on your behalf, so the load is yours to place. `str mediaReady` fires at the end of every successful load, which is where it belongs.

```ts
import type { VideoPlaylistItem } from '@nomercy-entertainment/nomercy-video-player';
import nmplayer, { VttSpriteThumbnailSource } from '@nomercy-entertainment/nomercy-video-player';

const player = nmplayer('player');
const thumbnails = new VttSpriteThumbnailSource();

const preview = document.createElement('div');
document.body.append(preview);

player.on('mediaReady', async () => {
  const item = player.item();
  if (!item?.previewSpriteUrl)
    return;

  const resolved = await player.resolveUrl(item.previewSpriteUrl, 'sprite');
  const absolute: VideoPlaylistItem = { ...item, previewSpriteUrl: resolved.href };

  await thumbnails.load(absolute);
});
```

Painting is four style writes: the sheet as a background, the frame's own corner as the offset, and the frame's size as the box.

```ts
function paint(timeSeconds: number): void {
  const frame = thumbnails.lookup(timeSeconds);
  if (!frame)
    return;

  preview.style.backgroundImage = `url('${frame.spriteUrl}')`;
  preview.style.backgroundPosition = `-${frame.x}px -${frame.y}px`;
  preview.style.width = `${frame.w}px`;
  preview.style.height = `${frame.h}px`;
}
```

## Where `previewSpriteUrl` comes from

Set it on the item directly, and the field is used as it stands. An item that arrives in the server wire format gets it filled at queue ingest instead, from the `key tracks` entry whose `key kind` is `str thumbnails`. Both shapes end up in the same field.

The field holds whatever you put in it, and `cls VttSpriteThumbnailSource` fetches that string as given. A path written against `key baseUrl` therefore needs absolutizing first, which is what `player.resolveUrl(url, 'sprite')` is for and why the example above goes through it.

## Rules & restrictions

- `fn lookup` past the end of the table answers with the last frame rather than `str null`. A scrubber dragged beyond the final cue keeps showing the closing thumbnail instead of clearing the bubble.
- `str null` therefore means one of two things: no successful `fn load` yet, or `fn unload` since.
- `fn load` answers `false` and never rejects. A missing `key previewSpriteUrl`, a response the server does not answer with a success status, and a manifest whose cues carry no `#xywh` fragment all take that branch.
- The parser keeps only cues carrying that fragment. A manifest of one standalone image per cue produces no frames, so a source of full-size stills is a custom implementation rather than a differently written manifest.
- The default caches one item at a time, and `fn load` clears the previous set before it starts. Call it again on every item change.
- The fetch is a plain `fn fetch` with no `str Authorization` header and no URL resolver behind it. Against a server that requires a credential, implement the port over your own fetch instead.
- `cls DesktopUiPlugin` runs its own sprite path, through the plugin's authenticated fetch, and paints into its own bubble. Its preview and this port are independent, so register the plugin and you already have the feature. See [Plugin: Desktop UI](/nomercy-video-player/plugins-adapters/desktop-ui).

## How to extend it

Implement the three methods against whatever holds your frames. Keep `fn lookup` a scan over a cached array.

```ts
import type { BasePlaylistItem } from '@nomercy-entertainment/nomercy-player-core';
import type { IThumbnailSource, ThumbnailFrame } from '@nomercy-entertainment/nomercy-video-player';

export class ApiThumbnailSource implements IThumbnailSource {
  private _frames: ThumbnailFrame[] = [];

  async load(item: BasePlaylistItem): Promise<boolean> {
    const response = await fetch(`https://api.example.com/thumbnails/${item.id}`);
    this._frames = (await response.json()) as ThumbnailFrame[];

    return this._frames.length > 0;
  }

  lookup(timeSeconds: number): ThumbnailFrame | null {
    const found = this._frames.find(
      frame => timeSeconds >= frame.start && timeSeconds < frame.end,
    );

    return found ?? null;
  }

  unload(): void {
    this._frames = [];
  }
}
```

A source that returns one full-size still per cue puts that still's URL in `key spriteUrl`. Leave `key x` and `key y` at zero, and set `key w` and `key h` to the image's own size. The painting code above then draws it whole.
