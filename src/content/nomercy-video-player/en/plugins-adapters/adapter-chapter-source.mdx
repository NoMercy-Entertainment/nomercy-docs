# Adapter: Chapter Source

`IChapterSource` is a small contract for chapter lookup. Load once per item, then answer "which chapter is active at this time" synchronously. The lookup is cheap enough to call on every scrubber hover.

Unlike [Adapter: Video Backend](/nomercy-video-player/plugins-adapters/adapter-video-backend), it is not a `setup()` config field. The player's own `chapters()`, `chapter()` and `seekToChapter()` read `item.chapters` directly and never consult this interface. See [Chapters](/nomercy-video-player/tour/chapters).

It exists for two things: custom UI that wants the same lookup shape without re-deriving it, and chapter data that does not live on the item.

## The interface

```ts
interface IChapterSource {
	/** Called after loadedmetadata. Fetch/cache here so current() is synchronous. */
	load(item: BasePlaylistItem): Promise<Chapter[]>;

	/** Chapter active at timeSeconds, or null outside every chapter's range. Synchronous. */
	current(timeSeconds: number): Chapter | null;

	/** The complete chapter list for the current item. Synchronous. */
	all(): Chapter[];

	/** Release cached data. Called on unload/dispose. */
	unload(): void;
}
```

## The shipped implementation

`VttChapterSource` reads straight from `item.chapters`.

That field is either populated by a consumer as canonical `ChapterRef[]`, or derived by `normalizePlaylistItem` from the server's millisecond-based `chapters` array at queue-ingest time. See [The Queue & Playlist](/nomercy-video-player/tour/queue).

It fetches and parses nothing. The list is already resolved by the time `load()` runs, and this class only does the synchronous `current(time)` lookup on top of it:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player';

const player = nmplayer('player');

const source = new VttChapterSource();
await source.load(player.item()!); // caches item.chapters
const active = source.current(player.time()); // Chapter | null, no async lookup
```

## Rules & restrictions

- `load()` returns an empty array for an item with no `chapters` field. That is a legitimate "no chapters" state, not an error.
- `current()` and `all()` stay synchronous in any implementation. They are called from hot paths, scrubber hover and `timeupdate`-driven UI, where an `await` shows as lag.
- `DesktopUiPlugin` does not use it either. Its chapter-marker rendering reads `player.chapters()` directly, the same source of truth this adapter's default reads, without going through the interface.

## How to extend it

Implement the four methods when your chapter data comes from a source `normalizePlaylistItem` does not cover. That means a chapters endpoint separate from the item payload, or a format your server does not ship as the item's `chapters` field:

```ts
class ApiChapterSource implements IChapterSource {
  private chapters: Chapter[] = [];

  async load(item: BasePlaylistItem): Promise<Chapter[]> {
    this.chapters = await fetchChaptersFromApi(item.id);
    return this.chapters;
  }

  current(timeSeconds: number): Chapter | null {
    return this.chapters.find((c) => timeSeconds >= c.start && timeSeconds < c.end) ?? null;
  }

  all(): Chapter[] {
    return this.chapters;
  }

  unload(): void {
    this.chapters = [];
  }
}
```

Call `load()` yourself from a `'mediaReady'` listener in your own overlay code. No automatic hook invokes it.
