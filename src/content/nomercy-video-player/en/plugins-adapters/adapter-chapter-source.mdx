# Adapter: Chapter Source

Chapters reach the player on the item. `player.chapters()` reads the list the active queue entry carries. The queue fills that field from the item's own `key chapters` array, or from a sidecar WebVTT track it fetches on the way in. [Chapters](/nomercy-video-player/tour/chapters) is that surface, and it needs nothing from this page.

`cls IChapterSource` is the same lookup shaped as a port you hold: load once per item, then answer "which chapter covers this second" with no await in the way. Implement it when the chapter data lives somewhere the item does not reach, such as an endpoint of your own, and call it from your own overlay code.

## The interface

```ts
interface IChapterSource {
  /** Fetch and cache here, so current() can stay synchronous. */
  load(item: BasePlaylistItem): Promise<Chapter[]>;

  /** The chapter covering timeSeconds, or null. Synchronous. */
  current(timeSeconds: number): Chapter | null;

  /** The whole list for the current item. Synchronous. */
  all(): Chapter[];

  /** Drop the cache. */
  unload(): void;
}
```

A `cls Chapter` is what both methods hand back, and it is the kit's own type, re-exported from the video package root and aliased there as `cls ChapterRef`.

```ts
interface Chapter {
  index: number; // zero-based position in the list
  start: number; // seconds
  end: number; // seconds
  title: string;
  synthetic?: boolean; // present only on a filler the player generated
}
```

## The shipped implementation

`cls VttChapterSource` reads the item's typed `key chapters` array and caches it. It fetches nothing of its own, so what this class adds is the position lookup over a list the queue has already put on the item.

```ts
import nmplayer, { VttChapterSource } from '@nomercy-entertainment/nomercy-video-player';

const player = nmplayer('player');
const chapters = new VttChapterSource();

await player.ready();

const item = player.item();
if (item)
  await chapters.load(item);

const active = chapters.current(player.time()); // Chapter | null
```

## Rules & restrictions

- `fn current` matches a chapter when the time is at or after its `key start` and strictly before its `key end`. So a gap between two chapters answers `str null`, and so does the last chapter's own `key end` and anything past it.
- `fn all` hands back the item's own array rather than a copy. Sort or splice the result and you have changed the queue entry.
- `fn load` answers with an empty array for an item carrying no `key chapters`. That is a film without chapter marks, not a failure.
- A `key tracks` entry with `kind: 'chapters'` is the queue's ingest path, not this class's. `cls VttChapterSource` handed an item that carries only that sidecar answers with an empty array.
- The player's malformed-list safety net, which backfills uncovered spans and marks them `key synthetic`, runs over the queue entry. A list you return from this port is used exactly as you returned it.
- `fn current` and `fn all` stay synchronous in any implementation. They run on every `str time` tick and every scrubber hover, where an await shows as lag.

## How to extend it

Implement the four methods against whatever holds your chapter data. Fetch and cache in `fn load`, and keep the two readers a plain scan over the cache.

```ts
import type { Chapter, IChapterSource, VideoPlaylistItem } from '@nomercy-entertainment/nomercy-video-player';

export class ApiChapterSource implements IChapterSource {
  private _chapters: Chapter[] = [];

  async load(item: VideoPlaylistItem): Promise<Chapter[]> {
    const response = await fetch(`https://api.example.com/chapters/${item.id}`);
    this._chapters = (await response.json()) as Chapter[];

    return this._chapters;
  }

  current(timeSeconds: number): Chapter | null {
    const found = this._chapters.find(
      chapter => timeSeconds >= chapter.start && timeSeconds < chapter.end,
    );

    return found ?? null;
  }

  all(): Chapter[] {
    return this._chapters;
  }

  unload(): void {
    this._chapters = [];
  }
}
```

Nothing calls a source on your behalf, so the three call sites are yours to place.

`str mediaReady` fires at the end of every successful load, which is where the fetch belongs. `str time` carries the position on every media tick, so a label follows playback there. `str item` fires when the queue cursor moves, which is where the old cache goes.

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player';

import { ApiChapterSource } from './api-chapter-source';

const player = nmplayer('player');
const chapters = new ApiChapterSource();

const label = document.createElement('span');
document.body.append(label);

player.on('mediaReady', () => {
  const item = player.item();
  if (!item)
    return;

  void chapters.load(item);
});

player.on('time', (state) => {
  label.textContent = chapters.current(state.time)?.title ?? '';
});

player.on('item', () => {
  chapters.unload();
});
```
