# Plugin: Desktop UI — Labels

`cls DesktopUiPlugin` draws no hardcoded English. Every tooltip, menu row, shortcut name and status message it shows comes from a translation key, and `packages/player-web/nomercy-video-player/src/plugins/desktop-ui/i18n/en.ts` is the canonical set.

`cls DesktopUiTranslationKey` is derived from that file, so every sibling `<tag>.ts` in the folder is typed against exactly those keys. A locale missing one, or carrying one English doesn't have, fails to compile.

This page lists the keys by group. For the options and buttons the overlay itself accepts, see [Plugin: Desktop UI](/nomercy-video-player/plugins-adapters/desktop-ui).

## How a locale loads

{/* partial */}
```ts
static override readonly translations: Translations = translationsFromGlob('./i18n/*.ts');
```

That call is a literal string a Vite plugin rewrites at build time into `import.meta.glob('./i18n/*.ts')` — without `str { eager: true }`. Loading is lazy: only the active language's file, and its BCP-47 parents, is ever fetched. A visitor reading Dutch never pulls in the other 78.

Nothing registers a language by hand either way. Adding a file to the folder is what adds the language — discovered at build time, even though it only loads later.

`str token-bundle.ts` is the one exception, and it is not a language file. `cls NMVideoPlayer` needs the three `key plugin.desktop-ui.token.*` keys — the `%S<n>` / `%E<n>` title-prefix tokens — at queue-ingest time, before it knows whether `cls DesktopUiPlugin` will even be added.

That bundle seeds those three keys standalone, for every language, so token resolution never waits on the plugin's own lazy load. It does not duplicate the rest of the set.

**Navigation** — `key plugin.desktop-ui.shortcuts.next` (Next item), `key plugin.desktop-ui.shortcuts.previous` (Previous item), `key plugin.desktop-ui.shortcuts.nextChapter` (Next chapter), `key plugin.desktop-ui.shortcuts.previousChapter` (Previous chapter).

Five keys carry no group heading, kept for backwards compatibility with an older shortcuts layout rather than for the current one: `key plugin.desktop-ui.shortcuts.seekBackForward`, `key plugin.desktop-ui.shortcuts.volumeUpDown`, `key plugin.desktop-ui.shortcuts.theater`, `key plugin.desktop-ui.shortcuts.pip`, `key plugin.desktop-ui.shortcuts.chapters`. A custom overlay reading the dialog's own row set does not need them; something reading the raw translation bundle still finds them there.

## Adding or overriding a language

Add a file named for the [BCP 47](https://en.wikipedia.org/wiki/IETF_language_tag) tag — `str fr.ts`, `str pt-BR.ts` — default-exporting an object literal typed `str satisfies Record<DesktopUiTranslationKey, string>`, the same shape every shipped file uses.

That `str satisfies` is what makes a stray key or a missing one a compile error rather than a silent gap. The object has to carry the full 113, not a subset.

Overriding one key in a shipped language without hand-copying the other 112 still needs the full set to satisfy that type. Spread the language's own default export as a base and your replacement over it, and the result carries every key even though you only wrote one.

The glob picks the file up either way; nothing else needs to know it exists.

```ts
import base from './nl';
export default { ...base, 'plugin.desktop-ui.menu.reset': 'Herstellen' } satisfies Record<DesktopUiTranslationKey, string>;
```
