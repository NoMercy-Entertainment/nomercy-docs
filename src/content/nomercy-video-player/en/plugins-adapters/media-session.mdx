# Plugin: Media Session

`cls MediaSessionPlugin` (id `str media-session`) puts the playing video item on the operating system's "Now Playing" surface: the lock screen, the notification shade, hardware media keys and Bluetooth remotes.

It is a one-method subclass of the kit's [`cls MediaSessionPlugin`](/nomercy-player-core/plugins-adapters/media-session), which owns the `ts navigator.mediaSession` wiring, the action handlers and the position reporting. This page covers the one thing the video subclass decides, which is the text a `cls VideoPlaylistItem` produces.

## Registering it

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player';
import { MediaSessionPlugin } from '@nomercy-entertainment/nomercy-video-player/plugins/media-session';

const player = nmplayer('player');

player.addPlugin(MediaSessionPlugin);
player.setup({ playlist: [] });
await player.ready();
```

## The three text fields

| Field | Video source |
|---|---|
| `key title` | `key title`, or an empty string when the item has none |
| `key artist` | `key show`, or an empty string. A film carries no show, so this field is empty for one. |
| `key album` | the season label, built with `fn t` from the `str season` key, whose English string is `str Season {season}`. An item with no `key season` gets an empty string. |

The season label is translated. The subclass ships a bundle for 79 locales, discovered by `fn translationsFromGlob`, so the lock screen follows the player's language rather than always reading English.

## Where the artwork comes from

The base class picks it, not this subclass. It reads the first of `key image`, `key poster`, `key thumbnail` and `key cover` that the item defines, resolves that one through `fn resolveUrl` under the `str poster` category, and publishes it as a single 512x512 artwork entry with a MIME type guessed from the URL.

An item with none of the four publishes text and no artwork.

The chain stops at the first field the item defines rather than the first non-empty one, so leave a field out instead of setting it to an empty string.

## How to extend it

Override `fn getMetadata` when your items carry fields beyond the canonical shape. Calling up to the base gives you the three fields above to build on:

```ts
import { MediaSessionPlugin } from '@nomercy-entertainment/nomercy-video-player/plugins/media-session';
import type { VideoPlaylistItem } from '@nomercy-entertainment/nomercy-video-player';

interface ArchiveItem extends VideoPlaylistItem {
  year?: number;
}

class ArchiveMediaSession extends MediaSessionPlugin<ArchiveItem> {
  protected override getMetadata(item: ArchiveItem) {
    const base = super.getMetadata(item);
    return { ...base, album: item.year ? `${base.album} (${item.year})`.trim() : base.album };
  }
}
```

`fn getMetadata` returns the text only. Artwork is resolved separately by the base class, so an override never has to build the `key artwork` array.
