# Quality Levels

Adaptive bitrate is on by default. `hls.js` (or Safari's native HLS) keeps switching renditions to match bandwidth without you doing anything. This page is for when you want a manual quality menu on top of that.

## Listing levels

Once the `'levels'` event has fired, `qualityLevels()` returns the manifest's bitrate renditions. Each entry carries `bitrate`, plus `height`/`width` when the manifest provides them.

`qualityLevels({ includeUnsupported: true })` also returns renditions the current device cannot decode. That lets a menu show them disabled rather than hide them entirely:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player';

const player = nmplayer('player');

const levels = player.qualityLevels(); // QualityLevel[]
const withUnsupported = player.qualityLevels({ includeUnsupported: true });
```

## Reading and setting the selection

`quality()` reads the current level, `{ index, track }` when picked manually or the string `'auto'` when ABR is driving. `quality(idx)` locks a specific level, `quality('auto')` hands control back to the backend:

```ts
player.quality(0); // lock the first (usually lowest) rendition
player.quality('auto'); // back to adaptive
```

Setting a level emits two events, each suited to a different UI need: `'quality:requested'` fires immediately, before the backend confirms, for a UI that must reflect the request instantly. `'level-switched'` fires once the backend actually applies the switch, for a "now playing at 1080p" toast. Full signatures and payloads are on [Reference: Video Player Methods](/nomercy-video-player/reference/player-methods#track-selection) and [Reference: Events](/nomercy-video-player/reference/events#quality--tracks).

## Default quality

`defaultQuality` on `VideoPlayerConfig` applies once, after the first manifest parse. It takes `'auto'` or a fixed level index. `'auto'` is already the kit's own default, so setting it explicitly is only useful for readability:

```ts
player.setup({
  baseUrl,
  playlist: [item],
  defaultQuality: 'auto',
});
```

## Bandwidth and capability checks

`bandwidth()` reads the backend's current throughput estimate, the number ABR decides against. `canPlay(profile)` asks the platform's `MediaCapabilities` whether a content profile (`contentType`, resolution, bitrate, framerate) is decodable, ask it before offering a level in a menu. `bandwidthEstimator(fn)` replaces the estimator with your own, useful for a measurement shared across several players on one page.

These three are shared kit surface, not video-specific. Full signatures are on [Reference: Metrics, Clock & Accessibility](/nomercy-player-core/reference/metrics-and-accessibility#bandwidth--capability-checks).
