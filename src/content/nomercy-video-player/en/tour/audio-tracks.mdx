# Audio Tracks

One item can carry more than one audio rendition.
A second language, a commentary, a stereo mix beside a surround one.

The player reads that list off the source and lets you move between the entries.
It never invents a track and it never mixes two.

## Where the list comes from

`audioTracks()` returns what the mounted backend can see.

```ts
const tracks = player.audioTracks();
```

An HLS manifest hands over its audio renditions.
Anything the browser plays on its own hands over what `HTMLMediaElement.audioTracks` holds.
Chrome does not implement that property at all, so on Chrome the native path has nothing to read.

A source with no HLS manifest and no native track list returns an empty list.
That is the ordinary answer rather than a failure.
Where the native list does exist, a single-audio file yields one entry, not none.

Each entry is an `cls AudioTrack`.

| Field | What it holds |
| --- | --- |
| `key id` | An identifier within this source. For HLS it is `str audio-0`, `str audio-1`, and so on. |
| `key language` | The tag the source declares, when it declares one. |
| `key label` | Text to show: the rendition's own name, or `str Track 1` when it has none. |
| `key default` | `true` on the rendition the source marks as its default. |

## When the list is populated

`audioTracks()` reads the mounted backend, so it holds nothing until that backend has the item's media.

The load path emits `mediaReady` at that point, and that is where the player applies `key defaultAudioLanguage`.
A menu drawn from an `audioTracks()` call there, or at the moment a viewer opens it, reads the list the player itself read.

## Switching

```ts
await player.audioTrack(1);
```

The argument is a position in the list `audioTracks()` just returned.
It is not the `key id`, and the two are not interchangeable.

The call returns a promise because a listener sees the request first.
`beforeAudioTrack` carries the requested position and can cancel it, which raises `audioTrackPrevented` and leaves the current track playing.
Awaiting the call is how you know that whole cycle finished.

Called with nothing, `audioTrack()` reads back `{ index, track }`, or `null` when no track has been picked yet.

## The choice is a language, never a position

The player takes the language off the track and keeps that, for the reason [Subtitles & Text Tracks](/nomercy-video-player/tour/subtitles) sets out for captions.
Both selections share one memory.

**The event payload's field is called `key id`, and it carries a position.**
That is the published name, and it is the same position `audioTrack()` takes, so index the list with it rather than searching for a track whose `key id` matches.

```ts
player.on('audioTrack', ({ id }) => {
  const chosen = id === null ? undefined : player.audioTracks()[id];
  remember(chosen?.language);
});
```

Your own code wants the same key: read `key language` off the track, and let the next item find its own position.

## Choosing before the viewer does

`key defaultAudioLanguage` names the language you want the item to open in.

```ts
player.setup({
  baseUrl,
  playlist: [item],
  defaultAudioLanguage: 'eng',
});
```

The player applies it once the media for that item is ready.

Matching is exact first, then a prefix split on a hyphen.
So `str en` answers a track tagged `str en-US`, and `str en-US` answers one tagged `str en`.

It is not a prefix on letters.
`str en` does not answer a track tagged `str eng`, so pass the tag the source itself declares.
The Sintel manifest below declares `str eng`.

A remembered choice outranks this option.
Once a viewer picks a track, that language is what the next item opens in.
With nothing to honor, the rendition the source marks default is the one that plays.

## Which one is driving

`audioTrackMode()` reports `cls AudioTrackState.DEFAULT` until a track is explicitly picked, and `cls AudioTrackState.MANUAL` after.
The move is announced on the `audioTrackState` event.

A control offering to undo the choice reads this first, so it can stay hidden while there is nothing to undo.

## Walking the list

`cycleAudioTracks()` moves to the next entry and wraps from the last one back to the first.

There is no off position here, because something is always audible.
That is the one place it parts company with the subtitle cycle, which walks through off.

It does nothing at all when the list is empty.

## See it running

The Sintel manifest declares one audio rendition, in `str eng`, marked as its default.
`audioTracks()` therefore returns a single entry here, and every call above behaves the same way against it as against a manifest carrying six.
