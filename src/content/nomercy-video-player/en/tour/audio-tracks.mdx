# Audio Tracks

An HLS manifest can carry more than one audio rendition per item:

- alternate languages
- a commentary track
- a stereo/5.1 pair

`audioTracks()` and `audioTrack()` mirror the subtitle surface from [Subtitles & Text Tracks](/nomercy-video-player/tour/subtitles) exactly. They use the same index-based selection, the same `Current*Selection` shape, and the same auto-select config field.

## Listing and selecting

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player';

const player = nmplayer('player');

const tracks = player.audioTracks(); // AudioTrack[]: { id, language?, label }
const current = player.audioTrack(); // { index, track } | null

await player.audioTrack(1); // switch to the second rendition
```

Unlike subtitles, audio tracks have no "off" state. Once the manifest resolves, one track is always active. Because there is no off position to land on, `cycleAudioTracks()` walks the list and wraps around at the end instead of stopping.

## Default language

Once the manifest parses, `defaultAudioLanguage` on `VideoPlayerConfig` auto-selects a track. It uses the same BCP-47 exact-then-prefix matching as `defaultSubtitleLanguage`:

```ts
player.setup({
  baseUrl,
  playlist: [item],
  defaultAudioLanguage: 'jpn',
});
```

## Reading the selection mode

`audioTrackMode()` reports which one is driving the current choice:

| Mode | Meaning |
| --- | --- |
| `AudioTrackState.DEFAULT` | No explicit choice has been made yet. The backend's own default rendition is active. |
| `AudioTrackState.MANUAL` | A consumer or preference plugin has picked a track. |

A "reset to default" menu item reads this mode before deciding whether to show itself.
