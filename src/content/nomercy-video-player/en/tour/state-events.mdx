# Playback State & Events

A UI reads state two ways. Pull a typed reader when you need a value right now. Or subscribe once and let the player push updates.

Both ways come from the kit. Video only adds the events specific to its own medium on top.

## Typed state readers

These come straight from `nomercy-player-core` (see [Core: Time & State](/nomercy-player-core/tour/time-and-state) for the full contract) and work identically here. Each one returns a typed enum value or a snapshot object, never a raw string to compare by hand.

The full [state enum list](/nomercy-player-core/reference/types#state-enums) and the [`TimeState` shape](/nomercy-player-core/reference/types#time--tracks) `timeData()` returns are on Reference: Domain Types. `volumeState()` is the one a mute-icon component reads most, see [Volume](/nomercy-video-player/tour/volume).

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player';
import { PlayState } from '@nomercy-entertainment/nomercy-video-player';

const player = nmplayer('player');

if (player.playState() === PlayState.PLAYING) {
  // ...
}

const { position, duration, percentage } = player.timeData();
```

## Video-specific events

Most of what follows is unique to `VideoEventMap`, layered over the kit's `BaseEventMap`. That base carries transport, queue, volume, and i18n. Every tour page so far has covered those events.

Three rows are the exception. `firstFrame`, `level-switched` and `subtitleCue` are `BaseEventMap` members, listed here because they matter most in a video context. The music player and a raw core consumer see the same three.

The events fall into a handful of groups: playback signals (`firstFrame`, `waiting`/`canplay`/`stalled`), quality and track population (`levels`, `audioTracks`), subtitle cues, display state (`fullscreen`, `pip`, `theater`, `aspectRatio`, `videoRect`), segment boundaries, and OSD/navigation intents (`display-message`, `back`, `close`). Every name, payload shape, and firing condition is on [Reference: Events](/nomercy-video-player/reference/events).

```ts
player.on('levels', ({ levels }) => {
  // populate a quality menu now that the manifest is parsed
});

player.on('fullscreen', ({ active }) => {
  // sync a fullscreen button's icon
});
```

`videoRect()` and its event exist for overlay plugins:

- subtitles
- a letterbox border
- a click-to-seek layer

Under `object-fit: contain`, they let the overlay align to the actual painted video area. The container is the wrong target, because it includes the letterbox padding.
