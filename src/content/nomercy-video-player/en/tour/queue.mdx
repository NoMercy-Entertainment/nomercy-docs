# The Queue

A video queue is the kit's queue: an ordered list of items with a cursor on one of them.

`queue()`, `item()` and every list method behave as [Core: The Queue](/nomercy-player-core/tour/queue) describes them.
This player changes none of it.

What is video's own is when the cursor moves without you, what is fetched before it moves, and what the player rewrites on the way in.
Where the cursor starts is the fourth, and [How It Works](/nomercy-video-player/tour/how-it-works) has it.

## When the cursor moves on its own

At the natural end of an item the player calls `next()` itself.
This is on by default, and `autoAdvance: false` turns it off.

Turn it off when something else already drives `next()`, such as a Cast session or a socket-driven one.
Two things advancing one queue moves it two items.

The music player has no equivalent default.
Auto-advance there is a plugin you register.

## What is fetched before the cut

Ten seconds before the current item ends, the player asks for the next item's assets.

`cls VideoPreloadStrategy` decides what those are: the media URL, the poster, the preview sprite, each subtitle sidecar, chapter sidecars and ASS font manifests.
`key preloadLeadSeconds` moves the ten seconds.

Each asset gets one `HEAD` request, and the run announces itself through `preloadStart`, `preloadProgress` and `preloadComplete`.
The move between two items is a hard cut.

## Items are reshaped on the way in

Every item passes through `fn normalizePlaylistItem` as it enters the queue, so a media server payload goes in as it arrives.
`key file` becomes `key url`, a duration string becomes seconds, millisecond chapter cues become seconds, and a `str thumbnails` track becomes `key previewSpriteUrl`.

The pass is not a no-op on canonical items.
`key fonts` is rebuilt from each entry's `key file` alone, so a `key label` on a font does not survive it.
Every other canonical field is carried through as you wrote it.
