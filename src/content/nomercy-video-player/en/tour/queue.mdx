# The Queue & Playlist

Behind `queue()` is one cursor-aware `MediaList<T>` instance. It is the same structure [Core: The Queue](/nomercy-player-core/tour/queue) documents. `nomercy-video-player` adds two things: the item shape (`VideoPlaylistItem`) and a normalizer that accepts the server's wire format directly. All the queue mechanics stay unchanged kit code.

## Setting the playlist

`playlist` on `VideoPlayerConfig` accepts an array of items inline (or a URL string, fetched and parsed at setup). Every item's media path stays relative, and `baseUrl` supplies the origin. This is the pattern [Quick Start](/nomercy-video-player/quickstart#the-baseurl-pattern) introduces:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player';

const player = nmplayer('player');
player.setup({
  baseUrl: 'https://raw.githubusercontent.com/NoMercy-Entertainment/nomercy-media/master/Films',
  playlist: [
    { id: 'sintel', title: 'Sintel', url: '/Sintel.(2010)/Sintel.(2010).NoMercy.m3u8' },
    { id: 'big-buck-bunny', title: 'Big Buck Bunny', url: '/Big.Buck.Bunny.(2008)/Big.Buck.Bunny.(2008).NoMercy.m3u8' },
  ],
});
```

`file` (not `url`) is accepted here because `normalizePlaylistItem` reshapes the v1/server wire format into the canonical `VideoPlaylistItem` on ingest. The real media server's response goes through the same normalization. Pass canonical items (`url` instead of `file`) directly and they pass through unchanged.

## Reading, moving, and mutating the queue

Reading the cursor, moving it, and mutating the queue (append, prepend, insert, remove, move, clear, shuffle, sort) are all unchanged kit methods. `playItem(target)` and `playNow(items, start?)` are the race-free way to jump to an item and play it in one call, closing a gap where `queue(items); item(start); play()` can reach the backend before the source is even set.

Every mutation fires a typed event (`queue:append`, `queue:move`, ...) that a reactive playlist UI subscribes to instead of re-reading `queue()` after every call. The full method list, signatures, and event names are on [Reference: Domain Types](/nomercy-player-core/reference/types#queue-methods).

```ts
const items = player.queue(); // ReadonlyArray<VideoPlaylistItem>
const current = player.item();
player.item('big-buck-bunny'); // by id
player.item(1); // by index

player.playNow(films, 'big-buck-bunny'); // replace the queue and start playing this item
player.playItem('sintel'); // jump to an item already in the queue and play it
```

`peekNext()` / `peekPrevious()` read what `next()` / `previous()` (see [Transport](/nomercy-video-player/tour/transport)) would load. They do not move the cursor or trigger a load. That makes them right for a "coming up next" thumbnail.
