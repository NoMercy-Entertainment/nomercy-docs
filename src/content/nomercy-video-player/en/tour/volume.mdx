# Volume

The player's volume is one number between 0 and 100.
That number is a position on a slider, not a gain.
What reaches the video element is a curve applied to it.

## Setting the level

Call `fn volume` with a number once [`ready()`](/nomercy-video-player/quickstart) has resolved.

```ts
await player.volume(50);
```

The value is clamped, so `volume(140)` lands on 100 and `volume(-20)` lands on 0.
The call returns a promise that resolves once the new level has reached the backend.

`volume()` with no argument reads the level back.

```ts
const level = player.volume(); // 50
```

`volumeUp()` and `volumeDown()` move the level by five points.
Pass a number for a different step, as in `volumeUp(10)`.
Both clamp the same way, and neither hands you a promise to await.

Until the first `fn volume` call the video element runs at full output.
Set the level yourself after `ready()` if you want playback to start anywhere but the top.

## The curve between the two numbers

The number you set is a position.
The number the browser applies is that position on a 0-to-1 scale, squared.

```
gain = (level / 100) ** 2
```

| `volume(level)` | `element.volume` |
| --- | --- |
| 100 | 1 |
| 75 | 0.5625 |
| 50 | 0.25 |
| 25 | 0.0625 |
| 0 | 0 |

So halfway up the slider is a quarter of the amplitude.

The reason is that loudness is not heard on a linear scale.
Map the slider straight onto the gain and almost the whole audible range piles into the bottom third of the travel.
The squared taper spreads the change out, so a step of five sounds about the same size anywhere on the travel.

The curve is applied at the last moment, where the gain is written to the media element.
Everything above that point works in positions.
`volume()` therefore answers with the position, never the gain, so an interface reading `element.volume` and one reading `volume()` show different numbers for the same output.

## Muting

`mute()` silences the output and keeps the level.
`unmute()` brings the sound back at the level that was set.
`toggleMute()` flips between the two.

```ts
await player.mute();
await player.unmute();
player.toggleMute();
```

`volume()` reports 0 for as long as the player is muted, and the stored level is not lost.
`volumeState()` is what tells those two apart.
It returns `cls VolumeState.MUTED` or `cls VolumeState.UNMUTED`, whose values are the strings `str muted` and `str unmuted`.

```ts
import { VolumeState } from '@nomercy-entertainment/nomercy-video-player';

if (player.volumeState() === VolumeState.MUTED) {
  // draw the muted icon
}
```

Setting a level while muted lifts the mute.
`volume(40)` on a muted player unmutes it, then applies the level.
That is what makes a slider drag work while the mute button is on.
A mute icon should therefore read `volumeState()` rather than keep a boolean of its own.

**A level of 0 is not a mute.**
`volume(0)` writes a gain of zero and leaves `volumeState()` at `str unmuted`, so there is nothing for `unmute()` to undo.
Reach for `mute()` whenever you want the level held for later.

**Mute right after `setup()` to start a player silent.**

```ts
player.setup(config);
await player.mute();
```

The element comes up silent, `volumeState()` reads `str muted`, and `unmute()` hands the sound back on the viewer's first gesture.

## What a listener sees

`volume` fires with `{ level }` on every change, including each step of `volumeUp()`.
`mute` fires with `{ muted }` on every mute and unmute, including the one that lifting a mute produces.
Subscribe to those rather than polling the getters from a render loop.

`beforeVolume` and `beforeMute` run first, and either can be canceled.

```ts
player.on('beforeVolume', (event) => {
  if (event.data.level > 80) event.preventDefault();
});
```

A canceled change leaves the level and the mute state untouched.
`volumePrevented` or `mutePrevented` fires instead, carrying `reason: 'listener-prevented'`.
`beforeMute` is not dispatched at all when the player is already in the state being asked for.
