# Volume

Volume is another kit surface `nomercy-video-player` inherits unchanged. There is no video-specific volume behavior. The backend just needs a real `<audio>`/`<video>` gain to move.

## Reading and setting the level

`volume()` reads the current level as a number in `[0, 100]`. `volume(level)` sets it, clamped to that range. The setter returns a `Promise<void>` that resolves once the backend applies it:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player';

const player = nmplayer('player');

const level = player.volume(); // 0-100
await player.volume(50);
```

Set an initial level through `setup({ defaultVolume })`, a number on the same 0-100 scale that defaults to `100`. A player with no `defaultVolume` starts at full gain. So read a saved preference into that config field. Or call `volume()` yourself after `ready()` if you would rather set it later.

## Mute

`mute()` and `unmute()` are absolute; `toggleMute()` flips based on the current state. All three dispatch `beforeMute` first, the same cancellable shape as transport. When the player is already in the target state, they no-op and never dispatch:

```ts
await player.mute();
await player.unmute();
player.toggleMute();
```

`volumeUp(step?)` and `volumeDown(step?)` nudge the level by `step` (`5` by default). The result clamps to `[0, 100]`, the same as a direct `volume()` call. This is the pair a keyboard shortcut or a remote's volume rocker binds to.

## Reading the gain stage

`volumeState()` returns a typed `VolumeState.UNMUTED` or `VolumeState.MUTED`. A mute-icon component reads this value instead of tracking its own boolean. The value stays correct even when something else (a keyboard shortcut, a Connect sync) changes the mute state:

```ts
import { VolumeState } from '@nomercy-entertainment/nomercy-video-player';

if (player.volumeState() === VolumeState.MUTED) {
  // show the muted icon
}
```

Two event pairs carry the payload a listener needs:

| Events | Payload |
| --- | --- |
| `volume` / `beforeVolume` | `{ level }` |
| `mute` / `beforeMute` | `{ muted }` |

Subscribe to those instead of polling the getters from a render loop.
