# Chapters

Chapters come from the item's typed `chapters` field. You can set canonical `ChapterRef[]` (`{ index, start, end, title }`, seconds) directly. Or the item carries the server wire format's millisecond-based `chapters` array, which `normalizePlaylistItem` converts to the canonical shape at queue-ingest time.

`chapters()` is a plain synchronous getter over whatever list is already on the active item. There is no async fetch to wait on.

## Listing and navigating

`chapters()` returns the resolved list. Each entry carries an `index`, a `start` and `end` in seconds, and a display title.

`seekToChapter(idx)` jumps directly. `nextChapter()` and `previousChapter()` step relative to the current position, not the last chapter you explicitly selected. So they stay correct even after a manual scrub:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player';

const player = nmplayer('player');

const list = player.chapters(); // Chapter[]: { index, start, end, title }

player.seekToChapter(2);
player.nextChapter();
player.previousChapter();
```

`chapter()` reads the chapter containing the current position. It returns `null` when none covers it: before the list resolves, or in a gap the safety net has not backfilled.

Only `seekToChapter()` emits `'chapter'` with `{ index, title }`. `nextChapter()` and `previousChapter()` inherit that, because they route through it.

Playback crossing a boundary on its own does not fire the event. To follow the active chapter during ordinary playback, read `chapter()` on each `'time'` tick.

The `'chapters'` event fires once the list resolves.

For an item with no `chapters` field, `chapters()` returns `[]`. A chapter-marker UI can render unconditionally and simply show nothing when the list is empty.

Malformed lists get a safety net.

Once the duration is known, the player backfills any span the list fails to cover:

- a lead-in before the first chapter
- a hole between two chapters
- a tail after the last chapter

Each filler carries a translated fallback title, "Chapter" in English, and `synthetic: true`. So markers and `nextChapter()` always work against a list spanning the whole timeline.

A list that already covers the duration passes through untouched, and an empty list stays empty. The net only catches lists claiming partial coverage.

## Arbitrary time windows

Chapters are one instance of a more general primitive. `playSegment({ startSec, endSec, onEnd })` seeks to `startSec` and watches every `'time'` event for `endSec`. When playback reaches the boundary, `'segmentBoundary'` always fires first. Then `onEnd` decides what happens:

| `onEnd` | Behavior |
| --- | --- |
| `'loop'` | Seek back to `startSec` and keep playing. |
| `'hold'` | Pause at `endSec`, last frame stays visible. |
| `'advance'` | Emit the boundary event and let playback continue naturally. |

```ts
player.playSegment({ startSec: 30, endSec: 45, onEnd: 'loop' }); // a 15s preview loop
player.clearSegment(); // stop watching, no seek or pause
```

This primitive is not chapter-specific. An intro-skip loop, a disc-menu state window, or a highlight-reel scrubber would use the same calls.

When you call `playSegment()` again, the new window replaces any active one immediately. `clearSegment()` stops watching without moving playback.
