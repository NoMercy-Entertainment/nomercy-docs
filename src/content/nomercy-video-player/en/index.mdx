# nomercy-video-player

`nomercy-video-player` is the headless HLS engine that powers video on NoMercy TV.
Video is the hard part of playback: the stream changes bitrate as the network shifts, HDR has to be matched to the display, subtitles come in several formats, and the picture has to keep playing through all of it.
This package does that work and hands you plain events and methods to drive it, with no opinion about your UI.

The player is headless — no built-in UI. You drive it through typed events and methods and render the UI with plugins.

It is built on `nomercy-player-core`, the same core that powers the music player.
Everything that is not specific to video lives down there, the queue, auth, plugins, i18n, and storage, so this package stays small and focused on the hard video parts.

## What you get

- `NMVideoPlayer<T>`, the core class, generic over your own playlist item type.
- `nmplayer(id)`, a factory that creates or returns a named player instance.
- Video adapter ports you can swap when the defaults do not fit: backend, chapter source, thumbnail source, and subtitle style store.
- A full set of built-in plugins, from the desktop UI to subtitle overlays, skip markers, and Chromecast.
- Full TypeScript types for every public method, event, and config option.

## Install

```
npm install @nomercy-entertainment/nomercy-video-player@beta
```

`hls.js` installs automatically with the player (a direct dependency of the player package) — nothing extra to install for the npm / bundler path. See [Installation](/nomercy-video-player/installation) for the CDN exception.

Prefer no build step? The CDN build exposes a `nmplayer` global from a single `<script>` tag, see [Quick Start: CDN embed](/nomercy-video-player/quickstart#cdn-embed-no-bundler).

Everything below `NMVideoPlayer<T>` is generic.
It has zero knowledge of your server API, your item shape beyond the typed fields, or any NoMercy infrastructure.
App-specific glue lives in layer-5 consumer plugins.

## Container class system

The `<video>` element and the state CSS classes on `.nomercyplayer` are core-level concerns, so the player manages them directly through the container-class mixin.
The UI overlay (controls, seek bar, menus) is the job of the optional `DesktopUiPlugin`.

State classes like `playing`, `paused`, and `fullscreen` are applied to the `.nomercyplayer` container by the player core's container-class-emit mixin when state changes.
`DesktopUiPlugin` reads those classes to show and hide UI elements.

The core applies bare state-class names to `.nomercyplayer`: `playing`, `paused`, `buffering`, `active` / `inactive`, `fullscreen`, `muted`, and `ended`, among others. Do not redefine those classes on the container from outside the plugin.

See [Desktop UI](/nomercy-video-player/plugins/desktop-ui) for the full class table.
The exact boundary between core-owned and plugin-owned classes is tracked in the architecture spec, and Spine owns that boundary definition.
