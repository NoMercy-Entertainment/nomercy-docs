# Build a Player: Volume

[Step 2](/nomercy-video-player/build/scrubber) added seeking. This step adds volume, a slider and a mute button, next to it.

## Live, not on release

The scrubber only seeks once the user releases the thumb, seeking mid-drag would spam network requests for segments the user hasn't settled on. Volume has no such cost, apply it on every `input` event so the slider tracks the pointer exactly:

```ts
volumeSlider.addEventListener('input', () => {
  void player.volume(Number(volumeSlider.value)); // see Volume — 0-100, clamped
});
```

## A mute button that can't drift

A naive mute button tracks its own `isMuted` boolean, toggling it in the click handler. That drifts the moment anything else changes mute state, a keyboard shortcut, a Connect sync, another tab. Read `volumeState()` (see [Volume](/nomercy-video-player/tour/volume)) instead, and resync on the `'mute'` event rather than the click:

```ts
import { VolumeState } from '@nomercy-entertainment/nomercy-video-player';

const muteButton = player.createButton('my-mute', 'Mute', () => {
  player.toggleMute(); // the click only requests the change
});

const syncMute = () => {
  const muted = player.volumeState() === VolumeState.MUTED; // the event confirms it
  muteButton.textContent = muted ? '🔇' : '🔊';
  muteButton.setAttribute('aria-label', muted ? 'Unmute' : 'Mute');
};
player.on('mute', syncMute);
syncMute();
```

The click handler only ever *requests* a change; the `'mute'` event is what actually updates the icon, the same pattern Step 1's play/pause button uses for `playState()`.
