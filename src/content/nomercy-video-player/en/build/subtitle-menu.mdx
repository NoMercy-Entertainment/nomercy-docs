# Build a Player: The Subtitle Menu

[Step 3](/nomercy-video-player/build/volume) covered the volume slider. This step turns on the subtitles button and adds the second plugin this tutorial needs — two plugins, two concerns.

## Selection needs a renderer

[Subtitles & Text Tracks](/nomercy-video-player/tour/subtitles) makes the point directly: `subtitle(idx)` only changes selection state. `buttons.subtitles: true` gives `DesktopUiPlugin`'s settings menu a real, live-built subtitle picker — but painting the cue text onto the frame is a separate job, `SubtitleOverlayPlugin`'s alone, shipped as its own subpath so a player that never shows subtitles doesn't pay for it:

{/* partial: the imports + `plugins` property to graft onto setup(), not a standalone program — the complete version is in "See it running" below */}

```ts
import { DesktopUiPlugin } from '@nomercy-entertainment/nomercy-video-player/plugins/desktop-ui';
import { SubtitleOverlayPlugin } from '@nomercy-entertainment/nomercy-video-player/plugins/subtitle-overlay';

plugins: [
  { plugin: DesktopUiPlugin, opts: { buttons: { subtitles: true } } },
  SubtitleOverlayPlugin,
],
```

Neither plugin knows the other exists — both react to the same `subtitle()` selection state on the player. Swap `SubtitleOverlayPlugin` for `OctopusPlugin` (bitmap/ASS subs) and the menu keeps working unchanged; only the renderer underneath it changes.

## Declarative registration, same validation

Both entries resolve through the exact same `addPlugin()` path a manual pre-`setup()` call would use — same `core:plugin/duplicate-id` / `core:plugin/missing-dep` checks, same `pluginsRegistering` timing (see [Core: Add a Plugin](/nomercy-player-core/build/add-a-plugin) for the full registration contract). `plugins` in `setup()` is the declarative shorthand for that call, not a different mechanism.
