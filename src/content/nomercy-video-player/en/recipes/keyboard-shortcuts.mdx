# Recipe: Customizing Keyboard Shortcuts

[Plugin: Key Handler](/nomercy-video-player/plugins-adapters/key-handler) is the reference for what ships by default.

This recipe is the task on top of it: one more shortcut, a different key for an existing action, or a binding set that looks nothing like the default.

Three ways in. Pick the least invasive one that does the job.

## Add one binding at runtime

`bind(combo, fn)` on the live plugin instance adds a binding without touching anything else. Every default binding in the plugin is built from this same call internally:

```ts
import nmplayer from '@nomercy-entertainment/nomercy-video-player';
import { KeyHandlerPlugin } from '@nomercy-entertainment/nomercy-video-player';

const player = nmplayer('player');

player.addPlugin(KeyHandlerPlugin);
await player.ready();

const keys = player.getPlugin(KeyHandlerPlugin);
keys!.bind('l', (p) => { void p.forward(15); }); // custom 15s skip on 'l'
keys!.unbind('n'); // this app uses 'n' for something else entirely
```

`bind()` on an already-bound combo overwrites it silently. `replace(combo, fn)` works the same way; it is just an alias. Use whichever name reads better at the call site.

## Override one group in a subclass

The default binding set is built from small `protected` group methods (`addPlaybackKeys`, `addVolumeKeys`, `addFullscreenKeys`, and so on), each one focused on a single concern. Override one to change just that group and inherit everything else unchanged:

```ts
import { KeyHandlerPlugin } from '@nomercy-entertainment/nomercy-video-player';

class MyKeyHandler extends KeyHandlerPlugin {
  protected override addFullscreenKeys(): void {
    this.bind('f', () => { void this.player.toggleFullscreen(); });
    // 'F11' and 'Escape' from the default binding are intentionally dropped —
    // this app already binds Escape to closing a modal shell.
  }
}

player.addPlugin(MyKeyHandler);
```

This is the same technique [`TvKeyHandlerPlugin`](/nomercy-video-player/plugins-adapters/tv-key-handler) itself uses. It subclasses the desktop `KeyHandlerPlugin` and overrides only `addNavigationKeys`, `addVolumeKeys`, `addAspectRatioKeys`, and `addHelpKey`. Every other group (playback, modifier seeks, chapters, speed) is inherited as-is.

## Disable everything and start clean

Two ways lead to a genuinely minimal binding set. Pick based on whether you still want `KeyHandlerPlugin` involved at all.

Override `addDefaults()` directly when you still want the plugin (its scope handling, cooldown, input-field awareness) but none of its built-in binding groups:

```ts
class MinimalKeyHandler extends KeyHandlerPlugin {
  protected override addDefaults(): void {
    this.bind(' ', () => { void this.player.togglePlayback(); });
    this.bind('f', () => { void this.player.toggleFullscreen(); });
    // Nothing else — everything the default set adds (seeks, chapters,
    // speed, subtitle size, aspect ratio) is gone.
  }
}

player.addPlugin(MinimalKeyHandler);
```

Set `disableControls: true` on `VideoPlayerConfig` when you want no `KeyHandlerPlugin` at all. An app driving playback from its own remote-control protocol, for instance.

[`VideoPlayerConfig`](/nomercy-video-player/reference/config) declares the field, and `KeyHandlerPlugin` is its only consumer. `addDefaults()` checks it and returns before installing any binding group.

So leaving the plugin registered with this flag set is the same as never adding it. That helps when a shared setup path always calls `addPlugin(KeyHandlerPlugin)` and only some configurations want it live.

To silence only the hardware media keys, `MediaPlay`, `MediaPause`, `MediaTrackNext` and the rest, use the narrower `disableMediaControls`. It gates that group alone.

## Scoping bindings to the player, not the page

By default the listener attaches to `document`, so a bound key fires regardless of what else has focus. For a player embedded alongside other interactive UI on the same page, scope it to the container instead:

```ts
player.addPlugin(KeyHandlerPlugin, {
  scope: 'container',
});
```

Keys are already ignored when the event target is an `<input>`, `<textarea>`, `<select>`, or `contenteditable` element, regardless of scope. `scope: 'container'` narrows further: it fires only while the player element itself (or a descendant) has focus.
